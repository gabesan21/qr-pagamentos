# Deactivation sweep, spec close and owner copy fix

`setActive(..., false)` sweeps every `RESERVED` `checkout_attempt_v2` of the link to the fenced terminal `FAILED` (capability revoked) and its `CREATED` order to `REJECTED`, in the same transaction as the version CAS; `CREATING`/`PENDING`/`INDETERMINATE` stay untouched so no dispatch is fenced into a no-op. Both `paymentLinkDeactivateDescription` locale values drop the false "unaffected" claim. No migration, no new state.
