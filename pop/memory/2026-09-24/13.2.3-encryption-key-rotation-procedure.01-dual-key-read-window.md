# Dual-key read window across crypto modules and consumers

`decrypt` in `nautt-crypto.ts`/`totp-crypto.ts` tries the current key then optional `*_ENCRYPTION_KEY_PREVIOUS`, never plaintext fallback; `encrypt`/issuance stay current-key only. The four capability verifiers and `createDirectoryCursorCodec.decode` rederive current-then-previous, constant-time; `CAPABILITY_KEY_VERSION` stays `v1`. Absent previous reproduces prior behavior; malformed fails loudly. Tests authored, not run (13.2.4 runs the battery).
