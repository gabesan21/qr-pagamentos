# Password change rotates the session instead of signing out

`POST /profile/password` leaves the service revocation untouched — every pre-existing session still dies atomically inside the user lock — and only then issues one fresh session for the same actor, using `createMfaVerified` when TOTP is enrolled so the MFA fact is not downgraded. The `qr_session` cookie is replaced with login's attributes and the merchant lands signed in on `/profile?password=changed`; the `qr_locale` write went away with the anonymous landing. Identity, TOTP, and Nautt notices are single-sourced through the toast bridge, Nautt returning to `/settings#settings-connection`.
