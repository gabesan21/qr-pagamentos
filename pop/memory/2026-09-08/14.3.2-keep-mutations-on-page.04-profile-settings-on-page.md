# Password change rotates the session instead of signing out

`POST /profile/password` leaves revocation untouched in the service — every prior session still dies atomically inside the user lock — and only then issues one fresh session for the actor, `createMfaVerified` when TOTP is enrolled so the MFA fact is not downgraded. The `qr_session` cookie is replaced with login's attributes and the merchant lands signed in on `/profile?password=changed`; the `qr_locale` write went with the anonymous landing. Nautt now returns to `/settings#settings-connection`.
