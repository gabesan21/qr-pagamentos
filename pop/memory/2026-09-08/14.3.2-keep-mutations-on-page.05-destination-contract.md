# Post-mutation destination written into the contracts

The delivered destinations became contract text instead of route folklore: the merchant redirect map now names order, payment-link, profile, and Nautt targets, the password paragraph states rotation with the `/profile` landing, and the V2 link section records create-to-detail with form-scoped failures. `DESIGN.md` adds the rule the fronts must obey — a mutation returns to the page that submitted it, with the destination derived server-side from the route param or the submitted `action`/`id`, never from a client-supplied path.
