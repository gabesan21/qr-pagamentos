# Three save routes return to their settings section

`POST /storefront`, `POST /checkout-policy` and `POST /storefront/logo` stopped redirecting to `/`: every outcome now targets a server-side literal `/settings?<code>#<anchor>` — `#settings-identity`, `#settings-policy`, `#settings-store`. Each literal is built inside its route file, so nothing from the client ever names a path. Guards, parsing, services, status codes and the opaque notice codes stay byte-identical; only the `Location` changed.
