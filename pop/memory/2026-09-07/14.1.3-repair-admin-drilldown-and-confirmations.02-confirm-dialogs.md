# One client boundary gates three destructive actions

Row delete, soft delete, and TOTP disable posted with no confirmation. One owned client module, `DestructiveActionForm`, renders the real POST form, opens the delivered `ConfirmDialog`, and submits that same element via `requestSubmit()` — the ref sits on the form the module renders, avoiding the detached-ref defect. Both deletions require the target username typed; TOTP disable is a plain destructive confirm. Routes and outcomes stay unchanged.
