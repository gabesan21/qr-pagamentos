# Failed mutations return to the originating form with the typed values

`POST /products` sent every failure to `/catalog`, discarding the merchant's input. Its `catch` now derives the target from the submitted action and id — create to `/catalog/products/new`, update/active/archive to that product's detail — keeping the closed `conflict|failed` notice; guards, services and success redirects are untouched. Since a native POST navigates, a session draft saves the typed values on submit, restores them only under a failure notice and clears on a clean load.
