# Failed mutations return to the originating form with the typed values

`POST /products` sent every failure to `/catalog`, discarding the merchant's input. Its `catch` now derives the target from the submitted action and id only — create to `/catalog/products/new`, update/active/archive to that product's detail, anything else to `/catalog` — keeping the closed `conflict|failed` notice; guards, action set, service calls, decimals and success redirects are untouched, and the categories route already landed on `/catalog/categories`. Because a native POST navigates, a session-scoped draft saves the typed values on submit and restores them only under a failure notice, clearing on any clean load.
