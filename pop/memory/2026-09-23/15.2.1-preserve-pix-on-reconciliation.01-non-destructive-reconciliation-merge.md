# Non-destructive reconciliation merge for PIX fields

`reconcileOrderData` wraps `orderData` and drops `pixCopyPaste`/`pixQrcodeUrl` unless the parsed `NauttOrderView` carries a truthy value; Prisma leaves an omitted column untouched, the in-memory store's spread keeps the current value. Both `reconcile` call sites (Prisma `updateMany`, in-memory `orders.set`) switched from `orderData(order)` to `reconcileOrderData(order)`; `completeCreation` in both stores is unchanged and still writes the explicit `null`. CAS guards, `where` tuple and version increment untouched. Regression tests: in-memory case drives the real store end to end (`provider-order-reconciliation.test.ts`), Prisma case extends the durable fake with `updateMany`/`findUniqueOrThrow` assertions (`provider-order-store.test.ts`), no Docker/database.
