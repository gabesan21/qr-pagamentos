# Refusal taxonomy and fail-closed writes

`pricing-orders-client.ts` gains a closed allowlist of seven `code` values (`order.quote_not_found`, `order.quote_expired`, `order.exchange_not_configured`, `order.payment_method_not_available`, `orders.deposit_bank_account_not_found`, `order.deposit_fields_required`, `order.deposit_fields_validation_failed`) on `400`/`422`, raising `NauttOrderCreationRefusedError` with the code attached; everything else (network, timeout, 5xx, invalid `201`, undocumented/absent code, unreadable body) is unchanged and still `NauttOrderCreationIndeterminateError`. `owner-pricing-orders.ts` catches the refusal, discards the provider-order row via a new store method and keeps the quote claim (no second POST possible on that quote). Both `public-checkout-v2.ts` and `standalone-checkout.ts` mark the attempt `FAILED`, the order `REJECTED`, revoke the capability, and the replay path answers the same redacted `provider-unavailable` outcome as first submit — no provider body/code/message crosses the HTTP boundary. Unit tests added in all four `*.test.ts` siblings; not run (deferred to [[15.2.4-phase-verification]]).

## Evidence

- `src/integrations/nautt/pricing-orders-client.ts` — refusal taxonomy and `NauttOrderCreationRefusedError`.
- `src/checkout/public-checkout-v2.ts`, `src/checkout/standalone-checkout.ts` — `FAILED`/`REJECTED` write and redacted replay outcome.
