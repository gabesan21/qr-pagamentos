# 15.2.2 — Fail closed on documented creation errors

- **Delivery:** `pricing-orders-client.ts` classifies seven documented `POST /orders/onramp` `400`/`422` codes into a new typed `NauttOrderCreationRefusedError` (code preserved); every other outcome (network/timeout/5xx/invalid `201`/undocumented code/unreadable body) still raises the unchanged `NauttOrderCreationIndeterminateError`. `owner-pricing-orders.ts` discards the provider-order row on refusal while keeping the quote claim; both checkout services (`public-checkout-v2.ts`, `standalone-checkout.ts`) mark the attempt `FAILED`/order `REJECTED`, revoke the capability, and answer the existing redacted pre-dispatch outcome on first submit and on replay — exactly one POST per attempt, no new public field.
- **Verification:** non-yolo, two sequential fronts (F01 fail-closed path, F02 specs/DOX), PR #19 squash-merged into `develop` (862f58ec). Unit tests added across the four owned modules; suite run deferred to [[15.2.4-phase-verification]] per the phase-verification rule.
- **Contract impact:** `pop/specs/nautt-finance-integration.md` and `pop/specs/checkout-and-order-lifecycle.md` gained the refusal class and the `FAILED`/`REJECTED` pairing; `src/integrations/nautt/AGENTS.md` and `src/checkout/AGENTS.md` updated to match.
