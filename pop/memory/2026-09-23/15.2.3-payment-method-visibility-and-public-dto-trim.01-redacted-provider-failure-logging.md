# Redacted provider failure logging

New `src/observability/provider-failure-log.ts`, reusing `server-request-log.ts`'s discipline: one JSON line, console sink, swallow-on-failure, never alters a thrown error or response. Closed record — operation, HTTP status (or transport marker), and `code` logged verbatim only against a closed allowlist, fixed unknown marker otherwise. Quote/onramp creation, order read and main-wallet balance read all call it; `createOnrampOrder` reuses 15.2.2's parsed `refusalCode`, no second body read.
