# 12.2.4.01 — State-semantic fixtures

Rebuilt the server-first `/design-system` route and its narrow client island so every applicable state maps to a real, semantically distinguishable DOM fixture.

## Changed

- `src/app/design-system/page.tsx` — server-side sections for display, empty-states, loading, table, and directory; directory specimens split into per-state `DirectoryTableSpecimen`, `DirectoryFilterSpecimen`, and `PaginationSpecimen`.
- `src/app/design-system/interactive-specimens.tsx` — client island with controlled CopyField, localized-field probes, real Modal/ConfirmDialog states, deterministic toast triggers, and state-driven OTP/Checkbox/Switch fixtures.
- `src/app/design-system/specimen-state.module.css` — persistent `:hover`/`:focus-visible` indicators using existing tokens without touching shared owners.
- `src/app/design-system/coverage.ts` — executable 20-entry coverage map with 101 applicable states and 72 explicit N/A dispositions.

## Witness strategy

Each binding now carries a `semanticWitness`: `data-probe`, `data-copy-state`, real component attributes (`aria-busy`, `disabled`, `data-state`, `aria-invalid`, `data-active`), or CSS-module forced states. No shared owner, data-directory source, brand asset, token, route, or dictionary was edited.
