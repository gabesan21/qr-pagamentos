## Clean install with the production origin guard (Docker)

- **Criterion 15 (13.2.2 C10)** — clean install with a loopback
  `PUBLIC_ORIGIN`/webhook callback and `ALLOW_LOOPBACK_OPERATOR_ORIGINS`
  unset (expect refusal), then set to `1` (expect success); a second clean
  install with a real host origin, unaffected either way; `install/test.sh`
  green. **Pass:** both installs reach `PASS install-health`; `install/test.sh`
  exits 0; the loopback install without the allowance fails closed with the
  documented message (`ALLOW_LOOPBACK_OPERATOR_ORIGINS=1 to allow it`).

## Encryption key rotation rehearsal (Docker)

- **Criterion 16 (13.2.3 C9)** — on a disposable install: rotate both
  `NAUTT_ENCRYPTION_KEY` and `TOTP_ENCRYPTION_KEY` per
  [[docs/production-runbook.md|the runbook procedure]] (stage new key behind
  the previous-key secrets, restart, run `rotate-encryption-keys.mjs` to zero
  remaining rows, drop the previous secret after the ≥24h TTL). **Pass:**
  login with TOTP still succeeds after rotation; reading a Nautt credential
  (owner webhook registration) still succeeds; no key material, ciphertext or
  plaintext secret appears in any container/installer log; `rotate-encryption-keys`
  output shows `rewrapped=0` on the second run (idempotent).
