# Plan — [[M-20.1-product-registration-fixes]]

- **Stage:** 002_planning · **Role:** `pop-planner`

## Objective and expected result

- **Objective:** make merchant product registration complete with one entered locale, exact local BRL entry, bounded fields, and in-place category creation.
- **Observable result:** a merchant can submit title/description in either locale only; blank counterpart values are copied, valid product data persists, and only a real submission failure receives an error toast.

## Strategy

Keep the persisted bilingual and canonical-decimal contracts unchanged. Before product validation/serialization, copy a trimmed supplied title or description into only its blank locale counterpart; never overwrite a nonblank value, and keep the inline error when both are blank. Apply the service bounds at every editable product/category control using code-point-aware validation plus compatible control limits: internal name 128, titles/categories 160, descriptions 2,000.

Reuse the delivered exact BRL cash adapter (no `Number`) for the product price: the named hidden input submits canonical ASCII decimal while the visible unnamed control shows and placeholders `R$ 0,00`. An inline category modal submits an explicitly JSON-negotiated create to the existing protected endpoint, appends/selects the returned owner category without navigation, and keeps all controlled product/draft state. Native category form redirects and opaque protected outcomes remain unchanged. Client validation/fallback is not a failed submission; only opaque `conflict`/`failed` outcomes trigger localized error toasts.

## Risks and abort conditions

- **Risk:** localized display leaks into persistence or loses precision — mitigate with the delivered adapter, unnamed visible input, canonical hidden value, and no `Number`.
- **Risk:** JSON negotiation accidentally changes browser/native, authorization, or opaque-failure behavior — preserve origin guard/protected empties and test both representations.
- **Risk:** `task/M-20.1-product-registration-fixes` is based on `main` while delivery targets `develop`; missing/deviated `develop` work can cause conflicts or regressions. Resolve the base/target discrepancy before integration; abort as blocked if reconciliation changes this plan's contracts.
- **Abort if:** inline creation cannot return the new owner category without broadening the protected route contract, or exact BRL conversion cannot retain the server grammar; record evidence and return to 002.
