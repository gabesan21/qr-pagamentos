# 11.2.3-rehearse-production-upgrade-and-recovery — Plan

## Objective
Add a disposable `production-rehearsal` container scenario that exercises the full operator lifecycle — clean install, identity seed, SMTP-bound self-hosted password reset, media persistence, representative Commerce V2 journeys, update, backup, restore, liveness, and exact-revision release ledger — without touching production data or leaking secrets.

## Areas touched
- `pop/scripts/container-test.mjs` — new `--scenario production-rehearsal`.
- `install/install.sh`, `install/update.sh`, `install/backup.sh`, `install/restore.sh` — exercised, not restructured.
- `install/AGENTS.md` — update if operational contract wording changes.
- `container/healthcheck.mjs`, `container/media-preflight.mjs`, `container/media-inventory.mjs` — exercised, no behavior change expected.
- Supporting container-test helpers for mock SMTP capture, media fixture creation, and commerce HTTP assertions.

## Strategy
Implement one integrated clean-clone scenario that reuses the existing install/update/backup/restore scripts exactly as an operator would. The scenario seeds realistic state, validates it survives the lifecycle, and asserts the release ledger at every boundary. Bilingual and six-theme assertions are gated on the closure of `11.2.2-verify-six-theme-bilingual-experience`.

## Work fronts
1. **Rehearsal scenario scaffold** — add `production-rehearsal` to `container-test.mjs`, prepare secrets, install on a disposable project, wait for health, and capture exact-revision evidence.
2. **Mail/reset validation harness** — deploy a mock SMTP sink container in the rehearsal network, trigger `POST /reset-password` and the reset link redemption, and assert the admin password rotates without email-dependent login.
3. **Commerce journey fixtures** — create a merchant user, active currency mapping, storefront settings with a logo, catalog products with images, a V2 payment link, a storefront cart checkout, and at least one order/attempt row.
4. **Lifecycle mutation rehearsal** — run `update.sh` (no-op fast-forward), `backup.sh` to a disposable destination, `restore.sh` with adversarial injection, and verify media/database inventory plus `/api/health` after restore.
5. **Ledger and liveness assertions** — confirm image labels, backup manifest, update evidence, and volume identities all bind the same 40-character SHA; assert no raw secret appears in logs or artifacts.
6. **11.2.2 integration gate** — once `11.2.2` closes, add locale/theme coverage to the commerce assertions; until then, mark those assertions as blocked and do not simulate the work.

## Dependencies
- `6.3.3-provision-persistent-media-operations` — media volume/backup/restore semantics already delivered; reused unchanged.
- `11.1.1-build-self-hosted-password-reset` — provides the reset route and SMTP-driven rotation contract exercised here.
- `11.2.2-verify-six-theme-bilingual-experience` — provides the six-theme and bilingual assertions to be included after closure. The plan does not assume closure; front 6 is a conditional add-on.

## Real risks
- Docker socket/permission or port-mapping flakiness in the host environment may block the integrated run, as happened in previous container-test closings.
- `11.2.2` may still be in 004 when this task moves; executing theme/locale assertions early would duplicate work and risk drift.
- Mock SMTP capture adds a second container to orchestrate; misconfiguration could leak the reset token into logs.
- Longer runtime from commerce fixtures may hit the 30-minute subagent timeout; the scenario must be designed to fail fast on first redaction or health violation.

## Acceptance criteria
- `pnpm container:test --clean-clone --scenario production-rehearsal` passes end-to-end.
- `install/test.sh` and `pnpm check` pass with no regression.
- Backup manifest and update evidence contain exact image labels and volume identities; no secret sentinel appears in stdout/stderr or artifacts.
- Post-restore database/media inventory matches pre-backup state, and `/api/health` returns `{"status":"ok"}`.
- `install/AGENTS.md` is current if any operational wording changed.
- If `11.2.2` is closed before 004, the scenario includes locale/theme assertions; otherwise a documented blocker defers front 6.
