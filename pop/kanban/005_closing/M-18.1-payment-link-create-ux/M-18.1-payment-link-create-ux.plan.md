# Plano — [[M-18.1-payment-link-create-ux]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** converge the merchant V2 payment-link create/edit form (`/links/new`, `/links/v2/[id]/edit`) with the panel's established conventions: an additive ISO `currencyCode` projection on the currency-pair catalog, the H-16.1 BRL live cash mask on the FIXED_AMOUNT amount, hidden canonical submits with edit dirty-omission CAS, expiry shown in the browser's local clock with UTC conversion, and bilingual copy/layout harmonized to the design system.
- **Resultado observável:** a selected BRL pair renders a live `R$` mask with stable caret and exact decimals (up to six places) posted through a hidden input; expiry edits in local time; untouched edit fields post absent; the preview is honest per currency; the radio cards, heading/divider, CTA, and copy follow the design system in `pt-BR`/`en`.

## Estratégia

Single front over one write set. The pair-catalog read gains the additive `currencyCode` through the existing `supported_exchange_currency` pointer relation — no schema, migration, or server-grammar change. The mask mirrors H-16.1's adapter semantics (digit-to-cents editing, strict localized-paste parser, `Number` never in the amount path) with the visual input unnamed and the canonical decimal in a hidden `amount` riding the delivered dirty-omission pattern; non-BRL pairs keep the plain input. Expiry keeps the delivered server grammar (UTC `YYYY-MM-DDTHH:mm`): the visible control is an unnamed datetime-local in the browser clock, a hidden `expiresAt` posts the local→UTC conversion, the stored instant converts post-mount (no hydration mismatch), untouched omits, clearing posts empty. Copy/layout stays in the existing dictionary domains using shared primitives and tokens; specs sync at 005. Focused tests are authored in 004 and run only at the 005 gate under the user's explicit authorization (focused vitest + direct pnpm, no Docker).

## Riscos e condições de aborto

- **Risco:** mask divergence from H-16.1 (caret/paste) — mitigação: mirror the delivered adapter plus focused interaction tests.
- **Risco:** expiry hydration mismatch or edit-CAS regression — mitigação: post-mount conversion, non-zero-UTC-offset and dirty-omission tests.
- **Abortar se:** the pair read cannot project `currencyCode` without a schema/migration change, or the server `expiresAt` grammar cannot accept the converted value without route/service edits — `blocked: true` with evidence.
