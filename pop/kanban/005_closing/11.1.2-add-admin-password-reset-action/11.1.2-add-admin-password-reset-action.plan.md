# Plano — [[11.1.2-add-admin-password-reset-action]]

- **Stage:** 002_planning · **Responsible:** planner agent

## Objective and expected outcome

- **Objective:** Harden the administrator-initiated password reset action so every attempt produces an append-only audit record while preserving the safe no-email, disabled/deleted-account, delivery-failure, and rate-limit opaqueness already delivered by 11.1.1.
- **Observable result:** Clicking "Send reset email" on `/admin/accounts/[id]` still redirects to `?reset=requested` or `?reset=failed`; persistence gains one `password_reset_request` row per click describing the actor, target, timestamp, and outcome class without exposing the challenge, email, or SMTP error.

## Strategy

11.1.1 delivered the mail config, SMTP sender, challenge creation, and opaque route/page behavior. This task adds the missing audit dimension: a new append-only audit table, service-level recording for every outcome, and deterministic tests covering all five outcome classes. The UI remains unchanged; the existing bilingual notices and evidence captures are reused.

## Execution fronts

### F01 — Audit schema and migration
- **Deliverable:** `password_reset_request` table/model with restrictive FK on `user_id`, plain `actor_id` UUID (no actor FK), `outcome` enum/varchar, and `created_at`; safe-language migration; bootstrap grant re-pin.
- **Contract:** [[11.1.2-add-admin-password-reset-action.f01-audit-schema]]
- **Owns:** `prisma/schema.prisma`, new `prisma/migrations/20260728*_password_reset_request/`, `prisma/bootstrap.sql` (grant re-pin).
- **Criteria:** 1, 2, 7.

### F02 — Admin reset service audit integration
- **Deliverable:** `sendResetEmail` receives the resolved admin principal, records one audit row atomically with the challenge creation on success and separately on every failure class, and keeps throwing the same opaque errors.
- **Contract:** [[11.1.2-add-admin-password-reset-action.f02-service-audit]]
- **Owns:** `src/auth/admin-password-reset.ts`, `src/auth/admin-password-reset.test.ts`.
- **Depends on:** F01.
- **Criteria:** 3, 4, 5.

### F03 — Route wiring and opaque response
- **Deliverable:** `POST /admin/users/[id]/reset-password` passes the resolved admin actor into the service and preserves origin-guard, re-authorization, request-log, and the closed `requested`/`failed` redirect set.
- **Contract:** [[11.1.2-add-admin-password-reset-action.f03-route-wiring]]
- **Owns:** `src/app/admin/users/[id]/reset-password/route.ts`, `src/app/admin/users/[id]/reset-password/route.test.ts`.
- **Depends on:** F02.
- **Criteria:** 3, 6.

### F04 — Tests and verification
- **Deliverable:** Unit/route tests for all audit outcomes, migration-policy check, disposable database test, and re-run of the existing evidence suites that exercise the reset card.
- **Contract:** [[11.1.2-add-admin-password-reset-action.f04-verification]]
- **Owns:** test files touched in F01–F03 plus aggregate gates.
- **Depends on:** F01, F02, F03.
- **Criteria:** 7, 8.

## Order and parallelism

## Risks and abort conditions

- **Risk:** migration-policy verifier rejects the audit table design — mitigation: generate from `migration.safe.json`, run `pnpm db:contract-check`, and keep grants aligned with `user_deletion` precedent.
- **Abort if:** `pnpm check`, `pnpm db:test`, or `pnpm admin-users:evidence`/`verify` fail; mark `blocked: true` with logs.
