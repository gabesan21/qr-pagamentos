- **Deliverable:** `sendResetEmail` receives the resolved admin principal, records one audit row atomically with the challenge creation on success and separately on every failure class, and keeps throwing the same opaque errors.
- **Scope:** integrate audit writes into the existing admin reset service while preserving its safe external contract.

## Execution contract

- Change `sendResetEmail(targetId: string)` to accept the admin principal as a second argument (e.g., `actor: Principal`) and pass it through the store.
- Extend `AdminPasswordResetStore` with `recordRequest(audit)` and, on success, run the audit `INSERT` in the same transaction that creates the challenge token via `password-reset` store (or immediately after when store boundaries prevent a single transaction).
- For each outcome class, write exactly one audit row before throwing/mapping: `SENT` (after successful SMTP send), `NO_EMAIL`, `UNAVAILABLE` (inactive/deleted), `RATE_LIMITED`, `DELIVERY_FAILED`.
- Keep the existing `AdminPasswordResetUnavailableError` and `MailSenderError` throws so callers map every failure to the same opaque redirect.
- Update `admin-password-reset.test.ts` to assert audit calls for success, no-email, unavailable, rate-limit, and send failure using a mocked store.
