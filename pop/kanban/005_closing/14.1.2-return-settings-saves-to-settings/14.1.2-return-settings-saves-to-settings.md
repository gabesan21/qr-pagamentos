# 14.1.2-return-settings-saves-to-settings — Return settings saves to settings


- **Origem:** [[pop/roadmap/14-template-fidelity-convergence|Phase 14.1]]
- **Plano:** [[14.1.2-return-settings-saves-to-settings.plan]] · **Aprovação:** [[14.1.2-return-settings-saves-to-settings.approval]] · **Verificação:** [[14.1.2-return-settings-saves-to-settings.verify]]

## O quê

Saving storefront settings, checkout policy, language preference and the staged logo returns the merchant to `/settings` (same anchor) with the outcome notice, never to `/`; the settings page renders its two-column sticky section nav with real styles, each section heading appears once, and the page description no longer reuses the admin-language copy.

## Por quê

Three of four save paths abandon the settings page and the `settings-surface__*` classes have no CSS at all, so the page the template designed is both unstyled and disorienting.
