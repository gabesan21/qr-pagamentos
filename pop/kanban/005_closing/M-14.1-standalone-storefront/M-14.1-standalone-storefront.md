# M-14.1 — Standalone storefront

## Approved plan

1. When `catalog.length === 0` and `standalonePayments` is enabled, retain the
   branded `CheckoutShell` and render a compact standalone amount card only.
   It has one localized heading, effective standalone currency, amount field,
   and one continuation action; it renders no products, cart, add actions, or
   totals.
2. Reuse the canonical storefront cart amount grammar without floating-point
   conversion or rounding. A valid value is forwarded only as the existing
   `/store/[slug]/pay?amount=` prefill; no API, checkout reservation, replay,
   lock, projection, or schema behavior changes.
3. A null effective currency shows a localized pending-configuration notice
   and disables the continuation action. It never invents a currency fallback.
4. Preserve catalog-present and standalone-disabled branches. Use existing
   Card, Field, Input, Button, theme tokens, responsive layout, keyboard
   semantics, and bilingual copy.
5. Add focused branch, currency, and canonical-prefill tests and update the
   storefront specification.
