## Summary

The plan covers the card's full scope: file-backed mail/public-origin configuration, real SMTP sender wired to the existing hashed single-use expiring challenge service, admin reset request with abuse limits, public consume flow with password rotation and session revocation, bilingual message, and run-bound redacted evidence plus container/installer integration.

The base implementation (table, challenge service, admin/public routes, consume page, dictionaries) is already in `develop`. The two unmerged commits on the prior branch (`7f95c34` real SMTP sender, `33f796e` admin a11y evidence) are explicitly rebased/adapted rather than discarded, and the front structure correctly isolates configuration, sender/admin request, public consume/evidence, and operational integration.

## Why it is ready

- **Scope coverage:** F01–F04 map directly to the card's "What".
- **Executability:** Each acceptance criterion has a concrete verification command and pass condition.
- **Ownership:** `owns`/`must_not_edit` boundaries are clear and respect the existing DOX split (`src/auth/*`, `src/app/reset-password/**`, `src/app/admin/**`, container/installer).
- **Dependencies:** Card dependencies `7.3.1` and `10.3.1` are implemented and closed in `develop`.
- **Risk handling:** Rebase risk is noted with a cherry-pick fallback; abort conditions are tied to the aggregate gates.

## Principal risks

1. **Rebase/adaptation of prior branch:** `7f95c34` assumes env-var config; it must be adapted to the new `_FILE` loaders without leaking env precedence details.
2. **Secret lifecycle:** New SMTP/public-origin secrets must follow the existing `0600` source / `0400` staged / `1000:1000` identity contract; any deviation breaks container and installer gates.
3. **Evidence redaction:** Reset-password evidence must avoid capturing the token value or SMTP credentials in screenshots/logs; the project-wide redaction helpers must be applied.

## Response to planner

Plan is approved for 004_processing. Proceed with the wave order (F01 → F02 → F03/F04) and keep the existing challenge/password-reset service byte-stable unless a concrete conflict emerges.
