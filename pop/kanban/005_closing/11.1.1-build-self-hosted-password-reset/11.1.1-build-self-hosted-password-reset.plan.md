# Plano — [[11.1.1-build-self-hosted-password-reset]]

- **Stage:** 002_planning · **Responsible:** planner agent

## Objective and expected outcome

- **Objective:** Close the self-hosted password reset: file-backed mail/public-origin configuration, real SMTP sender, request/consume flows with hashed single-use expiring challenges, abuse limits, password rotation, session revocation, bilingual mail, and redacted evidence.
- **Observable result:** An administrator clicks "Send reset email" on `/admin/accounts/[id]`; the user opens `/reset-password?token=...`, sets a new password, and returns to `/login`; no token, hash, or configuration is leaked.

## Strategy

Most of the flow already exists in `develop` (table, challenge service, admin/public routes, consume page). This task fills the gaps: file-backed configuration in the container, real SMTP sender, admin service unit tests, public evidence, and container/installer integration.

The prior branch `task/11.1.1-build-self-hosted-password-reset` has two unmerged commits: `7f95c34` (real SMTP sender with nodemailer) and `33f796e` (a11y evidence for the admin reset button). Rebase them onto `develop` and adapt them to the file-backed configuration; the content is reused, not discarded.

- **Deliverable:** Validated loader that reads mail/public-origin from files (`/run/secrets/*`) in the container, keeping env-var fallback for dev/test; compose and installer mount/stage the secrets.
- **Contract:** [[11.1.1-build-self-hosted-password-reset.g01-mail-config]]

### F02 — Real SMTP sender and admin reset request
- **Deliverable:** Real SMTP sender integrated into the admin reset service; admin service unit test; admin route keeps opaque redirects.
- **Contract:** [[11.1.1-build-self-hosted-password-reset.g02-admin-reset]]

### F04 — Container and installer integration
