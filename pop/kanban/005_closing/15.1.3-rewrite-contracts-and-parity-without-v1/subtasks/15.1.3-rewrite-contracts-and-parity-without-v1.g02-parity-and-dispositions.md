## Contrato de execução

Order of work:

1. **Inventory before writing.** List every `current-route` record whose `source.path` no longer exists, and every other record whose only current target is one of the two deleted routes. Report the ids; they are the change's scope.
2. **Retirement, then refresh.** The canonical `--refresh-semantic-contract` cannot express this removal: `refreshCurrentRouteSources` aborts with `PARITY_CURRENT_ROUTE_REFRESH_MISSING_INVENTORY` on an unmatched record and `assertRefreshInvariants` requires an identical record count and id set. Extend the checker with **one closed operation** that retires a record only because its bound current file is absent from the repository — never by name, list or flag argument — keeping every existing invariant for surviving records and adding no path to hand-editing. Then run the canonical `node scripts/check-frontend-template-parity-contract.mjs --refresh-semantic-contract`.
3. **Never hand-edit** `obligations.ndjson` or `manifest.json`: every byte of both files comes from a tool run.
4. **Record the dispositions** in the README: under "Authority and dispositions", the retired current routes (reason: the surfaces were deleted by 15.1.1 under the 2026-09-22 decision that V1 never existed as a product) and the supplied template's remaining V1 statements (`docs/template/info.md`, the V1/legacy checkout and links wording) as reference-only text that is never adopted and never edited; under "Regeneration and validation", the new closed operation and when it applies.
5. **Run no pnpm gate.** `pnpm frontend-parity:check`, the mutation probes and `pnpm check` are criterion C10 and run once in [[15.1.4-phase-verification]]. Running the parity tool's own refresh/inventory commands is part of the delivery, not a test run.

- Deliver only this scope; do not repair a spec, a DOX file or application code to make the parity gate happy.
- **Saber parar:** at most 2 attempts on an `agent` criterion failing for environment reasons; then record `ambiente`, report the reclassification to `verify: user` and move on.
- **`BLOCKED` instead of improvising:** 15.1.1 not integrated; a refresh diagnostic (`*_AMBIGUOUS`, `*_DUPLICATE`, `PARITY_REFRESH_INVARIANT_*`) that survives the retirement step; a semantic record left with no concrete target (`*_EVIDENCE_IDENTITY_INVALID`); or a retirement that could only be made to pass by weakening a fail-closed check. Report the exact diagnostic and record ids.
- Never edit paths outside `Owns`; a new need goes back to the main agent.
