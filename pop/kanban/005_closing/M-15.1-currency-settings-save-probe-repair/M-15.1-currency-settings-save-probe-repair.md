# M-15.1 — Currency settings save-probe repair

## What

Repair the merchant currency-pair save probe against the approved Nautt pricing contract. The server sends exact validated money as JSON numeric tokens, validates only the documented minimal quote DTO, preserves precise numeric lexemes, applies a ten-minute local TTL, and keeps the current owner, claim, selection, throttle, no-retry, and redacted-log boundaries. The settings DOM keeps its visible layout while every probe control is owned by an isolated sibling form.

## Why

The prior probe serializes money as JSON strings, accepts a stale response shape, and renders invalid nested forms. That prevents the saved PIX/BRL pair from receiving a reliable current probe result.

## Boundaries

- Use the current approved Nautt OpenAPI contract only; do not call it from this task.
- Money must never pass through `Number`; a local Node 26 `JSON.rawJSON` serialization boundary and `JSON.parse` reviver source-token boundary preserve numeric lexemes.
- Do not perform an order, expose credentials or raw provider bodies, relax registration/owner/claim/selection/throttle/no-retry gates, or migrate historical evidence.
- Historical stored refusal codes remain readable as generic refusals; only the approved current refusal allowlist becomes typed.
- Keep the existing storefront save route and its omission-of-unchanged-default behavior.

## Acceptance and verification

- Fiat and reverse quote requests emit unquoted exact numeric `amount`/`amount_usd` tokens.
- Quote parsing accepts required documented fields only, rejects malformed/missing/contradictory responses, preserves valid precision and bounded exponents, and uses a ten-minute TTL.
- Current refusal typing is limited to the approved five exact codes; the overlength provider code maps only to its documented bounded local evidence tag, while legacy persisted evidence stays generically readable.
- Each currency probe has one actual sibling form and isolated `FormData`; no nested form remains.
- Tests cover dispatch, redaction, ownership/claim behavior, defaults, and deterministic UTC evidence dates. Verification is intentionally deferred to the next authorized phase.
