# Plan — [[M-21.1-public-storefront-polish]]

- **Stage:** 002_planning · **Role:** planning context, separate from execution.

## Objective and expected result

- **Objective:** Deliver exactly three public storefront presentation corrections: monetary input placeholder/format `R$ 0,00`, circular store-logo crop at every storefront/payment/cart stage, and BRL formatting of every financial amount in payment/cart stages.
- **Observable result:** The monetary input and placeholder display `R$ 0,00`; the store logo is circular throughout storefront, payment and cart stages; and every financial amount in payment/cart stages uses the established BRL display convention.

## Strategy

- Trace the existing storefront and payment-stage UI, currency formatter and shared merchant-brand shell. Reuse the live BRL digit-to-cents mask and exact currency formatting rather than introducing a second parser/formatter. Format display only; preserve the canonical amount submitted to the server.
- Constrain logo crop to the existing logo rendering boundary, including product/cart/storefront header and standalone payment states where that merchant logo appears; preserve media identifiers, official fallback brand and alt text. Do not change other images.
- Do not polish unrelated layout, copy, controls, empty states or checkout behavior. Preserve both `pt-BR` and `en` UI support, request payloads, cart storage, amount precision, attempt/retry lifecycle, endpoint behavior and public redaction.

## Affected areas

- `src/app/store/[slug]/` — storefront/cart stages and the named monetary input, store-logo and financial-amount consumers.
- `src/app/store/[slug]/pay/` and shared public checkout presentation only where the existing store-logo or payment/cart financial-amount boundary is actually used; coordinate ownership before touching `src/app/pay/[identifier]/`.
- `src/i18n/dictionaries/storefront/` — the named monetary-input placeholder in both locales only where applicable.
- `DESIGN.md` and linked specs — synchronize only an actual durable presentation contract; leave existing implementation metadata unchanged until delivery.
