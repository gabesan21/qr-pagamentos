# Plano — [[13.4.1-validate-currency-pair-and-wire-payment-settings]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** make a registered currency pair *earn* the right to be selected — a documented pre-order provider probe plus durable, observed PIX/BRL evidence from the first real order — and make `GlobalPaymentSettings` (BRL/PIX) a refusal the checkout actually applies before dispatch.
- **Resultado observável:** a pair that Nautt refuses can no longer be picked for a link or a store default; a pair observed producing a non-PIX or non-BRL order refuses the next dispatch pre-money with the existing redacted outcome; the first-pair setup is documented instead of folkloric.

## Estratégia

**What the in-repo documentation proves (the only source; no external or invented fact).** The **quote is the only documented pre-order test of a pair**: `POST /pricing/panel/buy` takes exactly `currency_uuid` + `exchange_currency_uuid` + one amount (`raw/pricing/calculate-buy-conversion-panel.md:11-18`) and answers `200` or the closed codes `validation.exchange_currency_invalid` (400), `validation.currency_not_found` / `validation.exchange_currency_not_found` (404), `validation.failed` (422) (`:79-111`). **Method and currency are knowable only from an order**: `payment_data.payment_method` and `currency.symbol` appear in the creation `201` and in `GET /orders/{uuid}` (`raw/orders/create-onramp-order.md:91-104`; `raw/orders/get-order.md:85-98`), with `pix`, `qr_code`, `webpay`, `transferencia bancaria`, `bank_transfer`, `credit_card` as the documented tokens (`create-onramp-order.md:148-222`). `deposit_fields` is conditional *by currency* and the documented BRL/PIX example sends none (`:20`, `:28-35`), while its absence when required is the closed 422 `order.deposit_fields_required` (`:267-272`). Hence a **two-stage design**: stage 1 is a probe (reachability), stage 2 is observed proof recorded from the first order — never a claim the documents do not support.

**Declared gaps (LACUNA — no assumption is allowed to fill them).** *L1:* the `/exchange-currencies` schema is **not ingested** — the endpoint is only listed (`raw/index.md:76`), so how a mapping declares its method, currency, flags and `deposit_fields` is unknown; a documented mapping would let the app *look up* PIX/BRL before quoting, so its absence is exactly why proof must be observed. *L2:* the quote `200` body carries no method and no currency (`calculate-buy-conversion-panel.md:46-65`) — a passing probe proves the pair is *accepted for this account*, never that it is PIX/BRL. *L3:* the `qrcode` vs `pix_qrcode` rule per provider is undocumented (`nautt-finance.md:82`), so proof reads `payment_data.payment_method`, never the presence of a QR field. *L4:* nothing documents whether pair validity or `deposit_fields` is account-scoped, while an API key "identifies its owner and inherits that user's permissions" (`raw/index.md:14`) — so evidence is recorded **per (owner, pair)** and never extrapolated to another owner. *L5:* no documented enumeration backs the settings vocabulary, so `GlobalPaymentSettings` stays the closed BRL/PIX list already in code (`src/auth/payment-settings.ts:4-5`), compared case-insensitively against the observed tokens.

**Who may probe — the card's "admin action" is impossible as written, and this is the pinned correction.** Roles are disjoint (`src/auth/authorization.ts:16-20`) and a Nautt credential is strictly self-owned by a `USER` (`src/auth/nautt-credential.ts:63-68`): an `ADMIN` has no key and must never dispatch with a merchant's secret. So the **merchant** runs the probe from its own settings surface with its own key, for a pair the admin registered; the admin section gains a **read-only** evidence column (probe outcome, observed method/currency, timestamps) — honest visibility, zero admin-triggered provider call. A repeat probe for the same pair within 60s is refused from the stored timestamp (no new limiter infrastructure).

**Gates, recording and boundaries.** Selection gates fail closed on evidence, not on optimism: a pair may be chosen for a **new/edited link** (`payment-link-v2.ts:323-328`) or a **storefront default currency** (owner and admin paths, `storefront-settings.ts:270`, `admin-user-profile.ts:292`) only when that owner has a passing probe and no disproving observation; already-created links and settings are never retroactively invalidated. A successful creation records the observed `payment_method` + `currency.symbol` on (owner, pair), latest-wins, inside the same transaction as `completeCreation` (`provider-order-store.ts:130-137`) — an observation log of one row, never a verdict cache. The checkout reads `GlobalPaymentSettings` **before dispatch** and refuses with the existing redacted `provider-unavailable`/503 path (`public-checkout-v2.ts:137-154`; `standalone-checkout.ts:132-149`) when the recorded observation is outside the enabled sets or the sets are empty; a pair with no observation yet still dispatches, because the probe already gated its selection. Boundaries: the app **never sends `deposit_fields`** and treats `order.deposit_fields_required` as the already-closed refusal (`pricing-orders-client.ts:54-62`) surfaced to the admin as a diagnosis on the pair; no Nautt payment links; no `NAUTT_API_BASE_URL`, no webhook change, no retry; migration strictly additive (`pop/scripts/migration-policy.mjs:192-208`); no seed.

## Riscos e condições de aborto

- **Risco:** treating a passing probe as PIX/BRL proof (L2) — mitigation: the gate is named *reachability*; the only PIX/BRL claim in code comes from an observed order, and the settings check is fail-closed.
- **Risco:** probe quotes accumulating in `provider_quote`, or a probe racing a checkout — mitigation: the probe reuses the existing `quote()` path (one key handling, one ownership fence), never claims the quote, and is throttled to one per pair per 60s; expiry disposes of it.
- **Risco:** dictionary collision with in-flight 13.2.1 — mitigation: F02 adds new keys only and never edits `payment-links-directory` values; if a new key has no home outside a file owned by another card, report to the main agent instead of editing it.
- **Abortar se:** the verification table or the `currency_symbol` column cannot be expressed in `migration.safe.json` — sinalizar `blocked: true` naming the rejected operation.
