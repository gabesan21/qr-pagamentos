# Plano — [[15.4.3-phase-verification]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** prove Phase 15.4 once on the integrated tree, repair only what the sweep falsified, and close Epoch 15 by handing the human one consolidated verification checklist plus a closing report.
- **Resultado observável:** every command below exits 0 on integrated `develop`, every `verify: user` item of the epoch lives in one note with its step and expected pass, and the final `develop` → `main` PR is **suggested** to the human — never opened by the agent.

## Estratégia

Planned ahead of execution (human command 2026-09-23): the criteria below are the `verify: phase` rows of the [[15.4.1-migrate-template-vocabulary]] and [[15.4.2-fix-target-sizes-and-dictionary-debt]] plans as they stand in `003_human_approval`. **Entry pre-condition of 004:** both ledgers exist under `pop/memory/<data>/` and the verifier re-reads both final plans, because a `lacuna` round may have appended criteria. Divergence is an append-only `lacuna` amendment to this plan (new `C` rows, existing IDs untouched), not a block.

Everything runs by **direct pnpm**, never through a container. When pnpm refuses because the local Node is newer than the pin (A12 of the review findings), the equivalent binary is the *same* attempt, not a second one: `./node_modules/.bin/tsc --noEmit`, `./node_modules/.bin/vitest run`, `./node_modules/.bin/next build`, `node scripts/<checker>.mjs`. Setup does not consume attempts either (`SHARP_IGNORE_GLOBAL_LIBVIPS=1 pnpm install --frozen-lockfile`; moving `src/generated/prisma` out of `src/` when a checker demands a clean tree).

**Repair reach is the phase and only the phase:** assertions naming a migrated class, snapshots, pinned dictionary key lists and inventory allow-lists that the integrated diff falsified. A wrong durable contract or a structural defect is not fixed here — it becomes a modification/task proposal recorded in the memory entry, the way 15.1.4 and 15.3.4 recorded F2–F6.

## Ordem e paralelismo

1. **Onda 1:** pre-condition check (ledgers + final plans), then C1–C8 on the integrated tree; repair inside the reach and re-run only the falsified command.
2. **Onda 2:** C9 (code + UI review by reading), then C10/C11 — the two notes and the PR suggestion to the human.
3. **Integração:** o agente principal valida ownership, integra e confere os critérios `agent`; single write set, no parallelism.

## Riscos e condições de aborto

- **Risco:** repair drifting into product code to make a gate pass — mitigação: product paths are `must_not_edit`; a red gate that only product code fixes is a recorded finding, not an edit.
- **Risco:** Phase 15.2 still open (15.2.4 in `004_processing`) leaves the epoch hand-off incomplete — mitigação: C1–C9 run regardless; C10/C11 need the 15.1.4, 15.2.4 and 15.3.4 ledgers, and their absence blocks **only** the hand-off, recorded as such.
- **Abortar se:** a phase criterion demands changing a durable contract, a spec, DOX or `docs/frontend-template-parity/**` — `blocked: true` with the command output and the rule at stake.
