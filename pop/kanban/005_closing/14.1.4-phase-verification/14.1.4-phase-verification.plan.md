# Plano — [[14.1.4-phase-verification]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** run the aggregate gate `pnpm check` on the integrated `develop`, realign the assertions the three Phase 14.1 repairs invalidated, add the regression coverage the phase checklist accumulated, and repair inside the phase's reach whatever the suite catches.
- **Resultado observável:** `pnpm check` exits 0 with no test lost against the pre-phase baseline (1981 tests, 0 lint errors), and each phase-checklist behavior is pinned by a test that fails if the repair is reverted.

## Estratégia

Work in three passes on the already-integrated code, never re-opening the delivered behavior. **Pass 1 — realign:** run `pnpm test` first to get the real failure list, then update the assertions the diffs falsified: `admin/payment-links/v2/[id]/page.test.tsx:83` (`?link=` → `?filter.link=`), `storefront/route.test.ts:61,69,72,100,111`, `checkout-policy/route.test.ts:19` and `storefront/logo/route.test.ts:80-120` (targets now `/settings?<code>#<anchor>`). A test that encodes the *old* behavior is realigned, never deleted. **Pass 2 — cover:** add the regression cases the three verdicts owed, next to the sources, reusing each file's existing mocking idiom (`renderToStaticMarkup` for pages/components, direct `POST` calls with a hand-built `Request` for routes). **Pass 3 — repair:** the three cheap, in-phase findings the judges left — `encodeURIComponent` on the id interpolated into the `/products` failure `Location`, `role="none"` on the sign-out `<form>` nested between `role="menu"` and its `role="menuitem"`, and the two dead notice branches on the merchant dashboard for `storefront`/`checkout-policy` codes no route emits any more (drop them from the `searchParams` type and from `ownerNotice`; `payment-links` and `language` stay live). Finish with a clean `pnpm check`. Defects the suite exposes are repaired only where the cause sits inside the three tasks' files; anything wider stops (see Riscos). No new dependency, no test-infra construction, no Docker: everything is direct pnpm.

## Riscos e condições de aborto

- **Risco:** a failure whose cause is a durable contract, not an assertion — mitigação: do not "fix" it here; record it in memory and propose a task/modification (WORKFLOW › Verificação de phase).
- **Risco:** a client component (`shell-navigation`, `destructive-confirm`) resisting static rendering — mitigação: assert through the page/shell that already renders it; two attempts, then the criterion is reclassified `user` per the verification stop rule.
- **Abortar se:** the gate needs Docker or infra outside direct pnpm — sinalizar `blocked: true` with the failing command.
