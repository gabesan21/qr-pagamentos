# Plano — [[15.1.5-create-missing-parity-current-route-records]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** register the three live current routes that have no parity record — `src/app/(merchant)/error.tsx`, `src/app/(merchant)/orders/v2/[id]/loading.tsx` and `src/app/admin/orders/v2/[id]/loading.tsx` — through one sanctioned, fail-closed checker operation, and rebind the manifest with the tool.
- **Resultado observável:** `pnpm frontend-parity:check` no longer reports `PARITY_CURRENT_ROUTE_MISSING` for those three routes, and `--refresh-semantic-contract` no longer aborts because of them; every byte of `obligations.ndjson`/`manifest.json` still comes from a tool run.

## Estratégia

The canonical refresh cannot do this: `refreshCurrentRouteSources` aborts with `PARITY_CURRENT_ROUTE_REFRESH_MISSING` on a live route with no record, and `assertRefreshInvariants` rejects any added id. The README forbids hand edits. So the delivery is **one closed registration operation** in the checker, with its own CLI entry point, that (1) reads the live route inventory, (2) selects exactly the live routes with no matching `current-route` record, (3) derives every field from sources — `routeFor` for `route`/`routeKind`, the file hash for `source.sha256`, `ownerForSource(path, route)` for `laterOwner`, `{route, surface}` for `target`, `page→all-states`/`loading→loading`/`error→error-retry` for `evidenceTarget`, and the template route set (`:param` normalized to `[param]`) for the disposition: a match yields `direct-presentation-map`, no match yields `current-only-presentation-map` with the reason already used for `/design-system` — (4) writes the records sorted by id with the same key order as the existing ones, and (5) rebinds the manifest `count`/`sha256`. No record name, id, list or flag argument ever reaches the operation.

**Dispositions decided here (template evidence, `docs/template/app/src/App.tsx`):** `/` (MerchantDashboard), `/orders/v2/:id` and `/admin/orders/v2/:id` all exist in the template, so all three records are `direct-presentation-map`, with no `reason`, mirroring their already-mapped page/loading siblings — owners `12.5.1`, `12.5.2`, `12.4.2`.

**Registration is independent of the refresh.** Records bound to the V1 detail routes deleted by 15.1.1 still exist, so `--refresh-semantic-contract` aborts today with `MISSING_INVENTORY` regardless of this task; the registration must not call it, and this task must not run it. Retirement of those orphans and the full green gate belong to [[15.1.3-rewrite-contracts-and-parity-without-v1]] and [[15.1.4-phase-verification]].

**Boundary with 15.1.3 (this task lands first, 15.1.3 rebases):** the shared integration point is `assertRefreshInvariants`, which gains a third **options** parameter (`assertRefreshInvariants(before, after, options = {})`) carrying the authorized `registeredIds`; 15.1.3 folds its `retiredIds` into the same options object on rebase. Nothing else in the retirement path is anticipated here.

**Identity is verified, never invented.** Ids use the existing `obligationId` helper; before adding anything the operation must reproduce the id of every existing `current-route` record from its own inputs. If no single deterministic formula reproduces them all, the front reports `BLOCKED` — it never guesses an id format.

## Riscos e condições de aborto

- **Risco:** `OWNER_INVALID` if `laterOwner` is authored instead of derived — mitigação: the operation computes it with `ownerForSource(source.path, route)` and never accepts an override.
- **Risco:** collision with 15.1.3 in the same checker file and README — mitigação: the boundary above; this task ships first on `develop`, touches only the registration path and the "Regeneration and validation" section, and leaves retirement and the dispositions paragraph untouched.
- **Risco:** manifest digest drift or a half-written contract — mitigação: validate the pre-state binding before writing, write records and manifest in the same operation, abort before writing on any invariant failure.
- **Abortar se:** any condition in F01's `BLOCKED` list holds — sinalizar `blocked: true` with the exact diagnostic and record ids.
