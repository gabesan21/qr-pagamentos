# Plano — [[14.2.5-phase-verification]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** run the aggregate gate `pnpm check` on the integrated `develop`, realign the assertions the four Phase 14.2 tasks invalidated, add the regression coverage their checklists accumulated, apply the cheap in-phase repairs the judges left, regenerate the bound design-system evidence, and repair inside the phase's reach whatever the suite catches.
- **Resultado observável:** `pnpm check` exits 0 with no test lost against the post-14.1 baseline (2010 passing, 28 skipped, 0 lint errors), and every phase-checklist behavior is pinned by a test that fails if its task is reverted.

## Estratégia

Four sequential passes on the already-integrated code, never re-opening delivered behavior. **Pass 1 — realign:** run `pnpm test` first to get the real failure list, then update the assertions the four diffs falsified — `status-badge.test.tsx` (an `<svg>` per tone where a `bg-current` dot now draws), `standalone-payment-experience.test.tsx:152` (`bg-destructive` → `bg-danger-soft text-danger` on the four destructive terminals), the four list `page.test.tsx` that mock `next/navigation` without `useSearchParams` (the notice bridge now calls it), `settings-return-target.test.ts` (the closed `{ /settings, / }` allowlist became host-validated origin return) and `language-preference/route.test.ts` (the anonymous `401` became `303` + `qr_locale`). A test encoding the *old* behavior is realigned, never deleted. **Pass 2 — cover:** add the owed regressions next to their sources, reusing each file's existing idiom (`renderToStaticMarkup` for pages/components, hand-built `Request` + direct handler call for routes, node-side parsing for `globals.css`/`inventory.json`). **Pass 3 — repair:** the six cheap findings listed in Áreas afetadas, each inside a file the phase already owns. **Pass 4 — evidence:** one `pnpm design-system:evidence` + `pnpm design-system:evidence:verify` run, last, because passes 2–3 edit bound sources. Everything is direct pnpm; no Docker, no new dependency, no test-infra construction. Defects whose cause sits outside the four tasks' files stop and are recorded, not fixed (see Riscos).

## Riscos e condições de aborto

- **Risco:** a failure whose cause is a durable contract, not an assertion — mitigação: do not "fix" it here; record it in memory and propose a task/modification (WORKFLOW › Verificação de phase).
- **Risco:** `design-system:evidence` needs `pnpm start` to serve `/design-system`, which may demand a reachable database — mitigação: two attempts; if the server or `next build` needs DB/Docker, C13 is reclassified `user` under the `ambiente` stop rule and moves to the human checklist, without blocking the gate.
- **Risco:** client components (`shell-theme-picker`, `notice-toast`, `image-uploader`) resisting static rendering — mitigação: assert through the shell/page that mounts them or the module's exported contract; two attempts, then that criterion is reclassified `user`. **Abortar se:** the gate requires Docker or infra outside direct pnpm — sinalizar `blocked: true` with the failing command.
