- **Query contract:** register `state` (the eight provider states plus one explicit stateless value the adapter maps to `state: null`) and `merchant` (text; exact, case-insensitive owner-username equality) beside the delivered `source`/`money`/`from`/`to`/`link` — 7 filters, inside the spec's cap of eight. Filters only constrain columns that already exist; page sizes, the `(createdAt, id)` keyset, the cursor digest inputs, the `q` semantics and the `filter.<name>` grammar stay exactly as delivered, and the row DTO gains nothing. Validate before adapter I/O like the existing date filters.
- **Table:** columns merchant (monogram + username + deleted badge), payer, source (all three options in both the column and the select), link identifier as a compact `CopyField`, provider state, local outcome, amount, created, actions — the template's order. Adopt `ProviderStateBadge`/`LocalOutcomeBadge` with dictionary labels; a null provider state and `LOCAL_CANCELLED` have no member in those unions and render through `StatusBadge` with the matching tone. Keep the row href, the explicit action, the invalid-filters notice and the chip resolution delivered by 14.3.1.
- **V1 ledger:** do not merge it into the keyset page — V1 lives in another table, has no owner attribution and its service is byte-frozen. Keep the section below the directory and render it through an admin-local read-only table built from the owned table primitives so it reads like the directory's wide renderer. No new service, query or mutation.
