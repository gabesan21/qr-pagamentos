# Defesa do plano — [[12.3.1-rebuild-role-specific-application-shells]]

- **Etapa:** 002_planning · **Responsável:** agent planejador

## Decisões contestáveis

| # | Decisão | Escolha adotada | Alternativa rejeitada | Por quê | O que a falsificaria |
|---|---------|-----------------|------------------------|---------|----------------------|
| 1 | Local da fronteira cliente | `shell-navigation.tsx` único boundary; `app-shell.tsx` server-only | Boundary no layout ou múltiplos boundaries | Centraliza estado de drawer/menu/idioma e impede que auth/business cruzem para o server frame | Import de `@/auth` ou business DTO em `app-shell.tsx` |
| 2 | Largura do desktop rail | `248px` fixo, sticky full-height | Rail colapsável ou variável | Reproduz template com geometria determinística para evidence | Overflow horizontal ou quebra em 320px/1440px |
| 3 | Controle de idioma | Form POST nativo para `/language-preference` | Client-side locale prefix ou dropdown customizado | Preserva contrato existente de persistência sem rotas prefixadas | Falha em trocar locale ou introdução de rota `/[lang]/admin` |
| 4 | Menu de conta | Apenas `/profile` para merchant; nada para admin | Profile para admin ou mock switcher | Admin já tem gerenciamento de usuários; evita duplicação | Link de profile visível para admin ou sign-out quebrado |
| 5 | Footer | Strip fino dentro da coluna de conteúdo | Footer global com rotas novas | Alinha ao padrão template sem inventar páginas | Rotas inexistentes no footer ou quebra de layout mobile |
| 6 | Atualização de contrato parity | Refresh canônico de current-route para `/design-system` | Manter hash antigo | A página `/design-system` é afetada pelas mudanças de layout globais | `frontend-parity:check` falhando por SOURCE_HASH_STALE |
