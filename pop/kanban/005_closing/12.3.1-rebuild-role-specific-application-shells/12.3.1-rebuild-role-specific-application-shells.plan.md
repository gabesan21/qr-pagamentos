# 12.3.1-rebuild-role-specific-application-shells — Plan

## Objective

Rebuild the authenticated application shell for `ADMIN` (`/admin/**`) and merchant (`(merchant)/**`) layouts to reproduce the template visual system: persistent desktop rail, overlay mobile drawer, sticky top bar, account menu, language switcher, footer, and role-bound five-entry navigation. Authorization, session, locale-persistence, and sign-out contracts remain unchanged.

## Areas of change

- `src/app-shell/app-shell.tsx` — expand the presentational frame to accept top-bar title, account-menu labels, storefront link, language control, and footer; keep it free of auth/business data.
- `src/app-shell/shell-navigation.tsx` — remain the **only** client boundary; own pathname, mobile-drawer state, account-menu state, and language form.
- `src/app-shell/shell-types.ts` — extend `ShellNavigationItem` with an icon slot and add labels for the new chrome.
- `src/app-shell/app-shell.css` — replace the current sidebar-only layout with rail + top-bar + footer geometry, responsive visibility, and focus rules.
- `src/app/admin/layout.tsx` and `src/app/(merchant)/layout.tsx` — supply role-specific navigation inventories, labels, and the optional merchant storefront link.
- `src/i18n/dictionaries/app-shell/{en,pt-BR}.ts` — add keys for menu, language, profile, storefront, footer, and page titles; keep bilingual parity.
- `src/app-shell/app-shell.test.tsx` and `tests/app-shell.evidence.spec.ts` — update selectors, link counts, and visible identity assertions for the new shell.

## Implementation strategy

1. **Keep `AppShell` server-only and inert.** It receives only labels, links, identity nodes, username, locale, role label, optional storefront link, and children. No business DTO or credential crosses the boundary.
2. **Put all interactivity in `shell-navigation.tsx`.** It reads `usePathname()`, owns the mobile drawer and account menu disclosures, and hosts the language switcher form. It continues to import no auth or business modules.
3. **Navigation items** carry a Lucide icon, label, and href. Active state uses exact dashboard root or slash-delimited descendants, `aria-current="page"`, and a visible non-color accent marker.
4. **Desktop rail** is `248px`, sticky full-height, with brand lockup, the five navigation entries, and a user chip at the bottom.
5. **Mobile drawer** is a `248px` slide-in panel with overlay and close button; only one navigation copy is in the accessibility tree at a time.
6. **Top bar** is sticky `56px`: mobile menu toggle, dynamic page title, language switcher, optional merchant storefront link, and account menu (monogram + username + role badge + chevron).
7. **Language switcher** is a native `<form action="/language-preference" method="post">` with `<select name="locale">`; progressive enhancement submits on change. No locale-prefixed routes are introduced.
8. **Account menu** contains the merchant `/profile` link only; administrators get no profile entry. Sign-out posts to `/logout`. No mock role switcher or demo users.
9. **Footer** renders inside the authenticated content column as a thin powered-by + privacy + language strip, matching the template checkout/auth footer pattern without inventing routes.
10. Preserve the skip link, unobscured focus ring, `44×44px` targets, reduced motion, and `320px` fit.

## Fronts

No independent fronts: rail, drawer, top bar, account menu, and language control share the same props and client-boundary state, so they are built and verified together.

## Dependencies and risks

- **Dependencies:** existing `/logout` POST, `/language-preference` POST, role guards in `shell-context.ts`, `BrandIdentity`, and `Monogram` (already delivered).
- **Risk:** Evidence selectors and the frontend-parity contract depend on current shell structure. Rebuilding will require a fresh evidence run and a canonical parity refresh.
- **Risk:** Adding an icon slot to `ShellNavigationItem` is a type change for both layouts. Mitigation: update both layouts and tests in the same commit.
- **Risk:** Account menu could accidentally pull in auth code. Mitigation: keep username, role label, and profile/storefront links as props; `shell-navigation.tsx` remains the only client boundary and imports nothing from `@/auth` or business modules.

## Verification criteria

- `pnpm check` passes (`typecheck`, `lint`, `test`, `build`).
- `src/app-shell/app-shell.test.tsx` passes, including bilingual key parity and the five-entry navigation assertion.
- `pnpm app-shell:evidence` produces 50 captures (48 base + 2 mobile-open), zero serious/critical axe findings, no horizontal overflow, visible focused skip link, and all targets ≥ `44×44px`.
- `pnpm app-shell:evidence:verify` passes with an updated `artifacts/app-shell/<runId>/review.md`.
- `pnpm frontend-parity:check` passes after any canonical refresh.
- No auth or business imports are introduced into `src/app-shell/shell-navigation.tsx`.
