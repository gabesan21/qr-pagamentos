# 12.4.1-remodel-administrator-dashboard — Plan

## Objective

Remodel `src/app/admin/page.tsx` and `src/app/admin/dashboard.tsx` to match the supplied `/admin` template dashboard composition while preserving the existing server-only `AdminAnalyticsView` contract, exact per-currency facts, closed period set, redaction rules, and bilingual dictionary surface.

## Change areas

- `src/app/admin/dashboard.tsx` — layout, cards, progress bars, leaderboards, empty states, loading skeletons.
- `src/app/admin/page.tsx` — keep server-rendered shell context, period query handling, and notice strip.
- `src/i18n/dictionaries/admin-dashboard/{en,pt-BR}.ts` — add template-facing labels (overview caption, origin chips, provider-state tags, retry/stale, leaderboard navigation).
- `src/app/admin/dashboard.test.tsx`, `src/app/admin/page.test.tsx` — update assertions for new layout and facts.

## Strategy

Reuse the shared components delivered by task `12.2.3` (`StatCard`, `MoneyText`, `Monogram`, `CardSkeleton`, `TableSkeleton`, `StatGridSkeleton`, `EmptyState`, `Button`, `Alert`) and the existing `WorkspaceHeading` from `12.3.1`. Keep the page server-rendered and period changes as plain GET links; do not introduce client data fetching or a new animation dependency. Translate template-only mock behavior (mock query, retry toast, merchant filter drill-down) into production-safe equivalents that respect current contracts.

## Work fronts

1. **Layout and period switcher**
   - Compose the heading row with `WorkspaceHeading` on the left and a styled period switcher on the right.
   - Style the existing `AdminDashboardPeriodNavigation` as a segmented control using anchor links (`/admin?period=...`) so it remains server-rendered and keyboard operable.

2. **Stat cards and grids**
   - Replace `FactList` with `StatCard` for users (registered / active / deleted) and links/products (4 stats).
   - Deleted-user stat keeps a non-color danger dot cue.
   - Use `CardSkeleton` / `StatGridSkeleton` for the loading state.

3. **Orders, sales, and funnel card**
   - Orders card: render `createdInPeriod` as a large stat, add a progress bar segmented by source (`LINK` / `STANDALONE` / `AD_HOC`) with non-color origin chips, and provider-state tags below.
   - Sales card: render provider-confirmed and locally-finalized groups separately using `MoneyText` with formatted amounts and pair labels; never merge the two groups.
   - Funnel card: render attempts/converted/abandoned/in-progress with CSS-based progress bars and exact-decimal rates.

4. **Leaderboards**
   - Top owners: ordered list with rank, `Monogram`, username, deleted badge, confirmed orders, and confirmed volume via `MoneyText`.
   - Top products: ordered list with product fallback image/illustration, localized title, quantity, and revenue.
   - Owner rows link to `/admin/accounts` per the administrative foundation; do not replicate the template's mock `?merchant=` drill-down.

5. **Empty and error states**
   - Use `EmptyState` with existing `users`/`products` illustrations for empty leaderboards and `unavailable` for error recovery.
   - Preserve the current server error boundary; add a visible retry link only where it does not create a client data boundary.

6. **Dictionary and accessibility**
   - Add every new label to both `en.ts` and `pt-BR.ts`.
   - Ensure color is never the only state cue, focus rings are visible, and tables/lists use correct semantics.

## Dependencies

- `12.3.1-rebuild-role-specific-application-shells` — completed; `AppShell`, `WorkspaceHeading`, and admin navigation are available.
- `12.2.3` shared components — `StatCard`, `MoneyText`, `Monogram`, `Skeletons`, `EmptyState` are already in `src/components/ui/`.
- `10.1.1` admin analytics projection — `getAdminAnalyticsService` and `AdminAnalyticsView` are unchanged.

## Risks

- The template uses `framer-motion` and a client `useMockQuery`; the project has neither. We will use CSS transitions and stay server-rendered, which may differ in interaction feedback but matches the project's Next.js/Tailwind architecture.
- The template's leaderboard links to a mock merchant-filtered order URL; the spec routes owner attribution to `/admin/accounts`. Diverging from the template here is required by the administrative foundation.
- Adding new dictionary keys without breaking existing dashboard assertions.
