# Plano — [[14.1.1-repair-product-lifecycle-actions]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** make the two product lifecycle actions actually submit after confirmation, keep archived products inspectable read-only, and stop discarding merchant input when a catalog mutation fails.
- **Resultado observável:** on `/catalog/products/[id]` the confirmed Archive and Activate/Deactivate actions perform the mutation; an archived product still shows its data in a desaturated read-only form; a failed product or category create/edit lands back on the form that originated it, with the typed values still there and a visible opaque error.

## Estratégia

The mutation surface stays exactly as specified: native document `POST` to `/products` and `/product-categories`, guards, action set, service calls, exact-decimal handling and success redirects untouched. Nothing is intercepted by `fetch`, and no Server Action is introduced — both would duplicate or bypass the route contract the specs pin.

Three narrow moves. (1) **Lifecycle actions:** the `ConfirmDialog` `onConfirm` handlers must reach the real hidden forms — today they call `requestSubmit()` on refs that are never bound. Resolve the form the same way across the catalog confirmations (one mechanism, not two) and keep both confirmations in place. (2) **Archived read-only:** render `ProductForm` with `readOnly` instead of hiding it, inside a desaturated surface following the template's `ProductDetailPage`; in read-only mode the form renders as a non-submitting container — no `action="/products"`, no hidden action/id/version inputs, no submit control — so an archived product still exposes no mutation path. (3) **Failure return:** the originating form is already implied by the submitted action, so **no new form field and no path echoed from the client**: the route's `catch` maps `create → /catalog/products/new`, `update|active|archive → /catalog/products/<id>`, category actions → `/catalog/categories`, keeping the same closed opaque notice (`conflict|failed`); the two product form pages start reading that closed notice and rendering the existing `ProductNotice` (the categories page already does). Because a native POST navigates, the typed values are preserved on the client: one small shared helper stores the form's current values per form key on submit and restores them on load when the URL carries a failure notice, clearing the entry on success or clean load — same technique already used for the orders page-size preference. Copy is reused (`adminProductConflict`, `adminProductMutationFailed`, `catalogCategory*`), so no new dictionary key is expected, and the duplicated create submit is fixed while in these files: the page-level button in `new/page.tsx` goes, the form-owned one stays.

## Áreas afetadas

- `src/app/products/route.ts`, `src/app/product-categories/route.ts` — failure redirect target only, inside the existing `catch`.
- `src/app/(merchant)/catalog/product-form.tsx` (+ a new sibling draft helper) — read-only container, draft persist/restore, single submit.
- `src/app/(merchant)/catalog/products/[id]/product-detail-client.tsx` — confirmed submits, archived read-only branch.
- `src/app/(merchant)/catalog/products/{new,[id]}/page.tsx` — closed failure notice rendering; `categories/page.tsx` + `categories/category-row-actions.tsx` — draft restore for inline create/edit.

## Riscos e condições de aborto

- **Risco:** the draft restore leaks stale values into a later clean visit — mitigação: entry is session-scoped, keyed per form, written on submit and cleared on success or on a load without failure notice.
- **Risco:** the failure redirect becoming a client-supplied path (open-redirect surface) — mitigação: the target is derived server-side from the action and the submitted id; nothing from the client names a path.
- **Abortar se:** the delivery needs a new dictionary key, a `src/components/ui/**` change or a `DESIGN.md` decision — report to the main agent instead of editing; `blocked: true` with the exact missing contract.
