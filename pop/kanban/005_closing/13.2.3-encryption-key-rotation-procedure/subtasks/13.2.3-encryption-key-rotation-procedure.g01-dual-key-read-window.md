## Contrato de execução

- Pinned env names: `NAUTT_ENCRYPTION_KEY_PREVIOUS` and `TOTP_ENCRYPTION_KEY_PREVIOUS`, optional, same base64url/32-byte grammar and same error type as the current keys. Do not invent other names or a combined variable.
- Read path: try the current key first, then the previous one when configured. AES-256-GCM authentication makes a wrong key an exact failure — never widen an error class, never fall back to plaintext, never swallow a decryption failure when no key matches.
- Write path unchanged: `encrypt` and every issuance use only the current key. A previous key is never used to produce new material.
- Same window for MAC verification: the four checkout capability verifiers and `createDirectoryCursorCodec.decode` rederive with the current key and, on mismatch, with the previous one, preserving constant-time comparison. Encoding/minting stays current-key only, and `CAPABILITY_KEY_VERSION` stays `v1`.
- Absent previous key must reproduce today's behavior byte for byte; a configured but malformed previous key fails loudly at load, never silently ignored.
- Tests belong to this front: cover current, previous, absent and malformed for both modules, their consumers and the capability/cursor verifiers. **Do not run any test suite** — the phase task 13.2.4 runs the battery.
- Never log, print, return or embed key material, ciphertext, plaintext secrets or user identifiers in an error message.
- **Saber parar:** no máximo 2 tentativas quando a falha for de ambiente; na segunda, registre `ambiente` e siga.
- Dependência ou entrada ausente/incompatível → responder `BLOCKED` ao agente principal com evidência. Não implementar, simular ou corrigir dependências.
- Não alterar caminhos fora de `Owns`; necessidade nova volta ao agente principal.
