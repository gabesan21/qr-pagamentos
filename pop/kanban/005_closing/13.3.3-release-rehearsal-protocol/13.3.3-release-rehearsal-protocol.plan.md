# Plano — [[13.3.3-release-rehearsal-protocol]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** write a dated, repeatable release rehearsal protocol for the V2-only deployment and an evidence template that records each run, replacing the 2026-07-31 static waiver as the shape of proof.
- **Resultado observável:** `docs/release-rehearsal.md` gives the operator numbered steps, each with an exact command that already exists in this repo and its expected PASS line; `docs/release-evidence.md` gains a dated-run section the operator fills in, with the frozen 2026-07-21 candidate untouched.

## Estratégia

Documentation only. The rehearsal already has automation: `pop/scripts/container-test.mjs` implements `production-rehearsal` (install → admin login → merchant reset over a mock SMTP → media → storefront → checkout → no-op update → backup → restore), `identity-recovery` (`install/install.sh --recover-initial-admin`), `update` (rollback assertions), `install-lifecycle`, `media-backup`, `media-restore`; `install/test.sh` covers the static installer contract. The task therefore **reuses** those commands and **authors no new script or scenario** — every automated step cites an entry of the `allowed` scenario set (`container-test.mjs:23`). Steps with no automation (external callback reachability, operations on the operator's real install) are written as explicit operator steps using commands already documented in the runbook and `install/*.sh`, never as new tooling.

Structure the protocol in three blocks: **A — disposable harness** (clean-clone scenarios, repeatable, destroys only its own labelled project), **B — target deployment** (install/update/backup/restore/initial-admin recovery on a staging or production host), **C — external reachability** (the registered `NAUTT_WEBHOOK_CALLBACK_URL` answers from the public internet; local delivery simulation and signature forging stay out of scope per the 2026-09-23 decisions). Every execution step is `verify: user`: the agent never builds, runs or checks anything through Docker (root `AGENTS.md`), so this task only writes text. The evidence template is **additive**: a new section after the existing ones, one table per dated run, never a rewrite of the frozen ledger, its skip register or its handoff note. 13.3.1 rewrites the same files first; execution starts only after it is closed and rebases on its merged text.

- **Risco:** a step implies the agent runs Docker — mitigation: every execution step carries an explicit operator owner.
