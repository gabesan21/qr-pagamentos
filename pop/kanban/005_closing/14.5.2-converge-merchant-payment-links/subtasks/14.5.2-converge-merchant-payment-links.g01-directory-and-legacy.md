## Contrato de execução

- **Query contract:** register `era` (enum `v2`|`legacy`, default `v2` when absent), the currency filter (enum over the owner's active currency pairs, filtering `currencyPairId`; omit the control when the owner has none) and `from`/`to` calendar-day text filters, mirroring the delivered administrator directory's date semantics. Keep total registered filters at eight or fewer, and keep page sizes, keyset order, cursor digest inputs, `q` semantics and the row DTO exactly as delivered. Prefer an **additive optional parameter** on `resolveLinksDirectoryQuery` for the dynamic pair options so existing callers and doubles still compile.
- **Projection:** on `findForOwner` only, add the confirmed LINK-order count, the exact confirmed volume as a canonical decimal string, and a per-line product availability flag. Do not change `listWindow`, the row type consumed by the administrator module, or the opaque unavailable outcome. F03 consumes these members — report their exact names and types.
- **Money module:** `link-money.ts` is pure, client-safe (no `server-only`), and exports exact BigInt micro-unit multiplication by an integer quantity and summation of canonical decimal strings, at the price grammar's scale. `src/storefront/cart.ts` is the precedent and stays untouched; never import a `server-only` module into it.
- **Directory:** columns identifier (compact `CopyField`), summary, composition, type, state through `LinkLifecycleBadge` with dictionary labels, currency pair label, dates (created with expiry beneath), actions. Preserve the row href, the explicit action, the invalid-filters notice and the chip resolution.
- **Legacy era:** `era=legacy` renders the owner's V1 list through the same `DataDirectory` (no cursor, no page-size control), each row carrying the legacy chip and a client action opening a read-only modal with identifier, product, price, pair, type, expiry and state. `q`, state, type and `from`/`to` are applied to that list on the server. V1 create and revoke stay reachable inside this era in your own restyled source — never a capability removal, never a call into `@/app/admin/payment-link-management`, never an edit to a V1 service or route. Leave the admin file itself untouched.
- Every new or changed user-facing string lives in `payment-links-directory/{en,pt-BR}.ts` under the same key. You release this domain to F03 when you finish.
- **Saber parar:** no máximo 2 tentativas quando a falha for de ambiente; na segunda, registre `ambiente`, reporte a reclassificação para `verify: user` e siga. Nunca construa infraestrutura nova só para verificar.
- Dependência ou entrada ausente/incompatível → responder `BLOCKED` ao agente principal com evidência; nunca implementar ou simular a dependência.
- Não alterar caminhos fora de `Owns`; necessidade nova volta ao agente principal. Dublê de teste existente só pode receber ajuste mecânico de compilação.
