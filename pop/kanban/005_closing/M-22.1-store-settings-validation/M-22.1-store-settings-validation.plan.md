# Plano — [[M-22.1-store-settings-validation]]

- **Etapa:** 002_planning · **Papel:** `pop-planner`

## Objetivo e resultado esperado

- **Objective:** Make the merchant `/settings` Store identity easier to scan and prevent invalid identity data or activation, while retaining the other settings groups and the native Store save.
- **Observable result:** At narrow widths identity stacks in reading order; from `sm` (640px) it shows PT name / EN name on row one and slug / activation switch on row two. Invalid input cannot activate or persist; every editable Store text field has a contract-matched limit.

## Estratégia

Keep the existing `Field`/`Input`/`Switch`/`ConfirmDialog` controls, one native `POST /storefront` and logo upload form. Put the two localized names first in a responsive two-column grid, then slug and activation in a second row; validation notices remain associated with their fields and never disrupt the order. Do not turn the switch into a second save or alter Appearance, Payments, Currency, Connection, Policy, or Language.

Use rejection rather than silent filtering: show localized inline slug errors for uppercase, spaces, underscores, non-ASCII, leading/trailing/repeated hyphens, or >63 characters; preserve the attempted value for correction, and block activation and Store save until valid (blank is allowed only when disabled). Do not lowercase/strip a malformed slug or reinterpret conflicts; server continues the exact regex/opaque conflict path. Require slug and **both** display names, after the existing NFC/trim normalization, when enabling **and while enabled**; blank names remain nullable while disabled. A failed owner save has no mutation. Preserve no-JS native submission with the server as authority.

Field inventory: Store text inputs are slug (1–63 ASCII characters when set; `^[a-z0-9](-?[a-z0-9])*$`), PT/EN names (≤160 NFC Unicode code points each, trimmed and single-line), accent hex (optional, exactly `#RRGGBB`, 7 ASCII characters). Existing UI has `maxLength` 63/160/160/7 respectively; the service already enforces slug grammar/length, name code points/normalization, and hex grammar. Make name entry's browser limit agree with the service for astral characters (HTML `maxLength` counts UTF-16 units); keep server enforcement authoritative. Theme/layout/currency/toggles are closed choices, logo is an opaque 43-character hidden identifier and separate size/type-checked file form; keep their existing server contracts rather than imposing new arbitrary string limits. Connection API key, checkout policy, and language belong to other settings groups and are not changed.

## Riscos e condições de aborto

- Unicode: native `maxLength` is UTF-16 units but name validation counts NFC code points; do not accidentally reject a valid 160-code-point name or silently truncate paste. Validation must leave a correctable value and accessible PT/EN notice.
- Existing enabled records missing names or administrator edits may not satisfy the new owner UI rule: do not retroactively mutate rows or widen this task into the admin settings group; report any discovered contract conflict before widening scope. Preserve disabling and nullable names while disabled.
- Do not add raw visual values, expose ownership/collision details, change logo/media/currency merge semantics, or alter unrelated sections. Stop and return `BLOCKED` if an existing required contract makes the owner-only invariant impossible without an out-of-scope edit.
