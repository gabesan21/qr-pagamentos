## Execution contract

- The writer lives in `src/observability/` and reuses the discipline already proven by `server-request-log.ts`: server-only, one JSON line, console sink, failure to log is swallowed and never alters a thrown error, a response or a dispatch count.
- **Closed record membership:** the operation (a closed literal set), the HTTP status (or the transport-failure marker) and the provider `code`. Nothing else may be reachable from the record type — no response body or fragment of it, no headers, no request URL, no API key, no PIX payload, no customer data, no owner identity.
- **The code is allowlisted, never echoed:** a `code` is logged verbatim only when it belongs to the documented set ingested in the Nautt research; any other value — absent, unparseable, undocumented — logs one fixed marker. A provider-controlled string never reaches the log.
- Behaviour is unchanged: the same typed error classes, the same single `POST /orders/onramp`, no new retry, no new provider call, no new timeout, and `403`/`404` on the order read keep their single indistinguishable outcome.
- Restate the durable rule in `pop/specs/nautt-finance-integration.md` and the boundary rule in `src/integrations/nautt/AGENTS.md`; do not weaken the existing "never expose provider error bodies" fence — the new rule is its complement.
- Write and run no test: the assertions belong to [[15.2.4-phase-verification]] (criterion C9).
- **Knowing when to stop:** at most 2 attempts to make an `agent` criterion pass when the failure is environmental; on the second, record `ambiente`, report the reclassification to `verify: user` and move on. Never build new infrastructure just to verify.
- Missing or incompatible expected input → answer `BLOCKED` to the main agent with evidence. Never implement, simulate or repair the dependency, and never change paths outside `Owns`.
