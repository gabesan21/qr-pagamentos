# Plano — [[14.3.1-live-directory-toolbar-and-rows]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** turn `DataDirectory` into the template's `FilterBar`/`DataTable` pair on top of server-rendered data — search/filters/page size write the canonical URL on change, chips render localized on every directory, rows navigate, invalid params resolve to the reset state with an info toast, and `src/data-directory/AGENTS.md` is revised to own this behaviour.
- **Resultado observável:** on every merchant and admin directory, typing in search or changing a filter re-renders the list with no button press (skeleton while the server re-renders), applied filters show as removable localized chips, clicking a row opens its detail, and a hand-edited bad URL lands on the unfiltered list with a "filters ignored" toast and no echoed value.

## Estratégia

The server stays the data owner. The `<form method="get">` foundation stays in the markup — it is the no-JS path and the source of the `q` / `filter.*` / `pageSize` field names — but the client shell becomes a thin URL-state controller: search debounced ~350ms, every other control on `change`, each commit building the canonical query and calling `useRouter().replace(..., { scroll: false })` inside `useTransition`. `cursor` is always dropped on a commit, being bound to the filter digest; while the transition is pending the shell renders its existing geometry-preserving skeleton. Apply/Reset move into `<noscript>` (precedent: `orders-notices.tsx`); the visible template action is one ghost "Clear filters" anchor to `resetUrl`, shown only when chips exist, and a documented opt-out keeps the design-system gallery from navigating. Chips stop printing raw values: the client resolves each `filter.<name>` through the registered enum options and falls back to the submitted text for text/calendar filters, so localization comes from definitions the page already passes — but four consumers omit `canonicalFilterQuery` today and must pass it. Rows gain an optional server-evaluated `getRowHref`; the row/card click handler ignores clicks originating inside an interactive descendant, so `CopyField` and the explicit action keep working, and that action stays the keyboard path. Pagination keeps keyset prev/next only and adopts the template footer bar (rows-per-page left, prev/next right); the page-size select keeps its `${idPrefix}-page-size` id and gains `form=` so the GET form still owns it from the footer.

Invalid input becomes a route, not a card: a page (or its directory service) resolving `invalid-query` issues the existing zero-I/O redirect to its reset path plus one reserved `?filters=ignored` pair, and the reset render raises an info toast through the `NoticeToast` bridge with a `<noscript>` fallback. **Every** query resolver must strip that reserved pair before canonicalization — one that forgets turns the redirect into a loop. The `invalid-query` component state is not deleted: it stays declared (specimen, coverage, DESIGN.md) with no production producer. The seven near-identical `directory-copy.ts` files all change with the copy contract, so they collapse into one shared builder; the other consumer duplications (`pageUrl`, `firstValue`, `isValidSeekTuple`, `…CanonicalTarget`) are out of scope and stay recorded as debt in the card.

## Riscos e condições de aborto

- **Risco:** a resolver that does not strip the reserved pair turns the invalid redirect into a loop — mitigação: shared constant + criterion 8, conferido por leitura em cada resolvedor.
- **Risco:** co-located tests assert Apply/Reset and the invalid card, e a galeria monta seis specimens que passariam a navegar — mitigação: opt-out inerte (critério 7) e ajuste das asserções invalidadas **sem rodar teste**; falha residual é de `14.3.3`.
- **Abortar se:** honrar o critério 5 exigir apagar um estado declarado em `src/app/design-system/coverage.ts` — sinalizar `blocked: true` com a entrada da coverage.
