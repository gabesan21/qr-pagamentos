# 12.6.1-remodel-public-payment-link-checkout — Plan

## Objective

Align the public payment-link checkout under `src/app/pay/[identifier]/**` with the Epoch 12 template visual system while preserving every existing business, security, redaction, exact-decimal, V1/V2 lifecycle, and accessibility contract.

## Scope areas

- V1 checkout page, form, and unavailable/error/loading surfaces.
- V2 branded checkout page, form, paid terminal view, and unavailable/error/loading surfaces.
- Shared payment presentation primitives used by the checkout journey.
- The checkout evidence spec and its captured state matrix.

## Strategy

1. Read the template parity authority for `/pay/:identifier` and the current production surfaces, then map each template-presented state to the existing server-derived state machine without inventing or removing states.
2. Apply DTCG tokens, typography, spacing, radii, elevation, and focus rules from `DESIGN.md` and `pop/specs/application-frontend-system.md`; keep every business DTO, route, and mutation unchanged.
3. Compose with the shared inventory (`MoneyText`, `QrDisplay`, `CopyField`, `StatusBadge`, `Button`, `Card`, `Field`, `Alert`) rather than forking styles.
4. Preserve the V2 two-column composition contract unless the template parity checker proves a single-column layout is required; record the layout decision and its evidence disposition.
5. Update the evidence run so it exercises the same policy variants, QR/copy, polling, retry, privacy, terminal, paid, and unavailable states against the new visual structure.

## Dependencies

- `12.3.3-phase-verification` must be closed; the shared design-system evidence, token lint, and frontend-parity contract must be stable before product-route remodeling.
- Shared primitives delivered by `12.2.3` (`QrDisplay`, `CopyField`, `MoneyText`, `StatusBadge`) must be in their final ownership state.
- V1 checkout service/routes and V2 `checkout_attempt_v2` reservation/capability contracts remain untouched; this task changes presentation only.

## Real risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| Template single-column layout conflicts with the existing V2 two-column contract. | Parity failure or accidental weakening of the V2 composition boundary. | Treat the existing V2 two-column contract as authoritative; adapt template tokens/spacing to it and record the disposition in the parity manifest. |
| Reusing shared primitives forces prop changes that leak into other routes. | Scope creep and regression in unrelated surfaces. | Extend shared primitives only additively; if a prop is checkout-only, wrap locally rather than mutating the shared owner. |
| Motion/animation from the template violates reduced-motion or adds inaccessible focus jumps. | WCAG 2.2 AA failure. | Use `motion-safe` equivalents; keep focus stable and states complete under `prefers-reduced-motion: reduce`. |
| Evidence test selectors depend on current class names. | Broken evidence run after visual changes. | Update selectors and the source-hash inventory together with the code. |
| V1 is declared byte-frozen in behavior but not in presentation. | Unintended route or DTO change. | Restrict edits to JSX and class names; do not touch request bodies, endpoints, or polling cadence. |

## Acceptance and verification criteria

- `pnpm lint`, `pnpm typecheck`, and `pnpm test` pass after the changes.
- `pnpm design-system:evidence:verify` and `pnpm frontend-parity:check` remain valid; any parity disposition change is recorded.
- The checkout evidence run captures 127 screenshots and asserts the same state matrix (policy variants, QR/copy, polling, retry, terminals, paid, unavailable, 320 px reflow).
- WCAG 2.2 AA holds: all targets ≥44×44 px, focus visible, contrast ≥4.5:1 for normal text, no horizontal overflow at 320 px, no external requests, no console/page errors.
- V1 and V2 routes, request bodies, response handling, polling intervals, retry semantics, and redaction boundaries are unchanged.
