# Plano — [[15.3.3-checkout-template-and-a11y-convergence]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** the public checkout surface obeys the vocabulary and the AA rules already declared in `DESIGN.md` — one polite live region announcing the payment state, the `INDETERMINATE` line on a soft warning surface, a locale-aware `loading`, the declared `max-w-checkout` / `font-display` / `bg-accent` utilities in place of ad-hoc forms, a 44 px privacy trigger, and a scroll to the first invalid field that respects reduced motion.
- **Resultado observável:** a screen reader on `/pay/[identifier]` announces each state transition once, through the badge channel, without the copy button's channel duplicating it; the "confirming with the bank" line reads at AA over its own tint; a buyer with `qr_locale=en` never sees a pt-BR skeleton; the privacy trigger is tappable on a phone; with `prefers-reduced-motion: reduce` an invalid submit jumps to the field instead of animating.

## Estratégia

This is the phase's last task and its **conflict integrator**: it rebases over 15.3.1 (explicit no-retry states) and 15.3.2 (`NONE` customer block) and resolves whatever residue those two leave in the two adapters, without re-opening their decisions. Scope is the **public checkout surface only** (`src/app/pay/[identifier]/**` plus `src/app/store/[slug]/pay/loading.tsx`): finding A9's wider drift (`text-muted-foreground`, `bg-card`, `rounded-lg`) and A11's steppers/period controls are Phase 15.4. Every change is an **in-place edit of an existing file** — nothing under `src/` is created, renamed or deleted — which is what keeps the parity ledger's `currentComponents` targets stable and `docs/frontend-template-parity/**` out of this diff.

Three pinned choices bound the execution. **One channel:** exactly one `aria-live="polite"` region on the live payment view, enclosing the state badge and its adjacent state line; `CopyField` keeps its own announcement, nothing else on that view gains live semantics, and the region never encloses a `role="alert"` node. **AA wins over byte parity:** the template renders the `INDETERMINATE` line as `text-warning`, but `DESIGN.md` requires `text-<role>-on-soft` over the soft tint, the same pairing `StatusPill` already uses. **The CSS collapse is not enough:** `globals.css` neutralizes `scroll-behavior`, but a JS `scrollIntoView({ behavior: "smooth" })` overrides the computed value, so the gate belongs in the controller. Both `loading.tsx` read `qr_locale` through the helpers `page.tsx` already uses, falling back to `defaultLocale`; the route is already dynamic, so no rendering-mode decision is introduced. Tests are **updated, never run** here (the run is 15.3.4), and no durable contract changes — the rules already exist in `DESIGN.md` and in the frontend spec.

## Riscos e condições de aborto

- **Risco:** the accent whitelist in `scripts/check-design-tokens.mjs` is keyed by exact path and expression, so the `bg-primary` → `bg-accent` swap must leave the `--storefront-accent` inline style byte-identical — mitigation: that attribute is out of scope and the script is `must_not_edit`; needing to widen the whitelist aborts.
- **Risco:** file names under `src/app/pay/[identifier]/**` may have changed in 15.1.1's V1 removal — mitigation: the write set is read as a pattern over the surface; a renamed counterpart is the same owned file, a missing counterpart is `BLOCKED`.
- **Risco:** a second live region (a status `Alert`, an `EmptyState` `role="alert"`) double-announces the state — mitigation: C1 inspects the whole live view, not only the badge.
- **Abortar se:** `15.3.1` or `15.3.2` has no ledger in `pop/memory/<data>/`, the live view still exposes a retry affordance, or a change would require editing `DESIGN.md`, a spec or `docs/frontend-template-parity/**` — sinalizar `blocked: true` com path e linha.
