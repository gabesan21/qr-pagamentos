## Contrato de execução

- Reuse `ConfirmDialog` from `src/components/ui/modal.tsx` exactly as delivered — it already accepts a typed `confirmation` requirement; never create a second dialog or button style.
- The confirmation module is the only new client boundary: pages stay server components and pass it only ids, usernames and localized labels. The `<form method="post">` it submits is rendered by that same module, with the `ref` attached to that element (or the submit bound through the `form` attribute) — the detached-ref defect of `product-detail-client.tsx` is a known bug, not a pattern to copy.
- Both deletions require the target username typed to enable confirm; TOTP disable is a destructive confirm without typed input.
- The drill-down fix is the emitted query string only: `filter.link=<url-encoded identifier>`. If the `link` filter does not resolve against the V2 link identifier, stop and report `BLOCKED` — do not add a filter, service or API.
- Every user-facing string enters both `en` and `pt-BR` dictionaries; no literal copy in components.
- **Saber parar:** no máximo 2 tentativas de fazer um critério `agent` passar quando a falha é de ambiente; na segunda, registre `ambiente`, reporte a reclassificação para `verify: user` e siga.
- Dependência ou entrada ausente/incompatível → responder `BLOCKED` ao agente principal com evidência.
- Não alterar caminhos fora de `Owns`; necessidade nova volta ao agente principal.
