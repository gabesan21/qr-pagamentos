## Contrato de execução

- **Query contract:** register `state` — the eight provider states plus one explicit stateless value the adapter maps to `state: null` — beside the delivered `source`/`money`/`from`/`to`/`link`, for six filters total. Filters only constrain columns that already exist; page sizes, the `(createdAt, id)` keyset, the cursor digest inputs, the `q` semantics and the `filter.<name>` grammar stay exactly as delivered, and the row DTO gains nothing. Validate before adapter I/O like the delivered date filters, and keep the zero-I/O invalid path.
- **No `outcome` filter and no currency-pair filter.** The current outcome is the newest append of an append-only ledger and "latest is X" needs raw SQL or a denormalized column; registered filters are closed static enums while pair labels are dynamic registry rows. Keep the `money` (`USD`/`FIAT`) filter and the outcome column, and record both gaps in the report.
- **Table:** payer, source, link identifier as a compact `CopyField`, provider state, local outcome, amount, created, actions — the template's order — using the domain badge families with dictionary-supplied labels. Keep the delivered row href, the explicit keyboard-reachable action, the invalid-filters notice, the page-size preference and the chip resolution; never add totals, page numbers, arbitrary sorting or client-side row filtering.
- **Legacy V1 section:** do not merge it into the keyset page — V1 lives in another table behind a byte-frozen service. Keep the section below the directory and render it through a merchant-local read-only table built from the owned table primitives so it reads like the directory's wide renderer. No new service, query or mutation, and no edit to the shared `order-views.tsx`.
- **Stability contract for F03:** `ORDERS_NOTICE_KEY`, `ORDERS_NOTICE_VALUES`, `OrdersNotice` and `OrdersSearchParams` keep their names, shapes and semantics — the V2 detail page imports them.
- Every new or changed user-facing string lives in `orders-directory/en.ts` and `orders-directory/pt-BR.ts` under the same key.
- **Saber parar:** no máximo 2 tentativas quando a falha for de ambiente; na segunda, registre `ambiente`, reporte a reclassificação para `verify: user` e siga. Nunca construa infraestrutura nova só para verificar.
