## Front notes

- The resolver keeps today's host validation exactly (first `X-Forwarded-Host`, else `Host`, lowercased compare) and stops consulting the `{ /settings, / }` allowlist. It now returns the Referer's **path plus query**, drops the fragment, and accepts only a value starting with a single `/`; absent, unparseable, foreign-scheme, foreign-host, `//`-prefixed and scheme-bearing inputs all fall back to `/`. Keep the `#settings-language` anchor for a `/settings` return. Update the file's header comment — the current one documents the closed allowlist and would become a lie.
- The route drops the blanket `401`. An authenticated caller keeps the persisted-preference path unchanged; an anonymous caller gets `qr_locale` set with the same attributes `src/app/profile/password/route.ts` already uses (httpOnly, SameSite=Lax, secure in production, path `/`, one year). No `qr_session` read or write changes, and the same-origin guard stays first.
- `qr_locale` is already the anonymous resolution source in the root layout, login, reset and `/design-system` — reuse it, do not invent a second mechanism.
- `/pay/[identifier]/page.tsx`, `/store/[slug]/page.tsx` and `/store/[slug]/pay/page.tsx` currently hardcode `defaultLocale` on their anonymous branch; resolve `localeFromPreferenceCookie` there instead. The authenticated branch stays untouched. The public footer that will carry the visible control belongs to 14.6.1 — do not add it here.
- The compact switcher is a small client component in `src/app/language-preference/`: globe icon plus a `PT`/`EN` select that submits the existing POST form on change, ≥44px target, `aria-label` from the shared `languageLabel` string passed in as a prop (dictionaries are `server-only`). Style it with Tailwind utilities only — the `.auth-*` rules live in `globals.css`, which is closed. Do not extract or reuse the shell's `LanguageSwitcherForm`: it is a different, labelled variant and belongs to 14.4.1.
- Login and reset stay opaque: mount the switcher without adding any principal read, and leave their existing form-error Alerts alone.
- `route.test.ts` asserts today's `401` for anonymous; update it and add the resolver's hostile-input cases. Do not run tests — verification is `phase` (14.2.5).
- Spec sync: `administrative-foundation.md` states the closed `{ /settings, / }` allowlist (mutation-endpoint paragraph) and the "self-only preference" route-family row. Update both to the widened origin return and the anonymous capability, weakening nothing else.
