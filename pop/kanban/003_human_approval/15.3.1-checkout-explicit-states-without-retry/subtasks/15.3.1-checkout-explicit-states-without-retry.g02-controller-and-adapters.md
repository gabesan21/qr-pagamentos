## Execution contract

- **Pinned by the human (do not reopen):** no retry, automatic or manual; `checkoutStartOver` is the only action and it re-keys the attempt; the 5 s visibility-aware read stays because it is state observation; server-side idempotent replay stays untouched; the opaque `404` treatment (submit or poll) stays exactly as it is.
- **Polling rule to deliver:** a successful non-terminal read reschedules at 5 s; a **failed read stops the loop** — no reschedule, no backoff, no failure counter — and raises the failed-status-read flag that renders F01's *status unavailable*; polling keeps observing while the state is non-terminal, so a later successful read still flips the view. Remove `retryPoll`, `pollRetryTick`, `pollFailed`, the failure counter and the `1s·2^n` expression from both clients.
- **Submit rule to deliver:** every submit mints a fresh idempotency key — the "reuse the stored attempt" fallback disappears from both clients. A failed submit (non-ok, network, malformed body) renders F01's named submit-failure composition with `checkoutStartOver` as the only action, replacing the resubmit affordance; `startOver` stays the single reset and must clear the new flag too. Drop the `checkoutRetry`/`attemptMade` submit-label branch on both routes.
- **Polling controller:** import it from wherever Phase 15.1 left it. If it has no V2 home after the V1 removal, report `BLOCKED` — never recreate or resurrect a V1 module.
- **Evidence specs:** remove the captures of the retired retry affordances and add captures for the named states. **Never run them** — they are Docker/user-exclusive (criterion C09, `verify: user`).
- **Tests:** update the controller/adapter tests so they assert the new machine and no longer assert removed affordances. **Never run any test** — behavior proof is criterion `phase`, owned by 15.3.4.
- **Do not touch:** `pixQrCodeUrl` and the response parsers' DTO shape (15.2.3), the customer-data block (15.3.2), `aria-live`/tone/token vocabulary and `loading.tsx` (15.3.3).
