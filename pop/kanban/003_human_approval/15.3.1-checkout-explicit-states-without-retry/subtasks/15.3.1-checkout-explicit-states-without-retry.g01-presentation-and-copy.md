## Execution contract

- **Pinned by the human (do not reopen):** no automatic or manual retry anywhere; `checkoutStartOver` is the only action in every non-confirmed state; the 5 s read stays (it lives in F02); a waiting treatment is honest only while the status can still change.
- **View state map to deliver** — `CONFIRMED` and `REFUNDED` unchanged; `CANCELLED`/`EXPIRED`/`REJECTED` keep the terminal-failure composition (the template's `PaymentPhase` terminal block is the reference, but never its "new payment" or "check again" affordances); `RESERVED`/`CREATING`/`CREATED` render the waiting treatment — badge, amount, `aria-busy` on the waiting region, **no QR frame, no pulsing square and no caption promising data**; `PENDING` with payload renders QR + copy-paste; `PENDING` without payload, `INDETERMINATE`, and a rejected QR generation render *PIX unavailable*; a failed status read (flag supplied by F02) renders *status unavailable*.
- **Props contract for F02 (fix it, then report it):** remove `onRetryPoll` and `pollFailed`; add one boolean-style flag that names a failed status read; keep `pixQrCodeUrl` exactly as it is today (15.2.3 owns it) and never use it as a PIX source or fallback.
- **Shared composition:** export one named-state composition (title, body, `checkoutStartOver` as the single action, reusing the owned `EmptyState`/`ProviderStateBadge` vocabulary) so F02's adapters render the submit-failure state through it instead of inventing a second treatment.
- **`QrDisplay`:** report a rejected generation to the caller through an **additive optional** prop; a blank framed square is never an acceptable outcome. `totp-qr-code` and `/design-system` must keep their current behavior with no call-site change. Honor `src/components/ui/AGENTS.md` (additive props, `inventory.json`, `DESIGN.md`, `node scripts/check-shared-ui-inventory.mjs` only if the inventory changed).
- **Dictionaries:** remove `checkoutRetry`, `checkoutCheckAgain`, `checkoutPollErrorBanner`, `checkoutRetryStatus`, `checkoutGeneratingQr`; rewrite any copy that invites a retry or promises arriving data (`checkoutErrorDescription`, `checkoutStatusError*`, `checkoutWaitingPaymentData`, `checkoutConfirmingWithBank`) or delete it when the state that used it is gone; add the new state copy. `en.ts` and `pt-BR.ts` must end with identical key sets. Do not touch `checkoutErrorHeading`'s use in `error.tsx` semantics beyond the copy itself.
- **Tests:** update `checkout-payment-views.test.tsx` and `qr-display.test.tsx` so they assert the new states and no longer assert removed affordances. **Never run any test** — behavior proof is criterion `phase`, owned by 15.3.4.
- **Do not touch:** the customer-data block (15.3.2), `aria-live`, warning-tone tokens, `max-w-checkout`/`font-display`/`bg-accent` vocabulary and `loading.tsx` (15.3.3).
