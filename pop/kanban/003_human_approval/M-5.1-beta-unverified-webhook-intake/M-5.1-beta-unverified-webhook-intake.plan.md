# M-5.1-beta-unverified-webhook-intake — Plan

- **Objective:** accept Nautt webhook bodies without HMAC signature verification for the closed beta (human decision 2026-07-25), as one loudly-marked, trivially reversible seam, keeping bounded body, dedup, lease, reconciliation, and the empty no-store protocol statuses otherwise intact — plus the full registration trail (research on-hold, decision record, pre-production gate, spec/DOX edits).
- **Strategy:** replace only the authentication block inside `createWebhookIntake` with a beta owner-attribution step; everything downstream (claim, lease, reconcile, finalize, statuses) runs unchanged.

## Bypass seam (decided)

One seam: `src/integrations/nautt/webhook-intake.ts`, inside `createWebhookIntake`.

1. Delete nothing. Mark the change with a prominent comment: `BETA(M-5.1): unverified webhook intake — human decision 2026-07-25; HMAC verification skipped entirely; MUST be reversed before production. Reversal: restore the signature gate + verifyOwner block and the 401 status; remove resolveOwner.`
2. Verification is skipped entirely — missing, malformed, and present-but-invalid `X-Nautt-Signature` are all accepted (the human's "accept the body without verifying" read literally; no partial verification).
3. Owner attribution without HMAC: parse the envelope first, then resolve the owner from the local `provider_order` table by `providerOrderUuid` (globally `@unique` in `prisma/schema.prisma:276`) via a new injected dependency `resolveOwner(providerOrderUuid) => Promise<string | null>`. Production wiring lives in `webhook-runtime.ts` as a direct Prisma `findFirst({ where: { providerOrderUuid }, select: { ownerId: true } })` loader, next to `loadActiveWebhookSecrets`.
4. With the owner resolved, the existing claim/lease/reconcile/finalize path runs exactly as-is (`reconcileWebhookOrder(ownerId, providerOrderUuid)` and `findWebhookActionable` are untouched).
5. `WebhookIntakeResult` narrows to `204 | 400 | 503` with a BETA comment — `401` is suspended during beta and restored on reversal. `route.ts` needs no change (its `empty()` union is a superset).
6. Beta attribution outcomes (documented deviations, restored on reversal):
   - Valid envelope, resolvable owner → identical to today (`204` after durable processed/ignored decision).
   - Valid envelope, unknown provider order UUID → `204` ignored **without** evidence (no claim row possible: `webhook_delivery.owner_id` is NOT NULL). Replay re-runs only a cheap local lookup; zero provider GETs.
   - Malformed body: parse rejected identity; resolvable owner → REJECTED evidence exactly as today; unresolvable → `400` without evidence.
7. `loadCandidates` and `verifyOwner` are never called in beta (zero secret loads, zero decryption, zero HMAC) — pinned by spy assertions in tests. `webhook-runtime.ts` keeps wiring `loadActiveWebhookSecrets` so reversal stays one small diff.

## webhook-signature.ts fate (decided)

- `webhook-signature.ts`, `webhook-secret-candidates.ts` and their tests are kept **intact** — they are the reversal target and their unit tests still pass unchanged. Never delete them to hide the bypass.
- `webhook-intake.test.ts` is updated, not gutted: former 401 cases become beta-acceptance pins (missing / malformed / present-but-wrong signature all accepted), plus zero-`loadCandidates`/zero-`verifyOwner` assertions and the new attribution outcomes above.

## Deny

- Never delete or neuter `webhook-signature.ts`, `webhook-secret-candidates.ts`, or their tests.
- Never change the 256 KiB bounded body, dedup/lease/delivery-store semantics, reconciliation CAS or the one-GET economic bound, or the meaning of `204`/`400`/`413`/`503`.
- Never emit `401` for signature failure; never put the bypass behind an ENV/config toggle (unconditional marked code seam — a flag would add production-forgetfulness surface).
- No schema/migration changes, no new routes, no provider calls, no origin-guard / rate-limiter / server-request-log changes.
- Never persist raw body or signature in delivery evidence (existing rule stands).

## Risks

- Any internet caller who learns a provider order UUID can trigger one owner-bound provider GET — mitigated by UUID unguessability, the one-GET bound, dedup/lease, and closed-beta exposure; the pre-production gate is the fix.
- Parse-before-trust: unauthenticated malformed bodies now reach the parser — the 256 KiB bound caps cost; no state change occurs without a resolvable owner.
- Unknown-order deliveries lose durable ignored evidence during beta (accepted deviation; replay cost is one local indexed lookup).
