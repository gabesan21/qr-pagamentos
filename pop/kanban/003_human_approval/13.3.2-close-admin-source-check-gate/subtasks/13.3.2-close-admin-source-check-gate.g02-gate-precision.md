## Contrato de execução

- **Exemption 1 — shell BEM, rule-backed.** A `__` token is sanctioned only for files under `src/app-shell/**` **and** only when `src/app-shell/app-shell.css` (read relative to the scanned root) defines a matching selector. A multi-class literal is sanctioned only when **every** whitespace-separated token resolves. Outside `src/app-shell/**`, `__` remains a hard `local_variants` failure — no other subtree may own a BEM stylesheet (`src/app-shell/AGENTS.md`, `DESIGN.md` §"BEM retirement (14.7.1)"). **Do not** implement this as a prefix allowance or as a list of literals: the rule must keep failing a shell class whose rule was deleted.
- **Exemption 2 — token references.** A `--` occurrence inside a `var(--…)` reference is the sanctioned token channel and is not a variant; it mirrors the authorization `scripts/check-design-tokens.mjs` already grants (`:7`, `:32-38`) and the `max-w-[var(--layout-max)]` exception preserved by the 15.4.1 closed map. A `--modifier` that is **not** inside a `var(…)` reference stays a hard failure.
- **Both exemptions carry a comment naming the task and the exact contract they mirror**, in the shape the 15.4.1 repairs already use in this file. An exemption without that comment is the debt this task exists to stop repeating.
- **Prune what the rules make dead:** allow-list entries that no source uses and entries the new rules already cover. Removing them must not make any current file fail — check each before deleting.
- **The suite must not silently stop covering the shell path.** The fixture writes `src/app-shell/frame.tsx` with `app-shell__content`; under Exemption 1 that root also needs an `app-shell.css` defining the selector, or the "exact zero counters" case starts failing for the wrong reason. Add one case per exemption and keep the existing `rejects local_variants` case intact.
- **Não rode teste nem `pnpm admin:source-check`**: C1/C6/C7 são `verify: phase` e rodam em 13.3.4. Sua evidência é o mapeamento por leitura.
