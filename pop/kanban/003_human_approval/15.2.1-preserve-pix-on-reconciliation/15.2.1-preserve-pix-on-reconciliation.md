# 15.2.1-preserve-pix-on-reconciliation — Preserve PIX on reconciliation

- **Origem:** [[pop/roadmap/15-v2-only-pix-integrity-and-explicit-checkout|Phase 15.2]]
- **Plano:** [[15.2.1-preserve-pix-on-reconciliation.plan]] · **Aprovação:** [[15.2.1-preserve-pix-on-reconciliation.approval]] · **Verificação:** [[15.2.1-preserve-pix-on-reconciliation.verify]]

## O quê

`reconcile` in `provider-order-store.ts` (Prisma and in-memory) writes `pixCopyPaste`/`pixQrcodeUrl` only when the authoritative `GET /orders/{uuid}` carries a value; a stored PIX payload survives every status/version update. Regression tests cover a PIX-bearing fixture reconciled by a read without `payment_data.qrcode`.

## Por quê

Today any active-order webhook can null the buyer's PIX code mid-payment (finding A1) and no test protects it.
