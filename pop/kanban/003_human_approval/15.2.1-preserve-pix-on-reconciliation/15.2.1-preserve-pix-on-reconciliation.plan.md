# Plano — [[15.2.1-preserve-pix-on-reconciliation]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** `reconcile` merges the authoritative `GET /orders/{uuid}` into the stored provider order **without** clearing `pixCopyPaste`/`pixQrcodeUrl` when the read omits them — in the Prisma store and in the in-memory double — leaving the versioned compare-and-swap untouched.
- **Resultado observável:** a buyer whose order already carries a PIX payload keeps the copy-and-paste code through every active-order webhook or poll reconciliation; a regression test in each store fails if the write goes back to overwriting.

## Estratégia

`orderData` is shared by `completeCreation` and `reconcile` (`provider-order-store.ts:49-61`) and forces `pixCopyPaste: order.pixCopyPaste ?? null`. Creation writes that explicit `null` onto a fresh row and **stays exactly as it is**; only the reconciliation write changes, by omitting the two PIX keys when the parsed view has no value. Prisma leaves an omitted column untouched and the in-memory spread keeps the current value, so no new null-handling rule enters the domain. Keep the omission in one named helper consumed by `reconcile` in both stores, so the two implementations cannot drift.

Nothing else in `reconcile` moves: the gating predicates (`isActiveCreated`, `isKnownRecovery`, provider-UUID match), the `where` tuple (owner, provider UUID, `creationState`, `status`, `reconciliationVersion`), the version increment and the post-write re-read are byte-identical in intent before and after. Absence is the provider's documented "field omitted when empty" ([[pop/researches/nautt-finance/raw/orders/get-order|GET /orders/{uuid}]]), never a signal to clear local state; a PIX value **present** in the read still overwrites the stored one.

Tests are written here and executed only in [[15.2.4-phase-verification]]. The in-memory case drives the real store end to end; the Prisma case extends the existing durable fake in `provider-order-store.test.ts` with `providerOrder.updateMany`/`findUniqueOrThrow` (process-local, no database, no Docker) and asserts the update payload. Build every fixture from the `StoredProviderOrder` type as it exists after 15.1.4 — never reintroduce a V1 field.
