## Strategy

This is the only task of the phase where running tests is an `agent` criterion. Every command runs through **direct pnpm** — never containers. If a `pnpm <script>` invocation fails for reasons of the package manager or a Node/pin mismatch (see the recon note A12), re-run the same work through `./node_modules/.bin/<bin>` or `node scripts/<file>.mjs`: the fallback is the same criterion by another path and **does not consume a verification attempt**. Setup is not a criterion failure: if `src/generated/prisma` is missing run `pnpm precheck`; a fresh worktree install uses `SHARP_IGNORE_GLOBAL_LIBVIPS=1 pnpm install --frozen-lockfile` ([[pop/notes/references/limites-de-verificacao|verification limits]]).

Writing tests is work of **this** task: 15.3.1 delegated C03/C04/C05 (named states, waiting rule, rejected generation) and 15.3.2 delegated C6 (`NONE` block absent on both surfaces) to the phase run. The existing suites already carry much of this; the verifier reads each named file, keeps what holds, and adds or tightens only the assertions a criterion below demands — no new coverage beyond the phase's scope.

**Repair reach.** The verifier repairs only what Phase 15.3 falsified: asserts, snapshots, dictionaries and inventories that the phase diff made stale, plus its own edits' desyncs. A durable-contract defect, a structurally unmet request from an earlier task or anything outside the phase is **not fixed here** — it becomes a proposal for a modification or a new task, recorded in the task memory with the evidence. Docker-dependent verification never enters the agent's reach; it is born `user`.

**Review and environment.** The same run applies [[.agents/skills/clean-code-review/SKILL|clean-code-review]] to the integrated phase diff (15.3.1→15.3.3) and [[.agents/skills/ui-review/SKILL|ui-review]] to the renderable checkout surfaces in what is verifiable without Docker: Nielsen heuristics and WCAG 2.2 AA read from markup, dictionaries and tokens — **no screenshot/vision loop**, pixel evidence belongs to the human checklist. An `agent` criterion gets **two attempts** when the failure is environmental (sandbox, permission, flakiness); on the second, record `ambiente` in the telemetry, reclassify it as `verify: user` with a Log line, move it to the human checklist and go on. Never build infrastructure to make a criterion runnable, and an environment failure never returns the task.

## Riscos e condições de aborto

- **Risk:** `frontend-parity:check` can diverge because its semantic derivation reads the gitignored generated Prisma client — follow-up F2 registered in [[15.1.4-phase-verification]]. Mitigation: the phase pass is **zero divergence class attributable to 15.3's own files**; residue of the known class is left to F2 and named in the memory, never silenced by a broad `--refresh-semantic-contract`. A red test rooted before the phase follows the repair reach: record, do not fix.
- **Abortar se:** a failure is reproducible and rooted in a durable contract (spec/DOX) rather than in the phase diff — `blocked: true` with the failing command, output excerpt and the proposed task/modification.
