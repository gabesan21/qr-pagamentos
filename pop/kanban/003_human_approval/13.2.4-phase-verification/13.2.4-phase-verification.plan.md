# Plan — [[13.2.4-phase-verification]]

- **Stage:** 002_planning · **Role:** `pop-planner` (separate from execution)

## Objective and expected result

- **Objective:** run Phase 13.2's accumulated checklist once, on the integrated 13.2.1→13.2.3 tree, via direct pnpm; repair only defects inside the phase; consolidate the Docker-dependent items into one human checklist.
- **Observable result:** `pnpm check` green with the phase's new suites, the three lifecycle changes proven together, and every remaining proof either a named human item or a recorded out-of-reach proposal.

## Strategy

Planned **before** the sibling tasks execute, from their approved plans in 003. The checklist below is therefore anticipated: the first act of 004 is to re-read the three final plans and their ledgers and, where execution diverged (renamed module, extra criterion, front split), amend this plan by `lacuna` — append rows, never renumber. Criterion 1 is that precondition.

This is the phase's single task where **running tests is an `agent` criterion**, so the `005_closing` gate may legitimately demand a re-run; criteria 14-17 are human and never block it. **Docker remains user-exclusive:** `pnpm db:test`, `install/test.sh`, compose and any container build are never executed here. Installer and one-shot code is proven statically instead (`bash -n`, `node --check`, `container:contract-check`), which is the whole reach the agent has over that surface.

**Repair reach is the phase.** The verifier fixes falsified tests anywhere the phase diff made them stale (the 15.2.4 lesson: `owns` must already cover out-of-phase fixtures) and product code inside the three tasks' write sets. A wrong durable contract — spec text, DOX line, runbook step, a structurally unmet request from a sibling task — is **not** fixed here: it becomes a proposal recorded in memory (criterion 12). **Environment:** if pnpm aborts on the Node pin mismatch, run the equivalent direct binaries (`tsc --noEmit`, `eslint .`, `vitest run`, `next build`) and record `ambiente`; a fresh worktree installs with `SHARP_IGNORE_GLOBAL_LIBVIPS=1 pnpm install --frozen-lockfile` ([[pop/notes/references/limites-de-verificacao|verification limits]]); at most 2 attempts per environment failure. Failures that predate the phase (e.g. the red `admin:source-check`, owned by Phase 13.3) are recorded, never repaired here.

## Risks and abort conditions

- **Risk:** the anticipated checklist diverges from what executed — mitigation: criterion 1 re-reads the final plans and amends by `lacuna` before running anything.
- **Risk:** a failure outside the phase's reach blocks the battery (15.2.4 round 1) — mitigation: `owns` already covers every `*.test.ts`; product repair outside the phase is a proposal, not an edit.
- **Risk:** the installer/one-shot surface is only statically checkable — accepted: static checks here, real behavior on the human checklist.
- **Abort if:** a checklist criterion can only pass by changing a durable contract or by running Docker — flag `blocked: true` naming the criterion and the blocking constraint.
