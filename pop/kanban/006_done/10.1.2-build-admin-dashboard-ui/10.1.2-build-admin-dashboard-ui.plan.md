# Plan — [[10.1.2-build-admin-dashboard-ui]]

- **Stage:** 002_planning · **Responsible:** planner agent

## Objective and expected result

- **Objective:** replace the `EmptyWorkspace` placeholder on `/admin` with the server-rendered, bilingual administrator dashboard composed over the delivered 10.1.1 global projection (`src/orders/admin-analytics.ts`), with period controls, the two never-merged sales groups, KPI counts, funnel, bounded leaderboards with deleted-owner treatment, and explicit loading/empty/error states.
- **Observable result:** an active administrator landing on `/admin` sees users, orders, sales, funnel, link/product counts, and top-5 owner/product leaderboards for the selected period; every section renders localized empty states when empty; the run-bound `admin-dashboard:evidence` pair proves the composition across themes, locales, and widths. No new route, mutation, client data fetching, or projection change.

## Strategy

Pure read-only server composition; the projection is consumed exactly as delivered (`getAdminAnalyticsService().getGlobal(principal, period)` inside the page, after `requireAdminShellContext`). Six pinned decisions the executor must not revisit:

1. **No charts.** DESIGN.md bans decorative charts; quantitative composition is ruled ledger `Card`s, fact `<dl>`s, and captioned native `Table`s from the owned shadcn inventory, mirroring the 8.4.2 merchant dashboard composition (`src/app/(merchant)/dashboard.tsx`) as the visual precedent.
2. **Period handling mirrors 8.4.2.** Closed `today`/`7d`/`30d` set; absent, unknown, or service-rejected (`invalid-period`) values re-query and render the pinned `7d` default (no redirect); switching is plain GET links to `/admin?period=<id>` with the current entry a non-link `aria-current="page"` span marked by type/underline, never color alone.
3. **Sales and money discipline.** `confirmedSales` and `locallyFinalizedSales` render as two separate ruled groups, never summed or merged anywhere; amounts render exact-decimal per currency pair via `formatCatalogPrice`, never through `Number`; null-code/unlabeled pairs get the explicit localized unlabeled treatment; rates render as exact-decimal localized percents with an explicit n/a on null.
4. **Sections and their source members** (one card each, in order): period navigation; Users (`registeredTotal`/`activeNow`/`deletedTotal`); Orders (`createdInPeriod` + by-source and by-state fact lists — the null state gets an explicit localized "no provider state" label); Sales (decision 3); Funnel (attempts/converted/abandoned/in-progress + rates); Links & products counts; Top owners; Top products. Users, links, and products counts are period-independent and carry an explicit localized caption saying so.
5. **Deleted-owner treatment.** Leaderboard rows with `owner.deleted` render a distinct localized non-color badge (Badge inventory, not color alone); aggregates never change.
6. **No cross-role imports.** The admin dashboard owns its local period-navigation component and its local copy of the pure four-digit rate-to-percent shifter; it never imports from `src/app/(merchant)/` or any merchant module, and never passes a business DTO into `src/app-shell/` (shell stays inert).

The existing `/admin` notice strip (`?success`/`?error` alerts) and the shell (`layout.tsx`, `guard.ts`, `shell-context.ts`, `error.tsx`, `loading.tsx`) stay byte-unchanged; service failures propagate to the existing admin error boundary, and the existing bilingual `loading.tsx` skeleton is the loading state. Dictionaries arrive as a new `src/i18n/dictionaries/admin-dashboard/{en,pt-BR}.ts` slice merged into the two aggregators.

## Risks and abort conditions

- **Risk:** shared-file collisions with in-flight 10.2.1 (004) and approved siblings (10.2.2/10.3.2/10.3.3) on `scripts/run-admin-evidence.mjs`, `package.json`, dictionary aggregators, root `AGENTS.md`, and the administrative-foundation spec — mitigation: strictly additive minimal hunks in every shared file; the roadmap already serializes final integration of shared admin shell/dictionaries; the orchestrator resolves overlaps keeping both additive blocks.
- **Risk:** merging or summing the two sales groups or cross-currency totals in a "headline" KPI — mitigation: decision 3 + tests asserting the split and per-pair lines; 005 reads against the spec definitions.
- **Risk:** redaction regression through rendering (pair UUIDs, owner email, payer data) — mitigation: the DTO carries none; page tests assert absence in rendered HTML; no new route means the observability/rate-limit inventories stay untouched.
- **Risk:** dictionary key drift or parity break — mitigation: single new slice, parity tests in F01.
- **Abort if:** the delivered DTO proves insufficient for a required section (would force a projection change, which is out of scope) — signal `blocked: true` with the missing member and the spec line.
- **Abort if:** a shared file (runner, aggregators, spec) has been structurally rewritten by in-flight work so additive edits are impossible — signal `blocked: true` with the conflicting diff.
