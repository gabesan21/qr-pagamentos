# Plan — 7.2.3 Build product and category management

## Objective

Deliver the bilingual merchant catalog workspace: dedicated product and
category list/create/edit pages under `/catalog` with image upload (placeholders
+ size guidance), currency/category selects, and honest terminal archive states —
a pure UI/route composition over the integrated 7.2.1/7.2.2 services. No service,
schema, media, or payment-link/checkout internals change.

## Strategy

One cohesive front, one executor. Evolve the existing `/catalog` scaffold (today
rendering V1 `OwnerProductManagement`) into a routed workspace, reuse the owned
shadcn inventory and the `src/data-directory/ui` composition, and add exactly one
new mutation route (product-image staging). Tone, tokens, six mandatory states,
and WCAG 2.2 AA follow `ui-change` against the existing DESIGN.md
"PIX settlement desk" direction — no tone work needed, only new-state registration.

## Information architecture

- `/catalog` — products directory (replaces the current single-card page):
  `src/data-directory/ui` composition fed by `productService.listForOwner`;
  columns: 48px image thumbnail (`GET /media/[identifier]`, ACTIVE-only) or the
  official brand merchant-fallback placeholder (never a page-local asset),
  internal name, localized title, locale-formatted exact price + nullable
  currency code, category name, state badge (active/inactive/archived — never
  color-only); row actions: edit (non-archived) / view (archived). States:
  ready/loading/empty (+create CTA)/error; search + state/category filters via
  GET toolbar. Decision: single-page directory (no cursor URLs) — the product
  store exposes no keyset contract and service internals are denied territory;
  owner catalogs are bounded. Executor may adopt the foundation's
  canonical-request parsing if it fits without editing `src/data-directory/**`;
  otherwise page-local strict form decoding with zero-I/O invalid paths and
  canonical `307` resets.
- `/catalog/products/new` and `/catalog/products/[id]` — create/edit forms
  (FieldGroup/Field, labels above inputs, one primary action): existing V1 text
  fields + category `NativeSelect` (active own categories only; inactive ones
  absent), currency `NativeSelect` from registry `listActiveChoices` redacted
  `{code,label}`, image upload block, archive action (edit page only).
  Archived `[id]` renders read-only facts with the archived badge and terminal
  explanation — no edit/active/delete/archive controls.
- `/catalog/categories` — categories directory (same composition) with inline
  create (bilingual name fields) and per-row edit; deactivation opens an inline
  destructive-confirmation block with a replacement-category select (distinct
  active own categories) when products reference it, mirroring the service's
  atomic reassignment; deactivated rows are retained, badge-marked, edit-locked.
- CAS conflict (`?…=conflict`) and opaque failure (`?…=failed`) notices render
  as destructive `Alert`s on the referring page, matching existing doctrine.

## Mutation routes (no service edits)

- Reuse `POST /products` and `POST /product-categories` unchanged in behavior;
  the front may repoint their relative redirect targets from `/?products=…` /
  `/?categories=…` to the new `/catalog…` pages and update their route tests —
  that is route wiring, not service internals.
- New `POST /products/images`: origin-guard first, `requireOwnerFromCookie`,
  bounded multipart parse (reject >5 MiB before decode), `mediaService.create(
  actor, "PRODUCT_IMAGE", bytes)` → `200 {identifier}` with `Cache-Control:
  no-store`; every failure is one opaque empty `422`-class/`401` outcome with no
  decoder detail. Registered in `serverRequestRoutes` (literal template) and
  wrapped in `withServerRequestLog`. No rate-limiter integration (closed surface
  per `src/security/public-rate-limit.ts` doctrine).
- Dirty-field omission (7.1.3 pattern): the client posts `categoryId`,
  `currencyCode`, `imageMediaId` only when changed — absent = unchanged, so an
  unchanged stored currency never re-gates after a later mapping deactivation.
  Currency select empty state: when `listActiveChoices` is empty, render the
  select disabled with an explanation alert (no admin contact detail, no UUIDs);
  a stored code still displays as a disabled factual row.

## Upload UX

Client hints mirror, never replace, server validation: `accept="image/jpeg,
image/png,image/webp"`, ≤5 MiB and ≤4096×4096 stated in copy, ideal-dimension
guidance (square, ≥600×600) from dictionary keys. Flow: staging route returns
identifier → hidden `imageMediaId` field + STAGED preview via
`GET /media/[identifier]` (owner may read own STAGED) → product save activates;
remove/replace clears the hidden field. Placeholder when no image: the official
brand merchant fallback from `src/brand/` (DESIGN.md identity rules), identical
in all six themes via `currentColor`.

## Risks

- Data-directory server contract expects cursor adapters the denied services
  cannot provide → settled by the single-page-directory decision above; flag in
  the verify note if the composition forces pagination URLs.
- 7.1.3 may later add a storefront-logo staging route with the same shape —
  keep `/products/images` product-scoped; no shared abstraction now.
- Native-form architecture: staging upload needs a small focused client
  boundary (fetch + hidden field + preview); keep it observation-only like the
  existing `ProductSubmit` pattern, never replacing the native `/products` POST.
