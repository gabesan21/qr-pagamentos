# Plan — [[9.1.2-build-storefront-catalog-and-cart]]

- **Stage:** 002_planning · **Responsible:** planner agent

## Objective and expected result

- **Objective:** rebuild the sessionless `/store/[slug]` page into the bilingual branded catalog experience: the merchant theme/logo/accent applied, catalog groups rendered in the owner's `boxed` or `table` layout, a standalone custom-amount first item when `standalonePayments` is on, per-product quantities, and a slug-scoped versioned browser-local cart with exact-decimal totals and stale-item recovery.
- **Observable result:** a buyer browses grouped products in both layouts and locales, adds products (1–9,999 each) and at most one custom amount to a cart that survives reload under the store slug, sees per-currency exact totals, and gets a localized notice when the store changed and stale entries were dropped. No server cart, no checkout command (9.1.3 owns it), no rate-limit/request-log/sessionless-route change (9.2.1 owns those).

## Strategy

SSR page + one focused client cart boundary; the projection from 9.1.1 is the only data source. Pinned decisions the executor must not revisit:

1. **Catalog replaces the V1 list on the page.** The page renders the grouped `catalog` as the single browsing surface and stops rendering the V1 link-driven `products` section; the `products` DTO member and its projection tests stay byte-frozen, and `/pay/[identifier]` links remain reachable directly. Rationale: no duplicated product presentation; phase 9.1 ships as one unit, and 9.1.3 restores the purchase path via cart checkout. Until then the cart has **no checkout control at all** — no disabled tease, no speculative copy.
2. **One additive projection member.** Add `standalonePaymentCurrencyCode: string | null` (the stored store-default code — display metadata only, surviving registry deactivation, never a pair UUID or inactive-code discovery surface). Same amendment class as 9.1.1's resolved product currency code; it exists so the custom-amount item and cart totals are honestly labelled. This is the task's single deliberate redaction-boundary amendment (spec + root `AGENTS.md` updated at closeout; flagged for 005).
3. **Cart is a pure, versioned, slug-scoped envelope.** localStorage key `qr-pagamentos:storefront-cart:v1:<slug>`; payload `{ version: 1, items }` where an item is `{ kind: "product", reference, quantity }` (integer 1–9,999, the V2 line bounds) or the single `{ kind: "custom-amount", amount }` (canonical positive-decimal grammar, same class as `PRICE_PATTERN` in `src/auth/product.ts:64`). Unknown version or unparseable payload discards silently. Only references and quantities persist — never prices or totals.
4. **Stale-item recovery at every hydration.** The client reconciles the stored cart against the server-rendered catalog snapshot: entries whose `reference` is absent or `available: false` are dropped, quantities are clamped, and exactly one localized "cart was updated" notice appears when anything changed. The cart never trusts stored data beyond item identity.
5. **Exact totals, never `Number`.** A small pure (framework-free, no `server-only` import) cart module owns the amount grammar, BigInt decimal arithmetic at the grammar's 6-place scale, reconciliation, and serialization. Server BigInt money modules (`src/orders/*`) are not client-safe and must not be imported. Totals are grouped per resolved currency code and never summed across currencies; a null-code group renders without a code label. Amounts render as canonical decimal strings with `tabular-nums` (existing storefront precedent), no float/`Intl.NumberFormat` money conversion.
6. **Theme and brand.** The shell scopes the resolved theme with `data-theme-preview={themeId}` on `<main>` (existing scoped-token mechanism, precedent `src/app/storefront-preview.tsx:53`) and keeps `--storefront-accent`. The logo renders via `<img src="/media/[identifier]">` with a localized alt when `logoMediaIdentifier` is set; otherwise `BrandIdentity variant="merchant-fallback"` stays (brand contract: fallback only while no merchant image exists). No new primitives — compose `Card`, `Button`, `Input`, `Table`, `Alert`, `Skeleton`, `Badge` per the ui-change inventory rule; token-semantic CSS only in the existing `globals.css` storefront block.
7. **States per ui-change/DESIGN.md.** Loading: catalog+cart skeletons in `loading.tsx`. Empty: no groups and standalone off → the existing opaque empty treatment; standalone on → the custom-amount item alone is a non-empty store. Unavailable: the existing one opaque null state, unchanged. Error: one opaque localized error with a retry link (App Router `error.tsx` for the route, echoing no detail). Overflow: 9,999 quantity cap, bounded groups/products (projection `take` caps stand), `overflow-wrap` on names, tabular figures. Cart-empty, cart-populated, and cart-recovered-notice states all render. Quantity steppers and controls ≥44px, keyboard reachable, visible focus, non-color markers; 320px fit.
8. **Zero edits to the parallel task's surface:** `src/security/public-rate-limit.ts`, `src/observability/server-request-log.ts`, and every sessionless command route stay untouched; no new route of any kind.

## Risks and abort conditions

- **Risk:** redaction drift via the new currency member or the cart snapshot embedding server data — mitigation: absence assertions stay green; the page embeds only the delivered redacted DTO.
- **Risk:** float money creeping into totals — mitigation: unit tests pin exact decimal strings (e.g. `0.000001` scale, 9,999-quantity multiplication); 005 greps for `Number(`/parseFloat in the cart module.
- **Risk:** collision with 9.2.1's worktree on shared files — mitigation: write sets are disjoint by construction; orchestrator validates the diff contains zero 9.2.1-owned paths.
- **Risk:** V1-list removal regresses the only purchase path if 9.1.3 slips — accepted deliberately (phase ships as one unit; decision 1); the 005 critic re-checks it against the card objective.
- **Abort if:** the scoped-theme mechanism cannot recolor the page without token/CSS-generator changes (that would violate F02's scope) — signal `blocked: true` with evidence.
- **Abort if:** honest standalone-item labelling proves impossible with the additive member (e.g. 9.2.1 concurrently rewires the projection) — signal `blocked: true`, do not improvise a second data source.
