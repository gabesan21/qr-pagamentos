## Original request

Card What/Why: bilingual boxed/table storefront views with merchant branding, standalone payment as the first item when enabled, product quantities, a slug-scoped versioned localStorage cart, exact totals, and stale-item recovery — buyers assemble a cart without server state until they choose to pay.

Delivered against every clause:

- Boxed/table: `storefront-experience.tsx` renders `Card` grids or ruled `Table` rows per the owner's layout (`data-layout`), in both locales; `page.test.tsx` asserts both.
- Standalone first item: custom-amount block precedes the groups; `page.test.tsx` pins `indexOf("Valor livre") < indexOf("Cafés")`; the standalone item alone makes a store non-empty (test-pinned).
- Quantities: steppers + numeric input, clamped 1–9,999, disabled at bounds.
- Cart: `qr-pagamentos:storefront-cart:v1:<slug>`, envelope `{ version: 1, items }`, only references/quantities/one amount persisted; unknown versions and unparseable payloads discard silently (unit-tested).
- Exact totals: `src/storefront/cart.ts` does BigInt micro-unit arithmetic at the 6-place grammar scale, grouped per currency code and never summed across codes; grep confirms zero `Number(`/`parseFloat` in the money path (`Number.parseInt` touches only the quantity draft, which is not money).
- Stale-item recovery: hydration reconciles against the server-rendered snapshot (stale/unavailable drop, clamp, dedupe, custom amount only while standalone is on) with exactly one localized notice; unit tests and run-bound captures prove it.
- No checkout control anywhere in the cart UI — correctly deferred to 9.1.3.

## Findings

- **nit** — `src/storefront/cart.ts:67`: `BigInt(fraction || "0")` — the `|| "0"` fallback is dead (`fraction` is always six padded characters). Harmless.
- **nit** — `artifacts/storefront/20260726031015/manifest.json` `gitHead` records `5cd65d4` while HEAD is `904c856`: the BigInt-literal style fix rode the working tree through the run and was committed after binding. The manifest's `sourceHashes` match HEAD exactly (verified by re-running the verifier and by manual `sha256sum` comparison), so the run is honest at the delivered tree; `gitHead` is informational and unchecked by the verifier.
- **nit** — `scripts/verify-storefront-evidence.mjs:63`: `states("-logo")` relies on suffix non-collision with `-logo-fallback`; true today, but a future state named `*-logo` variant could silently widen the filter.

No `bloqueante`, no `sugestão` that changes behavior.
