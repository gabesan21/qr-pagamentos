## Fences

- **No new routes/mutations:** build route table unchanged; page is server-rendered GET only; period switching is plain links (no POST, no origin guard needed).
- **Projection frozen:** `merchant-analytics.ts` byte-identical; the UI consumes only the exported DTO types.
- **Closed period set with 7d fallback:** service returns `invalid-period` before any DB work; page re-reads `7d` and throws only if even the pinned default is rejected (impossible).
- **Never summed:** separate `SalesGroups` sections; unit test and evidence both assert the summed amount string is absent.
- **No trend charts:** none present; ruled/tabular only, per DESIGN.md.

## Deviations judged

1. **Bare `getStorefrontSettingsService().getForOwner(principal)` (no null branch):** justified. The Prisma store `get` is `findUnique` on the user row; `requireMerchantShellContext()` has already re-resolved an active merchant principal, so a null row is impossible. `requireSettings` would throw `ForbiddenError` only in that impossible case. The plan's "null settings row = hidden" was predicated on a nullable read that the delivered service does not have; gating on `storefrontEnabled && storefrontSlug !== null` covers every reachable hidden case.
2. **Additive `--merchant-dashboard` mode in `scripts/run-admin-evidence.mjs`:** correct maintenance, not ownership invasion — the harness is the shared disposable-runtime runner; the new mode mirrors `--links`/`--catalog` and is pinned in the evidence source-hash inventory.
3. **No charts despite the card's "charts/tables" wording:** projection has no time-series; widening it was explicitly out of bounds (abort condition). Documented in plan, DESIGN.md, and spec. Non-blocking.
