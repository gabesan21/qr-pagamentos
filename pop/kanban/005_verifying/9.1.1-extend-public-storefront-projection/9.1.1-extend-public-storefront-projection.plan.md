# Plan — [[9.1.1-extend-public-storefront-projection]]

- **Stage:** 002_planning · **Responsible:** planner agent

## Objective and expected result

- **Objective:** extend the server-only public storefront projection (`src/storefront/public-storefront.ts`, consumed by the sessionless `/store/[slug]` page) from branding-only to a redacted public catalog: active categories (grouped, bilingual names), active products with image media identifier, exact-decimal price, resolved display currency code, availability, an opaque per-product cart reference, and the standalone-payments capability flag — while amending the durable redaction boundary (spec + root `AGENTS.md`) deliberately and preserving every existing opaque/unavailable outcome.
- **Observable result:** `/store/[slug]` keeps rendering exactly as today, and the projection DTO additionally carries the catalog/capability data that 9.1.2 (catalog+cart UI), 9.1.3 (one-time cart links), 9.2.x (standalone payments), and 9.3.1 (branded checkout) will consume — with contract tests proving no owner identity, credential, provider, or toggle-raw data crosses the boundary.

## Strategy

Pure read-projection evolution; no new route, no mutation, no UI rebuild (9.1.2 owns views). Three pinned decisions the executor must not revisit (each is an explicit spec amendment reviewed at the critical 003 gate):

1. **Catalog eligibility broadens.** Today a product reaches the public page only through an active unexpired V1 payment link. The cart flow (9.1.2/9.1.3) makes the product itself the browsing unit, so the new catalog member exposes every active (non-archived) product of the storefront owner. The existing `products` member (V1-link-driven, with `paymentLinkIdentifier`) stays byte-compatible and the `/store/[slug]` page stays unchanged; the new data arrives as additive DTO members only.
2. **Public-safe references and currency.** The per-product cart reference is the product's canonical UUID — opaque, unguessable, and never trusted: 9.1.3 revalidates every cart item server-side (same posture as the pair UUIDs already exposed by `GET /api/payment-links/[identifier]`). The resolved display currency code (product `currency_code` ?? store default) is exposed as display metadata so 9.1.2 can render exact totals; provider pair UUIDs stay out of the storefront projection. Both amend the current "never exposes the default currency code / internal UUIDs" redaction line.
3. **Capability flag, not raw toggle.** The projection exposes a single derived `standalonePayments` capability boolean for 9.2.2's entry point; the enabled gate and all other toggle semantics stay hidden.

Rate limiting: **no change**. `src/security/public-rate-limit.ts` keeps its closed three-route surface; `/store/[slug]` is an SSR page read and stays outside it (per contract, pages are never added lightly). 9.1.3 owns the limiter-inventory extension for its future cart command route. Reads stay bounded: deterministic ordering plus explicit `take` caps on categories and products. Branding resolution (display name, accent, theme, layout, logo) remains in this module as the single source 9.3.1 will reuse; this task adds no checkout consumer.

## Risks and abort conditions

- **Risk:** redaction regression — owner identity, credential state, provider data, raw toggle values, or internal fields (ids beyond the product UUID, versions, timestamps) leak into the public DTO — mitigation: whitelist DTO typing plus explicit absence assertions in contract tests; 005 reads the DTO against the amended boundary.
- **Risk:** unbounded catalog read on a sessionless page — mitigation: closed ordering + `take` caps asserted by tests.
- **Risk:** exposing currency/product-UUID erodes the redaction posture more than intended — mitigation: both are explicit spec amendments reviewed at the critical 003 gate before execution.
- **Abort if:** the 003 critic rejects decision 2 (UUID reference and/or currency exposure) — signal `blocked: true` with the critic's objection; replan with the alternative (no currency exposure, or a minted per-product public identifier column).
- **Abort if:** keeping the current page byte-stable proves impossible without touching V1 behavior — signal `blocked: true` with the conflicting test/page evidence.
