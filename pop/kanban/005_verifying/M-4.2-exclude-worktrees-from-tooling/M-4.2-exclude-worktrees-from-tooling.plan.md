# M-4.2-exclude-worktrees-from-tooling — 002 plan

## Objective

Stop `pop/worktrees/**` from leaking into main-checkout tooling so `pnpm check`
stays green while task worktrees exist. M-4.1 already fixed Vitest; this task
closes the remaining leaks.

## Recon findings (2026-07-25)

Per-tool scan of the main checkout, from the configs as they exist today:

- **`tsconfig.json` — LEAKS.** `include` is `**/*.ts(x/mts)` with
  `exclude: ["node_modules"]` only, so `tsc --noEmit` (and `next build`'s type
  checking, which reuses tsconfig) compiles `pop/worktrees/**`. This is the
  observed TS2739 failure.
- **`eslint.config.mjs` — clean.** Already has `pop/worktrees/**` in
  `globalIgnores`, and `scripts/check-epoch1-source.mjs` contract-tests that
  ignore (fails if it regresses).
- **`vitest.config.ts` — clean** (M-4.1).
- **Repo scripts (`scripts/*.mjs`) — clean.** Every `readdir`/walk is anchored
  to a fixed subtree: `check-design-tokens.mjs` and
  `check-admin-ui-inventory.mjs` walk only `src/**` roots; `generate-brand-assets.mjs`
  reads `public/brand` + fixed manifest paths; `verify-*-evidence.mjs` read only
  their own `artifacts/<name>` run dir; `check-admin-contract-sync.mjs` and
  `generate-design-tokens.mjs` read fixed files. None descends into `pop/`.
- **`pop_validate.py` — clean.** `LINK_SKIP_PARTS` and the pop-hash/link checks
  already skip `worktrees`.
- **`next build` — covered transitively** by the tsconfig fix (its type check
  honors `include`/`exclude`); pages are discovered only under `src/app`.

## Front

One executor owns exactly:

1. `tsconfig.json` — add `"pop/worktrees"` to `exclude` (keep `"node_modules"`;
   do not touch `include`, so no tracked source is hidden).
2. `scripts/check-epoch1-source.mjs` — extend the existing worktree-isolation
   contract (it already guards the ESLint ignore) with one `requireSource`
   assertion that `tsconfig.json` excludes `pop/worktrees`, mirroring the
   ESLint guard so the exclusion cannot silently regress.

Must not edit: `src/**`, `eslint.config.mjs`, `vitest.config.ts`,
`next.config.ts`, any other `scripts/*.mjs`, `pop/**` outside this plan, kanban
cards (orchestrator-owned).

## Execution steps

1. Edit `tsconfig.json` `exclude` to `["node_modules", "pop/worktrees"]`.
2. Add the tsconfig assertion to `scripts/check-epoch1-source.mjs` next to the
   existing ESLint worktree guard (same `requireSource` helper).
3. Verify (acceptance below).

## Acceptance criteria

1. Create a synthetic dummy worktree `pop/worktrees/dummy-m42/src/broken.ts`
   containing deliberately invalid TS (e.g. an unsatisfied object literal),
   then on the main checkout: `CI=true pnpm typecheck`, `CI=true pnpm lint`,
   and `CI=true pnpm check` all pass. Remove the dummy afterwards.
2. With no worktrees present: `CI=true pnpm typecheck`, `CI=true pnpm lint`,
   `CI=true pnpm check` all pass.
3. `node scripts/check-epoch1-source.mjs` passes with the new assertion;
   `pop_validate` (run per harness convention) stays valid.
4. `git ls-files pop/worktrees` stays empty — the exclusion hides only
   untracked task worktrees, never tracked source.

## Risks

- **Over-broad exclusion:** only `pop/worktrees` is added; `include` is
  untouched and criterion 4 proves no tracked file lives there. Any future
  tracked code under `pop/worktrees/` would be silently untyped — mitigated by
  the convention (worktrees are disposable, git-ignored) and criterion 4.
- **Regression of the exclusion:** mitigated by the new contract assertion in
  `check-epoch1-source.mjs`, same pattern as the existing ESLint guard.
- **`pnpm check` runtime:** full gate includes `vitest` + `next build`; both
  already clean, expected green unchanged.

## Contracts / specs impact

- No AGENTS.md contract changes expected: root AGENTS.md does not pin
  tsconfig exclude contents. Executor re-checks during 004 closeout.
- No spec changes: tooling-only, no application behavior.
