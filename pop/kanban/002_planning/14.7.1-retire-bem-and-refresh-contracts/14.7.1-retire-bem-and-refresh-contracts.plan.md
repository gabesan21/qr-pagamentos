# Plan — [[14.7.1-retire-bem-and-refresh-contracts]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** end the parallel CSS system — every route-scoped BEM rule left in `src/app/globals.css` either loses its last consumer and is deleted, or is named as a sanctioned exception with the reason it cannot be a utility — and align `DESIGN.md`, [[pop/specs/application-frontend-system|the frontend spec]], the DOX tree and the audit's gap ledger with the converged single system.
- **Resultado observável:** `globals.css` below `/* generated-theme-tokens:end */` holds only tokens, `@theme inline`, base element rules and the documented exceptions; `src/app-shell/app-shell.css` is the one remaining route-neutral BEM file, declared as such in its own DOX; no contract still describes a class that no longer exists; the closed and still-open audit gaps exist as one readable list for 14.7.2's report.

## Estratégia

Retirement is by consumer, never by prefix. A rule leaves only after a grep in `src/**` proves zero referrers (tests included); a rule whose only referrer is a dead export goes with that export; a rule that survives does so for a written reason, not by omission.

Two reasons are accepted for surviving. First, `scripts/check-design-tokens.mjs` (inside `pnpm lint`) rejects any raw `px|rem|em|ch|#hex` in `src/app/**`, `src/app-shell/**`, `src/components/ui/**`, and it **sanctions by name** only two literals, both inside `globals.css`: `(min-width: 900px)` and `(min-width: 64rem)`. `64rem` is Tailwind's own `lg:`, so the settings two-column layout migrates freely; `900px` has no variant and cannot be written as `min-[900px]:` without violating the gate, so the auth split-card breakpoint block stays CSS. Second, a migration that would need a component API change (a descendant override reaching into `BrandIdentity`'s internals) is out of scope and becomes a recorded gap, never a forced refactor. Neither front edits `check-design-tokens.mjs`; a needed entry returns to the agente principal.

14.6.2 F02 is executing in parallel and removes the public `storefront-*`/`receipt-rail*` blocks and the seven leftover `.checkout-*` rules. This task does not plan them. But `/design-system` still consumes `receipt-rail`, `receipt-rail__label` and `receipt-rail__facts`, so whichever way 14.6.2 resolves that grep, **each front re-greps at run time** and treats the tree it finds as truth, reporting any divergence from this inventory instead of assuming it.

Behaviour is frozen: no route, dictionary key, form body, authorization, redaction or money path changes. Class-for-utility swaps preserve rendered geometry; replacements use the projected vocabulary and `var(--space-*)`/`var(--layout-max)` style references, never a literal.

- **Risco:** apagar export/arquivo ainda importado por teste ou rota — mitigação: grep de importador em `src/**` e `tests/**` antes; positivo → manter e apenas migrar as classes.
- **Risco:** editar `/design-system` e as páginas de auth invalida evidência ligada por hash (`artifacts/design-system/current.json`) e as baselines de pixel de login/reset — mitigação: repassar a regeneração para 14.7.2 (C10) como fato, não como surpresa.
