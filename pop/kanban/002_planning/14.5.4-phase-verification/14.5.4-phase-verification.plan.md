# Plano — [[14.5.4-phase-verification]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** close Phase 14.5 by running the aggregate gate over the integrated `develop`, realigning every suite the three merchant tasks falsified, adding the regression their checklists owed, repairing what the suite catches inside the phase's reach, refreshing the design-system evidence that `globals.css` retirement invalidated, and consolidating the human checklist the epoch's final PR will carry.
- **Resultado observável:** `tsc`, the lint chain, `vitest` and `next build` exit 0 from the task worktree; the merchant suites assert the converged compositions instead of the retired ones; every repair is named with `file:line`; the design-system evidence run is regenerated and verified; the Docker-driven merchant evidence runs and the browser pass are handed to the human as one explicit checklist.

## Estratégia

Verification only. Application behaviour changes exclusively where the suite proves a defect **inside Phase 14.5's reach** — merchant dashboard/analytics, `/orders**`, `/links**`, `/catalog**`, `/settings` and its four surfaces, `/profile` and TOTP. A defect outside that reach is a reported follow-up, never a repair here; `prisma/**`, every `route.ts`, `src/components/ui/**`, `src/data-directory/**`, `src/media/**` and `src/integrations/**` stay read-only unless the repair is the bug itself and the DOX contract still holds.

Five decisions are pinned. **(1) Direct binaries, never `pnpm <script>`, never Docker.** The task runs in its own worktree where the workspace scripts resolve wrongly; the gate is `./node_modules/.bin/tsc --noEmit`, the expanded lint chain (`node scripts/generate-design-tokens.mjs --check && node scripts/generate-brand-assets.mjs --check && node scripts/check-font-provenance.mjs && node scripts/check-design-tokens.mjs && ./node_modules/.bin/eslint .`), `./node_modules/.bin/vitest run` and `./node_modules/.bin/next build` — the same four gates `check` aggregates. **(2) Realignment asserts the converged surface, it never lowers the bar.** No `.skip`/`.todo` is added, no case is deleted without being re-covered, and every falsified assertion is rewritten against the delivered composition read in the source, not around it. **(3) The falsified list is a floor, not a closed set.** 14.5.1's checklist and 14.5.2's `g04` name their suites; 14.5.3's slices carry no filled report, so its list is discovered from the integrated diff and the failing run — `settings-surface`, `storefront-settings-management`, `storefront-preview` (pinned to the retired `storefront-preview__card`), `nautt-credential-surface` (missing `locale` prop), plus the catalog and profile suites — and the discovery is reported, not assumed. **(4) Evidence splits by runner, not by area.** `run-admin-evidence.mjs` drives merchant-dashboard, orders, links, catalog, store-settings and profile through `docker compose` (`run-admin-evidence.mjs:75`), so those six runs are **user-exclusive** and are handed over stale with their commands; the design-system run is local (`next build` + Playwright) and binds `src/app/globals.css` (`artifacts/design-system/20260908212142/manifest.json:97`), which 14.5.3 edited — it is regenerated and re-verified here, and `verify-login-evidence.mjs` is re-run as a pure hash check. **(5) The baseline is a floor.** Before this phase the suite stood at 2185 passing / 28 skipped with lint at 0 errors; passing count only grows, skipped count does not.

## Áreas afetadas

- Non-test sources under the phase's reach — only where a repair is proved, each with `file:line`.
- `artifacts/design-system/**` — written exclusively by the evidence script, never by hand.

## Frentes de execução

### F01 — Phase 14.5 gate, realignment, regression, repairs and evidence

- **Entrega:** the whole verification pass — realignment, owed regression, in-reach repairs, the design-system evidence refresh, the aggregate gate result and the consolidated human checklist.
- **Contrato:** [[14.5.4-phase-verification.g01-phase-gate]] — *siga como fatia única desta frente* · **Papel:** `pop-phase-verifier` · **Depends on:** 14.5.1, 14.5.2 e 14.5.3 integradas · **Critérios:** C01–C10.

**Frente única, justificada:** the gate is one indivisible run over the integrated tree, repairs cross area boundaries (shared merchant primitives, dictionaries, `link-money`), and a split would produce overlapping write sets in the same test tree plus two conflicting suite states — parallelism here buys nothing and costs the single source of truth for the aggregated result.

## Ordem e paralelismo

1. Read the three checklists and the integrated diff; run `vitest run` once to turn the floor list into the real failing set.
2. Realign (C01), then add the owed regression (C02), then repair what remains red (C03) — in that order, so a repair is never a way to make a stale assertion pass.
3. Run the four gates to green (C04); regenerate and verify the design-system evidence after the last source-touching commit (C05).
4. Write the handover: stale Docker runs with commands (C06), consolidated checklist (C07), carried criteria closed (C08). **Integração:** o agente principal confere ownership, o resultado agregado e os critérios `agent`.

## Riscos e condições de aborto

- **Risco:** a realignment that only makes red green — mitigação: C01 forbids `.skip`/`.todo` and uncovered deletions; every rewritten assertion cites the delivered source.
- **Risco:** repair drift beyond the phase — mitigação: C03 caps the reach and C09 pins the non-test diff to the listed repairs; anything else is a follow-up in the report.
- **Risco:** the local evidence run fails for environment reasons (build, browser, port) — mitigação: at most 2 attempts, then record `ambiente`, reclassify that item to `verify: user` and continue; the gate result is not blocked by it.
- **Abortar se:** a caught defect can only be fixed by a schema, route or `src/components/ui/**` contract change — reportar `blocked: true` com arquivo, linha e o contrato que impede.
