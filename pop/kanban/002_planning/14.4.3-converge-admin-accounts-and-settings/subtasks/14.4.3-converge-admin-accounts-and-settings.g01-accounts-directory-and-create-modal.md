## Contrato de execução

- The create form moves into the owned `Modal` primitive, opened from a header action; the modal keeps the delivered POST (`action="/admin/users"`, `method="post"`) and the exact field names `username`, `email`, `password`, `role`. Password generator, strength meter and copy are client-side only over that same field.
- **No initial-status control:** `POST /admin/users` and `createUser` accept no status and always write `ACTIVE`. Rendering a status control that changes nothing is a defect; the gap is F04's spec entry, not a service change here.
- The create route changes only its redirect target, to `/admin/accounts?success=created` and `/admin/accounts?error=create-failed` — the closed pair `resolveAdminAccountsDirectoryQuery` already parses. Authorization, origin guard, request log, parsing and service call stay byte-identical.
- Page feedback follows the delivered bridge: `NoticeToast` for the resolved notice plus the same `Alert` inside `<noscript>` (pattern in `orders-notices.tsx`). The visible top `Alert` for those outcomes goes away.
- Relative last-activity ("today" / "N days ago") is derived from the row instant already in the DTO, localized in both dictionaries, rendered beside the absolute value. Do not add a row field: `AdminUserSummary` has no `storefrontSlug`, so the store column keeps its badge and the slug stays a recorded gap.
- `admin-controls.tsx` holds the admin-local `SegmentedControl` (`role="radiogroup"`, `aria-checked`, ≥44 px targets, token classes only). Never import the merchant `catalog-fields.tsx` control; never add a second button style.
- `DataDirectory`'s `emptyAction` takes an href, not a modal trigger, and the composition is off-limits: keep the header action as the single primary create entry and report the empty-state CTA as a gap in `Resultado`.
- Every new string lands in `src/i18n/dictionaries/admin-users-directory/{en,pt-BR}.ts` with both locales in the same commit; never write another domain.
- **Saber parar:** no máximo 2 tentativas quando a falha de um critério `agent` for de ambiente; na segunda registre `ambiente` e siga.
- Dependência ou entrada ausente/incompatível → responder `BLOCKED` ao agente principal com evidência; não implementar dependência nem alargar `Owns`.
