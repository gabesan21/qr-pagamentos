## O que decidir dentro da frente

- The commit builder is the single place that assembles a canonical query: it keeps `q`, the registered `filter.*` pairs and a non-default `pageSize`, and always drops `cursor`. Search debounces ~350ms; selects, date and text filters commit on `change`. Commits go through `useRouter().replace(url, { scroll: false })` inside `useTransition`, and `isPending` selects the existing loading render so geometry is preserved and the live region keeps announcing.
- The `<form method="get">` stays. Give it an id, keep every field name unchanged, keep `cursor` out of it, and move Apply/Reset inside `<noscript>`. The visible actions are the removable chips and one ghost "Clear filters" anchor to `resetUrl`, rendered only when at least one chip exists.
- Chips resolve their label from the registered definitions: enum values map through `filters[].options`, text and calendar filters show the submitted value, `q` shows the search term. Removal links keep the current non-default page size and drop `cursor`. Never print a raw enum id.
- Rows accept an optional server-evaluated `getRowHref`; `DataDirectory` resolves it alongside `rowKey`/`cells`/`actions` so no projection crosses the boundary. The click handler on the table row and on the narrow-width card navigates only when the event did not originate inside an interactive descendant (anchor, button, input, select, label, `[role]` control). The explicit action cell stays and remains the keyboard path; add hover/focus affordances through existing tokens.
- The pagination footer follows the template composition (rows-per-page on the left, prev/next on the right, one ruled band) using the owned `Pagination*` primitives. Keyset prev/next only — no total count, no page numbers. The page-size select keeps id `${idPrefix}-page-size` (a client preference observes it) and is associated to the form by `form=`.
- Add a documented opt-out prop that renders the composition without live navigation, and pass it from both specimens in the design-system gallery. Keep `invalid-query` as a declared component state; do not remove it from the gallery or from `coverage.ts`.
- `src/data-directory/server/notice.ts` exports only the reserved key/value pair and a helper that builds a reset location carrying it — no I/O, no dictionary, no React.
- `src/app/directory-support.tsx` holds the shared copy builder (taking the dictionary plus the per-directory empty title/description, like the catalog one already does) and the server component that mounts `NoticeToast` with the informational message plus a `<noscript>` alert. Delete the seven `directory-copy.ts` duplicates only after every consumer front can import the builder — leave the deletion to F02/F03 if it would break their files mid-wave; announce which choice you made.
- New dictionary keys land in both locales with identical key sets. The invalid-filters message must not reference any submitted value.
- Update the assertions in `src/data-directory/ui/data-directory.test.tsx` that this contract invalidates. **Do not run any test** — `14.3.3` runs the suite.
