# Plano — [[14.2.2-add-authenticated-theme-switcher]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** make the six `:root[data-theme=…]` blocks live for authenticated surfaces — the root layout stamps `data-theme` on `<html>` from a validated per-browser cookie, and the shell account menu offers an instant swatch picker that persists the choice, without touching tokens, storefront/checkout `data-theme-preview` or the administrator default-theme setting.
- **Resultado observável:** an administrator or merchant opens the account menu, picks one of the six themes, and the whole shell repaints immediately with no reload; the choice survives navigation and reload because the server renders the attribute on the first paint (no flash).

## Estratégia

**Persistence — client cookie, no route.** The value is a non-sensitive presentation preference with no authorization effect, so the picker writes `document.cookie` directly (`qr_theme=<id>; path=/; max-age=31536000; SameSite=Lax`, plus `Secure` when `location.protocol === "https:"`; never `HttpOnly`, which a client write cannot set) and mutates `document.documentElement.dataset.theme` in the same handler. A POST route was rejected: it would need the origin guard plus a redirect/refresh per click, contradicting the template's instant switch and the 2026-09-07 decision. The cookie is therefore attacker-writable, so the **server never trusts it**: `src/app/layout.tsx` stamps the attribute only when a principal resolved **and** the value is one of the six ids; anything else stamps nothing, so the existing `:root:not([data-theme])` `prefers-color-scheme` fallback (`globals.css:209`) keeps working and public surfaces stay on `data-theme-preview`. The client never computes the `<html>` attribute during render — it mutates the DOM only inside the click handler, after hydration — so markup agrees and `suppressHydrationWarning` must **not** be added; the template's `localStorage`-during-render pattern is deliberately not transplanted. `src/design-system/theme-preference.ts` owns the cookie name, the read-side guard and the cookie-string builder, re-exporting the registry already derived from `resolver.json` in `src/design-system/themes.ts`, so no new literal list of theme ids enters the diff (the `STOREFRONT_*` naming is now a misnomer for a shared registry — recorded as debt, not renamed here, because its call sites are outside this write set).

**UI — one instance, inside the existing panel.** Anti-drift inventory: the account panel, `Button`, `Monogram` and the swatch assets `public/application-assets/theme-swatch-<id>.svg` already exist; the only genuinely new piece is the shell picker, justified because the admin `appearance-section.tsx` grid is a form POST bound to the admin dictionary and lives outside this write set (its duplication is tracked debt, not fixed here). Semantics inside `role="menu"` are `role="group"` + six `role="menuitemradio"` buttons with `aria-checked`, each a real `<button>` reachable by Tab with a visible focus ring, a check icon as the non-color active marker, a visible localized name and `alt=""` on the decorative swatch. Labels reuse the existing flattened `storefrontTheme*` keys (no duplicated strings); only the group label is new in the `app-shell` dictionaries. The panel stays open after a pick. Exactly one picker exists in the accessibility tree: the account trigger is the one control visible at every width (`app-shell.css:433-479` hides the rail and the language form, never the account menu), so the mobile drawer gets no second copy. CSS goes in `app-shell.css` with existing tokens only: swatch controls ≥44×44px and a panel that fits 320px without horizontal overflow.

## Riscos e condições de aborto

- **Risco:** the picker seems to need a new `globals.css` rule — mitigação: it must not; all styling lands in `app-shell.css` with existing tokens. If a token is genuinely missing, stop and report instead of editing 14.2.1's files. `14.2.3` also owns `src/app/layout.tsx` (toast viewport): the two tasks must not run in parallel — integrate this one first or rebase on it.
- **Risco:** required new shell props break `app-shell.test.tsx` typecheck — mitigação: update that file's props only, never its assertions; behavioural coverage belongs to 14.2.5. A crafted `qr_theme` on a public page is neutralized by the same gate: principal + closed id set.
- **Abortar se:** the delivery would require a schema column, a server route or a change to the administrator default theme — sinalizar `blocked: true` citing the 2026-09-07 decision.

## Topologia de execução

- **Forma/justificativa:** executor único (`pop-executor`) — one cohesive front sharing a single cookie contract across module, layout and component; splitting server stamping from the picker would force a contract handoff for ~10 lines and buy no parallelism.
- **Perfis:** fixos por papel nativo; `size: M` mantém orçamento sem recon.
