## Contrato de execução

- **Preserve what 14.3.2 delivered:** create keeps landing on the created link's detail and a create failure returns to `/links/new`; edit failures return to the edit form; the dirty-only field naming (absent = unchanged, so an untouched composition never trips the attempt gate) and the session-draft restore under the failure notice stay exactly as they are. Every control must still submit without JavaScript: radio cards are real `input type=radio` styled as cards, never buttons.
- **Composition and type** are radio cards with a caption each; on the edit page the immutable members (composition kind, type, currency pair) render as read-only facts with a lock note instead of disappearing.
- **Product lines:** a searchable picker over the server-rendered active products (client-side filtering of an already-loaded list, never a new read), each result showing its price; selecting an already-added product raises the "already added" toast through the delivered toast primitive. Each selected line shows title, −/+ steppers bound to the 1–9,999 range, unit price, line total, and a remove control; the running total uses `link-money.ts`. Keep the hidden serialized `lines` field the route parses, and keep the 1–20 line bound and the per-link product uniqueness hint.
- **Edit locks:** read the checkout-attempt existence through an additive member on the owner prefill service (the seam already exists inside the V2 service store) and render the financial lock note and the new-version banner **only** when it is true. Keep the `?from=<id>` supersede path unchanged. A line whose product is no longer among the active products renders locked with the unavailable caption instead of an empty select.
- **Descriptions:** render the localized description pair for every composition. For `PRODUCT_LINES` it is read-only with a caption naming the delivered contract — never post a description on a product-lines mutation and never invent a service field. Record the divergence in your report for F04.
- **Expiration** gains a clear control that empties the field and marks it dirty (explicit blank clears the stored value). **Preview** is a sticky 8+4 side column summarizing type, composition, currency pair, expiry, line count and the exact total, with an explicit empty state. **Validation** is inline: `aria-invalid` plus `data-invalid` on the field and one error banner, with the server remaining the enforcer; a failure banner offers reload/retry without introducing a new notice value.
- Every new or changed user-facing string lives in the new `payment-links-form` domain in both locales, registered once in the aggregator.
