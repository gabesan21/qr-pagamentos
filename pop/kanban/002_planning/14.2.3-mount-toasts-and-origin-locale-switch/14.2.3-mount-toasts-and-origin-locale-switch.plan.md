# Plan — [[14.2.3-mount-toasts-and-origin-locale-switch]]

- **Stage:** 002_planning · **Role:** `pop-planner` (separate from execution)

## Objective and expected result

- **Objective:** mount the toast owner application-wide, turn the mechanical query-string outcome notices into toasts with a no-JS fallback, and make `/language-preference` return to its origin page and serve anonymous callers, with a compact language control on login and reset.
- **Observable result:** every route can raise a toast; a mutation on catalog/categories/links/orders/admin shows a top-right toast whose param disappears from the URL (a refresh does not re-toast); switching language on any page stays on that page with its query intact; login, reset and the public surfaces honour an anonymous language choice.

## Strategy

Two independent repairs. **Feedback:** `ToastViewport` is mounted once in the root layout (it already resolves the locale, so it also supplies the localized region label) and covers authenticated, auth and public routes. One shared client bridge receives from the server a **closed registry of already-localized notices** (`param`, `value`, kind, message) plus the params to strip; it raises exactly one toast per navigation and then removes those params with `history.replaceState`. The registry form serves both mounts: pages pass the notice they already resolve, and the root layout passes the two global `language` entries (`languageSaved`/`languageError` already exist in the shared dictionary) — which is what makes the widened locale return safe on pages that render no language banner. **No-JS fallback is `<noscript>` wrapping the existing `Alert`**: it is the shipped, theme-correct composition with the right `role`, gives exact parity without JS, and adds no second live region — sonner already owns the polite/assertive region required by the frontend spec, and a visually-hidden duplicate would double-announce.

**Locale:** `resolveSettingsReturnTarget` stops being a closed `{ /settings, / }` allowlist and becomes an origin-path resolver: same host validation as today, then the Referer's **path + query** preserved, fragment dropped, accepted only when it starts with a single `/`; anything else falls back to `/`. The `#settings-language` anchor for `/settings` is preserved. **Anonymous mechanism: the existing `qr_locale` cookie** — it is already the anonymous resolution source in the root layout, login, reset and `/design-system`, and `profile/password/route.ts` is the precedent for setting it. So the route drops the blanket `401`: an authenticated caller keeps the persisted preference, an anonymous caller gets `qr_locale` set with the same attributes; no authentication logic changes. The three public pages that hardcode `defaultLocale` for anonymous visitors resolve the cookie instead, which makes the choice real before 14.6.1 adds the public footer control.

**Visual decisions, dictated here and transcribed into `DESIGN.md` by F01:** toasts stack top-right, success auto-dismisses at 5s, error and warning are sticky with an optional retry action, and motion stays inside the existing global reduced-motion collapse — no new motion CSS; the compact language control is a globe + `PT`/`EN` select variant for non-shell surfaces, ≥44px target, labelled from `languageLabel`. Boundaries: `src/app/globals.css` belongs to 14.2.1, so the auth switcher is styled with Tailwind utilities only; `src/components/ui/**` stays untouched (the bridge is route plumbing, not an inventory primitive, so no `inventory.json` churn); only the mechanical notice sites migrate — per-section settings/profile banners and the auth form errors stay Alerts and belong to 14.4.1/14.4.3/14.5.x.

## Risks and abort conditions

- **Risk:** the widened return lands a `language` notice on a page with no banner — mitigation: the global registry mount in the root layout is part of C2 and covers every route.
- **Risk:** relaxing the return target reopens an open redirect, or a hidden server live region double-announces alongside sonner — mitigation: C4 keeps host validation and rejects scheme/host/`//` forms; C3 keeps the fallback `<noscript>`-only.
- **Abort if:** 14.2.2 is not closed (no ledger in `pop/memory/`) when 004 starts — flag `blocked: true` citing the missing ledger.
