# Plan — M-4.1-repair-test-baseline-determinism

## Objective

Make `pnpm test` deterministic and green on the main checkout (with task worktrees present) by repairing three pre-existing baseline failures and the worktree leakage — without touching any production behavior. All four defects are on the test/fixture/config side; evidence below.

## Root causes (verified by scoped reproduction: `pnpm vitest run --dir src` → 2 failed/114 files; `--dir scripts` → green)

1. **`server-only` resolution — `src/auth/sign-in.test.ts`.** `src/observability/server-request-log.ts:1` does `import "server-only"`; the `server-only` package is not a dependency (absent from `package.json`/lockfile), so the unmocked transitive import via `src/app/login/submit/route.ts:7` fails suite collection. Project idiom for this is already established: `vi.mock("server-only", () => ({}));` at the top of the test file (used in `src/storefront/public-storefront.test.ts`, `src/i18n/locale-preference.test.ts`, `src/i18n/dictionaries.test.ts`, `src/data-directory/server/directory-page.test.ts`). **Correction side: the test** — add the same one-line mock. No dependency added, no config alias.
2. **Storefront locale expectation — `src/app/store/[slug]/page.test.tsx:59`.** The third test runs sessionless, and the page correctly falls back to the `pt-BR` default — proven by the file's own first test, which passes asserting `read` was called with `"pt-BR"`. The unavailable-state render therefore contains `"Esta vitrine está indisponível"`, while the third test wrongly expects the English `"This storefront is unavailable"`. **Correction side: the test expectation** — assert the pt-BR string (production page is consistent with its own locale contract).
3. **Product-price SQL fixture — `pop/scripts/db-test.mjs:504`.** The `INSERT` names **7 target columns** (`internal_name, title_pt_br, title_en, description_pt_br, description_en, price, owner_id`) but the `VALUES` list has only **6 expressions** — it lacks the trailing `'${otherUserId}'` that every sibling product INSERT (lines 487–494) carries. PostgreSQL reports "INSERT has more target columns than expressions" as SQLSTATE **42601**, masking the expected `23514` (`product_price_canonical`) for every invalid price. The production constraint is healthy: the valid-price inserts at line 499 (7 columns, 7 params) succeed and round-trip exactly. **Correction side: the fixture** — append `, '${otherUserId}'` to the `VALUES` list. Not a production defect; scope stays test-only.
4. **Worktree leakage — `vitest.config.ts:12`.** `exclude: ["tests/**", "node_modules/**"]` *replaces* vitest's default excludes, so `**/node_modules/**` is lost and `pop/worktrees/6.3.3-*/**` test copies (1602 files / 92 failures observed) enter the main-checkout run. No legitimate test lives under `pop/worktrees/**` (transient task checkouts) or nested `node_modules`; the only `pop/` test outside worktrees is `pop/scripts/db-runtime.test.ts`, which stays included. **Correction side: config** — `exclude: [...configDefaults.exclude, "tests/**", "pop/worktrees/**"]` (`configDefaults` from `vitest/config`), restoring `**/node_modules/**` and excluding worktrees explicitly.

## Strategy — one cohesive front (size S)

1. Add `vi.mock("server-only", () => ({}));` to `src/auth/sign-in.test.ts` (line ~6, matching sibling idiom).
2. In `src/app/store/[slug]/page.test.tsx` third test, expect `"Esta vitrine está indisponível"` (and keep the no-`/pay/` assertion); optionally assert `read` called with `"pt-BR"` for symmetry with test one.
3. In `pop/scripts/db-test.mjs:504`, append the missing `'${otherUserId}'` value to the invalid-price INSERT.
4. Rewrite `vitest.config.ts` excludes via `configDefaults.exclude` + `tests/**` + `pop/worktrees/**`.
5. Closeout: check root `AGENTS.md` — the Application contract does not describe the vitest exclude list; update only if the executor judges a contract line is needed. No spec changes expected (test-only repairs); confirm per `sync-specs`.
