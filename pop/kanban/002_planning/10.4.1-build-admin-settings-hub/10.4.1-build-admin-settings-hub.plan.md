# Plan — [[10.4.1-build-admin-settings-hub]]

- **Stage:** 002_planning · **Responsible:** planner agent · **Round 2** (round 1 returned by the 003 critic: theme-persistence deferral was a non-agent-decidable scope cut; restored here per option (a))

## Objective and expected result

- **Objective:** rebuild the existing `/admin/settings` page into the dedicated bilingual administrator settings hub that organizes, in anchored sections, the closed exchange-currency registry (via the 7.1.1 pointer service), Nautt catalog currency pairs, catalog payment methods, the legacy global payment settings, the **persisted, administrator-editable default theme assigned to new users**, and the administrator's own language preference — with safe dependency behavior communicated per section and mutation redirects landing back on the hub.
- **Observable result:** an active `ADMIN` manages every administrator-only configuration from `/admin/settings`, including saving the default theme new merchant users are created with (persisted across restarts, validated against the closed six-theme id set); each POST redirects to `/admin/settings?…` with a closed bilingual notice; wrong-role/unauthenticated outcomes stay exactly the documented redirects/empty `401`/`403`.

## Strategy

Composition over delivered mutations, plus one new persisted setting with its single mutation route. Eight pinned decisions the executor must not revisit:

1. **Existing configuration is composed, not reimplemented.** The hub posts to the delivered `POST /admin/exchange-currencies`, `/admin/catalog/currency-pairs[/id]`, `/admin/catalog/payment-methods[/id]`, `/admin/payment-settings`, and `/language-preference`. Only their redirect targets move, from `/admin?…` to `/admin/settings?…` (catalog task precedent); route logic, guard order, and service calls stay byte-identical otherwise. `src/security/public-rate-limit.ts` stays untouched (no public surface).
2. **One additive admin read.** The registry service gains an admin-only `listMappings(actor)` returning active pointer rows redacted to `{ code, label }` ordered by code; pair UUIDs stay in the catalog section. No owner-read, gating-primitive, or mutation semantics change.
3. **The default theme persists in a new `system_settings` singleton table** (fixed `id` SmallInt 1, nullable `default_theme_id VarChar(24)` with a closed-set check mirroring the six design-system theme ids, `updated_at`), delivered as one additive canonical `migration.safe.json` migration (`node pop/scripts/migration-policy.mjs generate`): create-table + typed constraint + closed runtime grants (SELECT/INSERT/UPDATE, never DELETE) only — no DML, no seed row, no backfill. **No migration file is written before execution:** the directory is generated and timestamped against `develop` at 004 time so it sorts after whatever 10.3.1 lands; their files are never edited. `prisma/bootstrap.sql` is edited only if its ordinary-table grant pattern provably requires a guarded entry (executor verifies; `container:contract-check` if touched).
4. **Creation-time stamping semantics (exact).** A new `src/auth/system-settings.ts` service resolves the effective default (persisted value ?? `DEFAULT_STOREFRONT_THEME_ID`) and saves it admin-only with `isStorefrontThemeId` validation. `src/auth/administration.ts` `createUser` stamps the effective default into the new row's `storefront_theme_id` **only for role `USER`** (ADMIN rows keep NULL). Nothing happens to existing users: no backfill, no rewrite, no read-time change — legacy NULL rows keep resolving to the code constant exactly as today, later setting changes affect only users created afterward, and merchants keep changing their own theme through existing store settings. Storefront/theme read resolution is untouched.
5. **Exactly one new mutation route.** `POST /admin/settings/default-theme` (`src/app/admin/settings/default-theme/route.ts`): request-log wrapper with one new literal `serverRequestRoutes` entry, origin-guard first, `requireAdminFromCookie`, form `themeId` → service, then opaque `/admin/settings?success=theme-default` / `?error=theme-default-failed` redirects; `protectedMutationResponse` yields the documented empty `401`/`403`. The `src/observability/server-request-log.ts` edit is one additive literal appended **after 9.2.1 merges** (flagged collision; never a rewrite of their entries).
6. **Language stays the administrator's own preference.** The roadmap row pins persistence only for "the default theme for new users plus the closed currency/payment configuration" (`pop/roadmap/10-administrative-operations.md`, Phase 10.4); it does not pin a persisted default language, so the existing `/language-preference` control is composed unchanged and no locale storage is added.
7. **Safe dependency behavior is communication plus preservation.** Section copy states delivered semantics: registry deactivation removes only the pointer row and stored product/link currency codes survive; replacement re-points atomically; duplicate pair/code yields the typed conflict mapped to the one opaque failure notice; inactive catalog records cannot be selected for new links but never break existing ones; the theme default never rewrites existing users. No behavior is altered to achieve this.
8. **Single page, anchored sections.** Order: Exchange currencies → Currency pairs → Payment methods → Global payment settings → Appearance (default theme form) → Language, in-page anchor navigation (6 items), one primary submit per section, five-entry admin shell route map unchanged. The legacy BRL/PIX `GlobalPaymentSettings` allowlists stay composed as-is; nothing is retired.

## Risks and abort conditions

- **Risk:** prisma-lane timing — 10.3.1's migration is not yet merged when 004 is reached — mitigation: the temporal gate is explicit; the migration is generated against post-merge `develop`, never by editing their directory.
- **Risk:** request-log inventory collision with 9.2.1 — mitigation: one additive literal appended after their merge; any semantic conflict (route template grammar) surfaces at integration, not mid-execution.
- **Risk:** stamping semantics drift (fallback vs assignment confusion) — mitigation: decision 4 pins creation-time, USER-only, no-backfill behavior with service and disposable-DB tests.
- **Risk:** `admin:source-check` failures from new layout classes/raw controls — mitigation: owned primitives only; register genuinely new classes in the allowlist and `DESIGN.md` in F02.
- **Abort if:** the closed `migration.safe.json` language cannot express the singleton table + closed-set check + grants without raw SQL or DML — signal `blocked: true` with the manifest gap (that would contradict `prisma/AGENTS.md`; human re-scoping required).
- **Abort if:** 10.3.1 lands its own system-settings/default-theme storage — signal `blocked: true`; reuse their surface instead of a parallel table.
