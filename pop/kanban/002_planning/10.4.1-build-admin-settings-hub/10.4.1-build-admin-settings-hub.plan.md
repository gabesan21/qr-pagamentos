# Plan — [[10.4.1-build-admin-settings-hub]]

- **Stage:** 002_planning · **Responsible:** planner agent

## Objective and expected result

- **Objective:** rebuild the existing `/admin/settings` page into the dedicated bilingual administrator settings hub that organizes, in anchored sections, the closed exchange-currency registry (BRL/ARS/BOB/COP-capable `[A-Z]{3}` codes via the 7.1.1 pointer service), Nautt catalog currency pairs, catalog payment methods, the legacy global payment settings, the six-theme appearance catalog with the current default new users inherit, and the administrator's own language preference — with safe dependency behavior communicated per section and mutation redirects landing back on the hub.
- **Observable result:** an active `ADMIN` manages every existing administrator-only configuration from `/admin/settings` (no new routes, no schema change, no service-mutation behavior change), each POST redirects to `/admin/settings?…` with a closed bilingual notice, and the registry gains its Epoch 10 management UI (the root contract's "no administrator management UI before Epoch 10" clause is satisfied by this task). Wrong-role/unauthenticated outcomes stay exactly the documented redirects/empty `401`/`403`.

## Strategy

Composition and navigation task over delivered mutations; the only new server capability is one read. Seven pinned decisions the executor must not revisit:

1. **No new routes, no migration, no request-log/rate-limit change.** The hub posts to the existing `POST /admin/exchange-currencies`, `/admin/catalog/currency-pairs[/id]`, `/admin/catalog/payment-methods[/id]`, `/admin/payment-settings`, and `/language-preference`. `src/observability/server-request-log.ts` and `src/security/public-rate-limit.ts` stay byte-untouched; `prisma/` is not opened (see Risk R1).
2. **Only redirect targets move.** Each composed admin POST repoints its success/failure relative redirects from `/admin?…` to `/admin/settings?…` (catalog task precedent: "only their redirect targets repoint"). Notice query keys join the page's closed mapping; unknown keys keep the generic fallback. Route logic, guards, origin-check order, and service calls stay byte-identical otherwise.
3. **One additive admin read.** The registry service gains an admin-only `listMappings(actor)` returning the active pointer rows redacted to `{ code, label }` (ordered by code). Pair UUIDs are not repeated in the registry section — the catalog currency-pairs section already lists them to administrators. No owner-read, gating-primitive, or mutation semantics change.
4. **Theme section is read-only.** It presents the six-theme catalog from `src/design-system/themes.ts`, marks `DEFAULT_STOREFRONT_THEME_ID` as the default new users inherit, and hosts no form. Copy must not promise editability — see Risk R1 (abort-level finding).
5. **Language means the administrator's own preference.** The existing `/language-preference` control is composed unchanged. A default-locale-for-new-users is not in the card wording and hits the same persistence finding as R1 — out of scope.
6. **Safe dependency behavior is communication plus preservation.** Section copy states the delivered semantics: registry deactivation removes only the pointer row and stored product/link currency codes survive; replacing re-points atomically; duplicate pair/code yields the typed conflict mapped to the one opaque failure notice; inactive catalog records cannot be selected for new links but never break existing ones. No behavior is altered to achieve this.
7. **Single page, anchored sections.** Order: Exchange currencies → Currency pairs → Payment methods → Global payment settings → Appearance → Language, with an in-page anchor navigation (6 items, within Miller bounds), one primary submit per section, and the five-entry admin shell route map unchanged. The legacy BRL/PIX `GlobalPaymentSettings` allowlists stay composed as-is; nothing is retired in this task.

## Risks and abort conditions

- **R1 (abort-level finding):** an admin-editable *persisted* default theme for new users has no storage — `GlobalPaymentSettings` holds only the legacy allowlists and no system-settings table exists; persistence requires an additive migration, which this task's lane forbids and which collides with the serialized prisma lane (10.3.1 pending). The plan therefore pins the read-only theme section (decision 4) and recommends recording a follow-up task for the persisted default. **Abort if** the 003 gate rejects this deferral — signal `blocked: true`; re-scoping with a migration is a human decision, not an executor workaround.
- **Risk:** dictionary/visual-lane merge friction with 9.1.2 — mitigation: module-scoped dictionary keys, append-only `DESIGN.md` edit.
- **Risk:** `admin:source-check` failures from new layout classes or raw controls — mitigation: compose only owned primitives; register any genuinely new class in the allowlist and `DESIGN.md` in F02.
- **Risk:** repointed redirects break dashboard notice handling that still references catalog keys — mitigation: dashboard keeps its mapping; F01 tests pin both pages' notice behavior.
- **Abort if:** composing existing routes proves impossible without a new POST route or a request-log inventory entry — signal `blocked: true` with the concrete gap (the wave constraint reserves that file).
