# Plano — [[14.1.2-return-settings-saves-to-settings]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** every settings mutation returns the merchant to the settings section it was submitted from, and `/settings` finally renders the two-column sticky section nav the markup already assumes, with one heading per section and its own page description.
- **Resultado observável:** saving storefront settings, checkout policy, the staged logo or the language lands back on `/settings` at the matching anchor with the outcome notice visible inside that section; from `1024px` up the page shows a sticky 192px section nav beside the sections, each section shows its title and description exactly once, and the page subtitle is settings copy instead of the admin language sentence.

## Estratégia

Server-first stays untouched: native `POST`, `rejectCrossOrigin`, owner re-authorization, storefront/policy/locale validation, the opaque `changed|failed|conflict|staged|saved|error` notice codes and the media boundary are all byte-identical. **Only the redirect target changes.** `/storefront`, `/checkout-policy` and `/storefront/logo` are reachable from `/settings` alone, so their targets are server-side literals — no client ever names a path. `/language-preference` is also posted by the shell switcher (which this task may not edit), so it derives its return from the `Referer` header: same host by the `rejectCrossOrigin` rule, then the pathname matched against a **closed allowlist**, anything else falling back to `/`. Query and fragment from the referer are discarded and the emitted value is always one of the allowlist literals, so no open redirect exists. The allowlist is deliberately `{ /settings, / }` — the only two pages that render the `language` notice; widening it would return the merchant to a page where the outcome is invisible.

Because a browser scrolls the anchor to the top, a page-level banner would land off-screen: outcome notices move **into their section** (the template's per-section banner), keeping the current copy keys; the Nautt banner stays where it is, since its duplication is a separate audit item. The `settings-surface__*` classes get real CSS in `globals.css` rather than a Tailwind rewrite: the same page already styles `storefront-workspace*`, `storefront-logo-*` and `storefront-preview*` there, and every other merchant page layout follows the same BEM-in-globals convention, so one idiom survives on the page. Composition follows the template (`lg:grid-cols-[200px_1fr]`, sticky nav, scroll-spy) with the project's numeric laws winning where they conflict: nav targets at `--control-min-height`, sticky offset and `scroll-margin-block-start` at `calc(var(--top-bar-height) + var(--space-6))`, `--space-6` between sections, active state carried by background + start border + weight, never color alone. Duplication is removed by keeping the section `<h2>`/`<p>` — they own the ids `aria-labelledby` already points at — and dropping the repeated `CardHeader` from the inner card.

## Áreas afetadas

- `src/app/{storefront,storefront/logo,checkout-policy,language-preference}/route.ts` — redirect target only, plus one new return-path module.
- `src/app/(merchant)/settings/{page.tsx,settings-surface.tsx}`, `src/app/{storefront-settings-management,checkout-policy-management}.tsx` — nav/scroll-spy, per-section notices, single heading.
- `src/app/globals.css` — the missing `settings-surface__*` rules; `src/i18n/dictionaries/settings/{en,pt-BR}.ts` — page description key.

**Anchor and notice contract (both fronts read it, neither may change it):** `/storefront` → `#settings-identity`; `/checkout-policy` → `#settings-policy`; `/storefront/logo` → `#settings-store`; `/language-preference` → `#settings-language` when returning to `/settings`, no fragment otherwise. Section ids and query codes stay exactly as they are today.

## Riscos e condições de aborto

- **Risco:** an open redirect born from the `Referer` derivation — mitigação: the host is checked exactly as `origin-guard` does, the pathname is matched against the closed allowlist, the emitted value is always a literal from this plan, and the referer's query/fragment are discarded.
- **Risco:** `Referrer-Policy: strict-origin-when-cross-origin` (next.config) keeps the path only for same-origin requests, and an anchor can hide its section under the fixed top bar — mitigação: an absent or unknown referer falls back to `/` (today's behavior), and every section gets `scroll-margin-block-start` equal to the sticky offset.
- **Abortar se:** the delivery needs an edit in `src/app-shell/**`, `src/app/admin/**`, `src/app/(merchant)/catalog/**` or `src/components/ui/**` — report to the main agent with `blocked: true` and the exact missing contract, without editing.
