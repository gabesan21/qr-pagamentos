# Plano — [[15.2.4-phase-verification]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** run the accumulated Phase 15.2 checklist on the integrated tree, write the assertions 15.2.1–15.2.3 delegated here, and repair only defects the Phase 15.2 diff caused.
- **Resultado observável:** `pnpm check` green, each checklist item green with a named command, and every failure outside the phase recorded with evidence as a follow-up proposal instead of fixed.

## Estratégia

Diagnosis first, repair second. The phase closes on a tree where `pnpm check` and the admin checks were already red at the end of Phase 15.3, attributed there to Phase 15.2 and 15.1.4. The verifier therefore starts by reproducing those runs and classifying every failure as (a) caused by the 15.2.1→15.2.3 diff — repaired here — or (b) pre-existing/outside the phase — recorded with `file:line` evidence and a follow-up proposal, never fixed. Registered hypotheses to confirm by reading before touching anything: stale assertions in the four test files 15.2.3 named; the deferred F03 (browser parsers/types still accept `pixQrCodeUrl`, a human scope reduction, not a defect); F2 (parity checker deriving from the gitignored generated client); F4 (dead dictionary keys, owned by 15.4.2). A hypothesis is only acted on after the verifier confirms it in the code.

Repair reach is the phase: assertions, fakes, fixtures and inventories the 15.2 change falsified. A wrong durable contract, or a structural request an earlier task did not meet, becomes a modification/task proposal in the memory — the verification task never rewrites a contract. No test run on containers: everything runs through direct pnpm, and the webhook is exercised in production only (decision 2026-09-22), which is out of reach here, not a gap.

Environment policy: at most two attempts per criterion when the failure is environmental; on the second, record `ambiente` in the telemetry, reclassify the criterion as `verify: user` with a Log line and move on. Setup does not consume an attempt — `pnpm precheck` (Prisma client generation), and `SHARP_IGNORE_GLOBAL_LIBVIPS=1 pnpm install --frozen-lockfile` in a fresh worktree. If the local Node differs from the pin and `pnpm` aborts, run the same command through `./node_modules/.bin/<vitest|tsc|eslint|next>`; the fallback is a transport change, not an attempt.

## Riscos e condições de aborto

- **Risco:** repairing an assertion that is reporting a real product defect — mitigação: C1 requires the classification, with evidence, before any edit.
- **Risco:** repair drifting into Phase 15.3/15.1 territory (parity routes, admin inventory, dictionary keys) — mitigação: `must_not_edit` plus C13.
- **Abortar se:** the checklist can only be met by changing a durable contract or a file outside `owns` — sinalizar `blocked: true` with the criterion and the `file:line` evidence.
