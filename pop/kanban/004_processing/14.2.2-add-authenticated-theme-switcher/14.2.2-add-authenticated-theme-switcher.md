# 14.2.2-add-authenticated-theme-switcher — Add authenticated theme switcher


- **Origem:** [[pop/roadmap/14-template-fidelity-convergence|Phase 14.2]]
- **Plano:** [[14.2.2-add-authenticated-theme-switcher.plan]] · **Aprovação:** [[14.2.2-add-authenticated-theme-switcher.approval]] · **Verificação:** [[14.2.2-add-authenticated-theme-switcher.verify]]

## O quê

Authenticated surfaces honour a per-user theme: the root layout stamps `data-theme=<id>` on `<html>` from a validated cookie (six ids, `pix-paper`/`midnight-clearing` fallbacks per the frontend spec), and the shell account menu offers an instant client-side theme picker with swatches that persists the choice; storefront/checkout `data-theme-preview` behaviour is untouched.

## Por quê

Nothing sets `data-theme` for the app today, so the six themes are dead CSS for merchants and administrators, contradicting the template and info.md ('selectable theme contexts shared by authenticated surfaces').
