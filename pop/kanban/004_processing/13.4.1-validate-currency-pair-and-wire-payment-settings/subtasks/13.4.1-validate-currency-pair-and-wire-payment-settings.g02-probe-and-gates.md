## Contrato de execução

- **The probe is merchant-only and self-keyed.** It requires a `USER` principal and runs with that principal's own credential through the existing owner quote path (`src/integrations/nautt/owner-pricing-orders.ts`) — one key-handling path, one ownership fence. An `ADMIN` never triggers a provider call here and no code reads another user's credential: roles are disjoint (`src/auth/authorization.ts:16-20`) and the credential is self-owned (`src/auth/nautt-credential.ts:63-68`).
- **Request shape:** the registered pair of an active supported code, resolved through `requireActivePair`, plus a fixed minimal fiat amount declared as one named constant (no documented minimum exists; the documentation's example uses `500.00`, so pick a small exact decimal and say why in a comment). Never an order, never `deposit_fields`, never any other endpoint.
- **Outcome recording:** `ok` on `200`; otherwise exactly one of the four documented pricing codes raised by F01's typed refusal; everything else is the opaque unavailable outcome and records no code. Store the code and the timestamp; never store or display the provider message, the key or the amount.
- **Throttle:** a second probe for the same (owner, pair) within 60s is refused from the stored `quote_checked_at` with its own typed outcome — no in-memory limiter, no new infrastructure.
- **Selection gate (`requireSelectable(ownerId, pairId)`):** allowed only when that owner's row has `quote_outcome = ok` **and** no disproving observation — an `observed_*` pair present but not enabled by `GlobalPaymentSettings` blocks selection through F01's shared predicate. Wire it into payment-link creation **and** edit next to the existing `pairActive` serialization (`src/auth/payment-link-v2.ts:323-328`), and into default-currency resolution on **both** paths (`src/auth/storefront-settings.ts:270` owner, `src/auth/admin-user-profile.ts:292` admin acting on a target owner — the gate always reads the *target* owner's evidence). Existing links, orders and stored defaults are never rewritten, revoked or re-validated.
- **Surfaces:** the merchant currency section gains one probe control per active code plus a status line (last check, outcome, observed method and currency when present, all dictionary-backed in `pt-BR` and `en`); the admin exchange-currencies section gains a **read-only** evidence column and no action. Both reuse owned primitives, the declared design tokens and the required states (idle, loading, success, refusal, empty, throttled). The probe route follows the `/storefront` convention: cross-origin guard, cookie principal, form POST, relative redirect with a redacted notice parameter; it returns no provider text and no UUID the caller could not already see.
- New dictionary keys only, in both locales, in the settings dictionaries. If a needed key has no home outside a file owned by another in-flight card, stop and report instead of editing it.
- Tests belong to this front (probe outcomes including throttle and missing credential, both gates, admin read-only). **Do not run any test suite** — task 13.4.2 runs the battery.
- **Saber parar:** no máximo 2 tentativas quando a falha for de ambiente; na segunda, registre `ambiente`, reporte a reclassificação para `verify: user` e siga.
- Dependência ou entrada ausente/incompatível → responder `BLOCKED` ao agente principal com evidência. Não implementar, simular ou corrigir dependências.
