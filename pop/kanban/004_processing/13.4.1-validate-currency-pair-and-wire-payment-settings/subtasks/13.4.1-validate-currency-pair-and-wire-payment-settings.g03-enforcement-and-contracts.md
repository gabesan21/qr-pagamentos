## Contrato de execução

- **Where the refusal happens:** after a `created` reservation and **before** `markCreating`/`quote` in both services (`src/checkout/public-checkout-v2.ts:137-140`; `src/checkout/standalone-checkout.ts:132-135`), so no quote is spent and no provider call is made. Refuse by reusing the delivered refusal shape byte for byte — `markFailed` plus the redacted `provider-unavailable` — never a new result kind, state, status code, route or DTO. Replay of a failed attempt keeps answering the same opaque outcome through the existing `FAILED` branch.
- **The rule:** refuse when the reservation's pair has an `observed_payment_method`/`observed_currency_symbol` **not** enabled by `GlobalPaymentSettings`, and refuse when either enabled set is empty (fail closed — an administrator who disables everything stops checkout). A pair with no observation yet **dispatches**: the probe already gated its selection, and the documentation cannot prove PIX/BRL before an order exists.
- **The policy module** reads the settings row and the verification row through Prisma, injected into both services as one dependency port, and uses the shared predicate from `src/auth/payment-settings.ts`; it must **not** import F02's verification service, which answers a different question (selection eligibility). No caching, no background refresh.
- **Logging:** one redacted line per refusal with the pair identity, the observed method/currency and the reason; never customer data, credentials or provider bodies.
- **Specs.** `nautt-finance-integration`: the probe as the only documented pre-order test, the four typed pricing codes, the never-sent `deposit_fields` with `order.deposit_fields_required` as the closed refusal, and the declared gaps in `## Open` — the `/exchange-currencies` schema is not ingested, the quote body proves no method/currency, the `qrcode`/`pix_qrcode` rule is undocumented, account scoping is undocumented. `catalog-and-payment-links`: a registered pair carries **observed** evidence, never inferred provider semantics, and selection requires the target owner's passing probe. `administrative-foundation`: the admin registers and reads evidence but never triggers a provider call, because a Nautt key is strictly self-owned by a merchant. `checkout-and-order-lifecycle`: the pre-dispatch settings refusal as a second producer of the existing failed/refused outcome. Stamp each `Updated` line for 13.4.1; state gaps as gaps and never as facts.
- **Documentation:** a first-pair setup section in `docs/production-runbook.md` (obtain `currency_uuid`/`exchange_currency_uuid` from the Nautt panel — the API listing exists but its schema is not in this repository — register them in admin settings, merchant saves its API key, merchant runs the probe, the first real order records the observed method/currency), with a README pointer. No seed, no scripted bootstrap, no invented endpoint or field.
