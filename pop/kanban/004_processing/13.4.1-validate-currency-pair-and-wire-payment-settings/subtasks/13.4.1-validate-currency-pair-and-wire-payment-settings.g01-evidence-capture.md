## Contrato de execução

- **Table `app.currency_pair_verification`**, one row per (owner, pair): `owner_id` and `pair_id` (both `UUID NOT NULL`), `quote_checked_at` and `quote_outcome` (nullable; `ok` or one documented pricing code), `observed_payment_method`, `observed_currency_symbol` and `observed_at` (nullable), `updated_at NOT NULL`. **Composite primary key `(owner_id, pair_id)`** plus restrictive foreign keys to `app.user` and `app.catalog_currency_pair` — the safe language expresses `createTable`, `addConstraint` (`primaryKey`/`foreignKey`) and `createIndex`, but **only typed constant defaults**, so no column may rely on `gen_random_uuid()` or `now()`: the service writes every timestamp explicitly and the Prisma model must not declare a default the migration never creates.
- **Additive column** `provider_order.currency_symbol` (nullable `VARCHAR`), nothing else on that table; no backfill, no drop, no rename, no data migration.
- **Order view:** carry `currency.symbol` from the creation `201` and from `GET /orders/{uuid}` into `NauttOrderView` as an optional field, parsed with the same strictness as the existing fields, and persist it through `orderData`/`reconcileOrderData` with the same never-clear rule already applied to the PIX payload. An order object without `currency` (documented for crypto kinds, `get-order.md:22-31`) records nothing and raises nothing.
- **Recording:** inside `completeCreation`, in **one transaction** with the order write, resolve the pair from the attempt's `order_v2` (`currency_uuid`, `exchange_currency_uuid` → the unique pair key) and upsert the verification row's `observed_*` triple, latest-wins. A provider order without `orderV2Id`, or an `order_v2` whose pair no longer resolves, records nothing and never fails the creation. Never widen the buyer-visible failure surface.
- **Quote diagnosis:** on a non-200 from `POST /pricing/panel/buy` with a parseable body, raise a typed refusal carrying exactly `validation.exchange_currency_invalid`, `validation.currency_not_found`, `validation.exchange_currency_not_found`, `validation.failed` — nothing else, never widened without new approved research. The new error **extends `NauttPricingAdapterError`** so every existing call site behaves byte for byte as today; any other status, an unparseable body or a transport failure stays the plain adapter error. Log the code, never the key, the body or the amount.
- **Shared predicate** in `src/auth/payment-settings.ts`: an exported pure function deciding whether an observed `(payment_method, currency_symbol)` pair is enabled by `GlobalPaymentSettings`, comparing case-insensitively against the closed BRL/PIX lists, and returning **not enabled when either enabled set is empty** (fail closed). Add the server-side read primitive the checkout needs, commented as never wired to a public or sessionless route, mirroring the gating-primitive convention in `src/auth/supported-exchange-currency.ts:116-125`. Do not change the admin-authorized service's behavior.
- The application **never sends `deposit_fields`**; do not add the field to any request path, and do not invent field names for any currency.
- Tests belong to this front (adapter refusal mapping, symbol persistence, recording with and without `orderV2Id`, the predicate's empty-set case). **Do not run any test suite** — task 13.4.2 runs the battery.
