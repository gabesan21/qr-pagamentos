# Plano — [[15.4.2-fix-target-sizes-and-dictionary-debt]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** raise the interactive targets still under 44 px to the contract minimum, retire the dictionary debt with per-key proof, and repair the two parity-gate defects so the UI gates pass from a clean checkout.
- **Resultado observável:** merchant link-line and period controls expose ≥44×44 px hit boxes built from the declared token family; both locales carry only referenced keys plus a plural product-count pair; `pnpm frontend-parity:check` and `--semantic-mutation-probes` pass with a generated Prisma tree present on disk.

## Estratégia

**Audit before edit.** Two of the four A11 sites are already compliant — `admin-controls.tsx:49` and `checkout-privacy-notice.tsx:20` both carry `min-h-11 min-w-11` — so the live defects are `link-lines-editor.tsx` (steppers `size-8`, remove button `p-1.5`) and `merchant-controls.tsx:32` (`px-3 py-1.5`, no minimum). F01 confirms each site by reading before touching it, leaves compliant ones byte-identical, and uses only the declared family (`min-h-11`/`min-w-11`/`size-11`): no raw pixel value, no second button style, no change under `src/components/ui/**` (frozen owners set).

**No key dies on one grep.** Every retirement candidate passes two stages: literal name search across `src/**`, `scripts/**` and tests; and a computed-access sweep over `dictionary[...]`, `keyof Dictionary` maps and template-literal prefixes (`designSystemCopy${…}` at `interactive-specimens.tsx:43` is the live example). A key reachable by any surviving prefix is kept and the retention is recorded. Removal is symmetric across `en` and `pt-BR` of the owning domain, and `dictionaries.test.ts` pinned lists are updated whenever a pinned key falls. For the plural, the project's convention is platform `Intl` with no bespoke pluralization table (`instant.ts:17`): `paymentLinkDirectoryProductsCount` becomes a flat one/other key pair selected through `Intl.PluralRules`, so the domain parity test keeps comparing key names.

**Fix the boundary before refreshing.** `semanticObligations` walks `filesUnder("src")` (l.260), which includes gitignored `src/generated/prisma` and lets `--refresh-semantic-contract` bake it into tracked records. F03 binds derivation discovery to the git-tracked set — the script already shells `git ls-files` in `trackedReference` (l.329) — and proves it with a probe that keeps a generated file on disk and asserts an unchanged derived contract. Only then does it run the official operations for the two checkout loading routes (`--register-missing-current-routes` when the record is absent, `--refresh-semantic-contract` for stale sources); manifest and obligations are never hand-edited. Order is load-bearing: F01 and F02 both write inside `src/**` — including the route file `admin/payment-links/page.tsx` — so any refresh taken before them goes stale again immediately.

## Riscos e condições de aborto

- **Risco:** apagar chave alcançada por acesso dinâmico — mitigação: confirmação em duas etapas com prefixos expandidos; prefixo que não resolve estaticamente retém a chave e vira registro, nunca remoção.
- **Risco:** `--refresh-semantic-contract` abortar por invariante (`PARITY_REFRESH_INVARIANT_*`) ou outra rota stale fora do escopo, ou a regra de tracked-tree esconder arquivo autorado não rastreado — mitigação: reportar a saída literal e comparar contagem/IDs derivados antes e depois; **abortar se** exigir tocar registro alheio ou a contagem mudar sem rota correspondente → `blocked: true` com o código do erro.
- **Abortar se** 15.4.1 não tiver ledger em `pop/memory/<data>/` — dependência não cumprida, `BLOCKED` sem editar nada.
