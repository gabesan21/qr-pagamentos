# M-6.1 plan — Fix admin authorization advisory lock raw void deserialization

- **Task:** [[M-6.1-fix-admin-authorization-lock-raw-void]] · size S · yolo, non-critical (002→004 direto) · verify-mode: full (toca o lifecycle administrativo entregue)

## Objetivo

`withAuthorizationLock` em `src/auth/administration.ts:158` chama `transaction.$queryRaw` sobre `SELECT pg_advisory_xact_lock(...)`, que retorna `void`; o pg-adapter do Prisma 7.8.0 lança P2010 ("Failed to deserialize column of type 'void'") e **toda** mutação administrativa que passa pela trava (`deleteUser`, `changeStatus`, `changeRole`) falha em runtime com o opaco `change-failed`. Trocar por `$executeRaw` (mesmo fix de 1.4.1 em `src/auth/session.ts:33`) e cobrir com teste de regressão.

## Estratégia

1. **F01 — fix + regressão (único front, executor único):**
   - `src/auth/administration.ts:158`: `$queryRaw` → `$executeRaw`. Nenhuma outra mudança de comportamento; a trava, o escopo transacional e os outcomes opacos ficam byte-idênticos.
   - `src/auth/administration.test.ts` (ou o arquivo de teste existente que cubra o serviço): teste de regressão espelhando `src/auth/session.test.ts:52` — injeta uma transaction fake cujo `$executeRaw` afirma o lexema SQL (`SELECT pg_advisory_xact_lock(hashtext(?))` com o literal `qr:authorization:active-admin`) e retorna `1`; afirma que `$queryRaw` **não** é chamado. Verificar se já existe teste cobrindo `withAuthorizationLock` e estender, não duplicar scaffolding.
2. **Gates no worktree:** `pnpm check` (PIPESTATUS, nunca pipe puro) e `pnpm db:test` — o db:test exercita o caminho real contra PostgreSQL descartável e deve provar deleteUser feliz.
3. **Closeout:** nenhuma spec muda (comportamento pretendido já está especificado — isto é repair, não mudança de contrato). Nenhum AGENTS.md muda. Log/telemetria do card.

## Contratos e invariantes
