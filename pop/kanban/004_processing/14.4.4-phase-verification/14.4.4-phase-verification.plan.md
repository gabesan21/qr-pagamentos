## Estratégia

Work in five ordered steps inside a single front: realign, cover, repair, evidence, gate. Realignment comes first because a falsified suite hides real regressions; the full `pnpm check` is the last step so its counts describe the final tree.

**Pins are exact-token assertions.** The 14.3.4 round-1 lesson holds: a pin that would also pass against pre-14.4 code proves nothing. Compare class tokens by equality (not substring), assert exact attribute values, exact route strings and exact prop names, and assert the *absence* of the retired token wherever a rename happened (`pageTitle`, `.admin-dashboard*`, `/admin`, 768px/`48rem`). Coverage must reach **every** site named in criteria 2–4, not a representative subset.

**Repairs are bounded.** Only the defects listed in criterion 6 may touch Phase 14.4 sources; the pt-BR dictionary edit is authorized for that single string only (`paymentLinkDirectoryFilterMerchant`, "Vendedor" → "Lojista"). A defect that needs a service, DTO or durable-contract change is above the phase's reach: record it in memory and propose a modification instead of fixing it here.

## Riscos e condições de aborto

- **Risco:** a pin encoded against the current DOM passes by accident — mitigação: criterion 5 demands the falsification note per renamed contract.
- **Risco:** flaky Playwright evidence (see [[pop/notes/references/limites-de-verificacao|limites-de-verificacao]]) — mitigação: two attempts, then reclassify that criterion as `verify: user` with a Log line and move on.
- **Abortar se:** a failure requires changing a service, DTO or durable contract to go green — sinalizar `blocked: true` with the failing test output and the modification proposal.
