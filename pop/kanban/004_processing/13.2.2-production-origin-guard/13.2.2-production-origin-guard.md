# 13.2.2-production-origin-guard — Production origin guard

- **Origem:** [[pop/roadmap/13-pre-production-hardening|Phase 13.2]]
- **Plano:** [[13.2.2-production-origin-guard.plan]] · **Aprovação:** [[13.2.2-production-origin-guard.approval]] · **Verificação:** [[13.2.2-production-origin-guard.verify]]

## O quê

A production build (`NODE_ENV=production`) refuses to start when `PUBLIC_ORIGIN` or `NAUTT_WEBHOOK_CALLBACK_URL` is a loopback HTTP origin unless an explicit allowance variable is set; the installer writes that allowance automatically when the operator chooses a loopback origin, so the current local test install keeps working unchanged. Documented in the runbook and `.env.example`.

## Por quê

The 2026-09-22 loopback allowance is host-scoped but nothing stops a real deployment configured by mistake with a loopback origin (decision 4 of 2026-09-23).
