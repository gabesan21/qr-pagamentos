# Plano — [[14.6.3-phase-verification]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** close Phase 14.6 by running the aggregate gate over the integrated `develop`, realigning every suite the two public-surface tasks falsified, adding the regression their checklists owed — checkout state machine, validation/masks, outcome views, the branded shell, storefront and standalone reuse — plus the regression owed for the three defects the judge caught in 14.6.1, repairing what the suite proves inside the phase's reach, refreshing the design-system evidence that the `globals.css` retirement invalidated again, and consolidating the human checklist the epoch's final PR will carry.
- **Resultado observável:** `tsc`, the lint chain, `vitest` and `next build` exit 0 from the task worktree; `/pay/**`, `/store/[slug]` and `/store/[slug]/pay` suites assert the converged compositions instead of the retired ones; each repair is named with `file:line`; the design-system evidence run is regenerated and verified; the three Docker-driven public evidence runs and the browser pass are handed to the human as one explicit checklist.

## Estratégia

Verification only. Application behaviour changes exclusively where the suite proves a defect **inside Phase 14.6's reach** — the public checkout `/pay/[identifier]/**`, the public storefront `/store/[slug]/*` and the standalone payment `/store/[slug]/pay/**`, plus `src/checkout/public-checkout*presentation*` where 14.6.1 projected the additive `branding`. A defect outside that reach is a reported follow-up, never a repair here; `prisma/**`, every `route.ts`, `src/components/ui/**`, `src/data-directory/**`, `src/media/**`, `src/integrations/**`, `scripts/**` and every merchant surface stay read-only unless the repair is the bug itself and the DOX contract still holds.

Six decisions are pinned. **(1) Direct binaries, never `pnpm <script>`, never Docker.** The task runs in its own worktree where the workspace scripts resolve wrongly; the gate is `./node_modules/.bin/tsc --noEmit`, the expanded lint chain (`node scripts/generate-design-tokens.mjs --check && node scripts/generate-brand-assets.mjs --check && node scripts/check-font-provenance.mjs && node scripts/check-design-tokens.mjs && ./node_modules/.bin/eslint .`), `./node_modules/.bin/vitest run` and `./node_modules/.bin/next build` — the same four gates `check` aggregates. **(2) Realignment asserts the converged surface, it never lowers the bar.** No `.skip`/`.todo` is added, no case is deleted without being re-covered, and every falsified assertion is rewritten against the delivered composition read in the source, not around it. **(3) The falsified list is a floor, not a closed set.** 14.6.1's checklist names its two forms; 14.6.2's `g01` reports its realignment done, and `g02` was still executing when this plan was written, so its list is **discovered from the integrated diff and the failing run** — `src/app/store/[slug]/pay/{page,standalone-payment-experience}.test.tsx` first, plus any suite asserting a retired `storefront-*`/`receipt-rail*`/`.checkout-*` class or the pre-`branding` `public-checkout-presentation` shape — and the discovery is reported, not assumed. **(4) Evidence splits by runner, not by area.** `run-checkout-evidence.mjs`, `run-storefront-evidence.mjs` and `run-standalone-payment-evidence.mjs` all delegate to `run-admin-evidence.mjs`, which drives `docker compose up -d --build` (`scripts/run-admin-evidence.mjs:75,89`), so those three runs are **user-exclusive** and are handed over stale with their command pairs; the design-system run is local and binds `src/app/globals.css`, which both 14.6.1 and 14.6.2 edited — it is regenerated and re-verified here, and `verify-login-evidence.mjs` is re-run as a pure hash check. **(5) The regression owed includes the judged defects.** The three blockers 14.6.1 repaired under judgement (identity centre-cut unwired, unavailable view with no render site after the poll `404`, `checkout-*` still emitted under `/pay`) each get a pinning test, so no future edit silently reopens them. **(6) The baseline is a floor.** Phase 14.5's own gate task ([[14.5.4-phase-verification]]) runs in parallel with this planning; its reported counts are the floor and are **read at run time** from its slice `Resultado` or its memory ledger — if neither is filled, the pinned floor is 2185 passing / 28 skipped with lint at 0 errors. Passing only grows; skipped does not.

## Frentes de execução

### F01 — Phase 14.6 gate, realignment, regression, repairs and evidence

- **Entrega:** the whole verification pass — realignment, owed regression, in-reach repairs, the design-system evidence refresh, the aggregate gate result and the consolidated human checklist.
- **Contrato:** [[14.6.3-phase-verification.g01-phase-gate]] — *siga como fatia única desta frente* · **Papel:** `pop-phase-verifier` · **Depends on:** 14.6.1 e 14.6.2 integradas · **Critérios:** C01–C11.

**Frente única, justificada:** the gate is one indivisible run over the integrated tree, the checkout controller/views are shared by all three public routes so any repair crosses the route boundary, and a split would produce overlapping write sets in the same test tree plus two conflicting suite states — parallelism buys nothing and costs the single source of truth for the aggregated result.

## Ordem e paralelismo

1. Read 14.6.1's memory entries and 14.6.2's two slices plus the integrated diff; run `vitest run` once to turn the floor list into the real failing set.
2. Realign (C01), then add the owed regression (C02, C03), then repair what remains red (C04) — in that order, so a repair is never a way to make a stale assertion pass.
3. Run the four gates to green (C05); regenerate and verify the design-system evidence after the last source-touching commit (C06).
4. Write the handover: stale Docker runs with commands (C07), carried criteria closed (C08), consolidated checklist (C11). **Integração:** o agente principal confere ownership, o resultado agregado e os critérios `agent`.

## Riscos e condições de aborto

- **Risco:** a realignment that only makes red green — mitigação: C01 forbids `.skip`/`.todo` and uncovered deletions; every rewritten assertion cites the delivered source.
- **Risco:** 14.6.2's `g02` lands after the run starts, or lands with an unfilled `Resultado` — mitigação: decision (3) makes the floor a discovery from the diff and the run; if `g02` is not integrated at all, the front returns `BLOCKED` instead of verifying half a phase.
- **Risco:** repair drift beyond the phase — mitigação: C04 caps the reach and C09 pins the non-test diff to the listed repairs; anything else is a follow-up in the report.
- **Risco:** the local evidence run fails for environment reasons (build, browser, port, `pnpm start` inside the worktree) — mitigação: start the server with the direct binary and pin `ADMIN_EVIDENCE_BASE_URL`; at most 2 attempts, then record `ambiente`, reclassify that item to `verify: user` and continue; the gate result is not blocked by it.
- **Abortar se:** a caught defect can only be fixed by a schema, route, dictionary-owner or `src/components/ui/**` contract change — reportar `blocked: true` com arquivo, linha e o contrato que impede.
