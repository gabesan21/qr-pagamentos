# 13.2.3-encryption-key-rotation-procedure — Encryption key rotation procedure

- **Origem:** [[pop/roadmap/13-pre-production-hardening|Phase 13.2]]
- **Plano:** [[13.2.3-encryption-key-rotation-procedure.plan]] · **Aprovação:** [[13.2.3-encryption-key-rotation-procedure.approval]] · **Verificação:** [[13.2.3-encryption-key-rotation-procedure.verify]]

## O quê

Give `NAUTT_ENCRYPTION_KEY` and `TOTP_ENCRYPTION_KEY` a rotation path: a documented procedure plus tooling (one-shot re-encryption of stored Nautt API keys, webhook secrets and TOTP secrets under a new key, with a dual-key read window so a half-rotated deployment never loses access), the runbook section, and the spec amendment closing the Open item on key lifecycle. Never logs or prints key material; never changes the webhook URL registration.

## Por quê

Loss or compromise of either key is unrecoverable today (spec Open, installer warning); a production deployment needs a rotation path before the first real secret is stored.
