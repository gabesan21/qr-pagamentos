## Contrato de execução

- Split by testability: the rewrap logic lives in `src/security/key-rotation.ts` (injected store and crypto, no Docker, no process exit) and `container/rotate-encryption-keys.mjs` is a thin wrapper reading `/run/secrets/*` like the other one-shots. Only the thin wrapper may touch the filesystem or the process.
- Rewrap covers exactly `nautt_credential.encrypted_api_key`, `nautt_credential.encrypted_webhook_secret` and `totp_credential.encrypted_secret`. Rows are processed regardless of `webhook_registration_state`.
- Every update is conditional on the ciphertext observed when the row was read and writes only that column. Never touch `credential_revision`, registration state, `provider_webhook_id`, timestamps or any other column; never register, call or change a webhook URL; never read `NAUTT_API_BASE_URL`.
- Idempotent and resumable: a row already readable under the current key is left alone, a re-run rewraps zero rows, and an interrupted run leaves a valid mixed state that the open window still reads.
- Output is counts and fixed codes per table (scanned, rewrapped, skipped, unreadable) — never a value, ciphertext, identifier, connection URL or filesystem path. An unreadable row under both keys is a non-zero-exit failure, never a silent skip.
- Wiring: `runtime.mjs` injects `*_ENCRYPTION_KEY_PREVIOUS` only when the optional secret exists, validating it with the same 32-byte base64url check; compose gets the two optional secrets and the one-shot service behind a profile so it never runs on `up`; the installer stages and validates an optional previous key without ever generating, rotating or overwriting existing key material.
- The installer contract "never rotate, regenerate, overwrite, print, hash-log, or path-log continuity material" stays intact: rotation is an explicit operator-invoked operation, never a side effect of install or update.
