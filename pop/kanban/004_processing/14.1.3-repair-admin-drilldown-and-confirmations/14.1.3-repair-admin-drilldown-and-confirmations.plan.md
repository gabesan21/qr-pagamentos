# Plano — [[14.1.3-repair-admin-drilldown-and-confirmations]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** repair three blocking administrator defects — the dead link→orders drill-down, three destructive actions that POST with no confirmation, and the account menu that renders empty for administrators.
- **Resultado observável:** "View orders" on `/admin/payment-links/v2/[id]` reaches `/admin/orders` filtered by that link's identifier instead of the invalid-query card; row delete, account soft delete and TOTP disable each require an explicit `ConfirmDialog` — typed username for the two deletions — before the unchanged native POST; the top-bar account menu always offers Sign out and offers Profile only where the role has one.

## Estratégia

The change is presentation and interaction only: the `/admin/users/<id>/{delete,totp-disable}` routes, authorization, the final-active-administrator safeguard, opaque outcomes and redaction stay byte-frozen, and each confirmed action still submits the same native POST form.

Drill-down: `/admin/orders` already declares a `link` text filter (`ADMIN_ORDER_V2_DIRECTORY_FILTERS`) resolved server-side against `paymentLink.identifier`, and the parser accepts only the `filter.<name>` grammar. No directory, service or filter addition is warranted — the defect is the emitted query string alone, which becomes `filter.link=<url-encoded identifier>`; a non-canonical target already redirects to its canonical form.

Confirmations: one owned client module under `src/app/admin/accounts/` pairs each destructive control with the real `<form method="post">` it submits, holding the `ref` on that very element (or using the `form` attribute) and confirming through `requestSubmit()`. The detached-ref defect of `product-detail-client.tsx` — refs declared but never attached, owned by [[14.1.1-repair-product-lifecycle-actions]] — must not be reproduced. `ConfirmDialog` already supports the typed `confirmation` requirement; it is consumed, never edited. Copy is dictionary-only, added to `en` and `pt-BR`; styling uses Tailwind utilities or `src/app-shell/app-shell.css`, since `src/app/globals.css` belongs to 14.1.2 in this wave.

## Áreas afetadas

## Riscos e condições de aborto

- **Risco:** reproducing the detached-ref defect, leaving a dialog that confirms nothing — mitigação: the `ref` lives on the same `<form>` element rendered by the module that owns the dialog, and criterion 5 reads the diff for it.
- **Risco:** a confirmation boundary turning an administrator page into a client tree and leaking server-only data — mitigação: the client module receives only id, username and labels; the pages stay server components.
- **Abortar se:** the `link` filter proves not to resolve against the V2 link identifier, or a confirmation cannot be added without changing a delivered route — sinalizar `blocked: true` citando arquivo e linha.
