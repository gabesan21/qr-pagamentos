# Plano — [[14.3.4-phase-verification]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** run the aggregate gate on the integrated `develop`, realign every assertion Phase 14.3 falsified, add the regression its three checklists owed, apply the cheap in-phase repairs the judgments left, and refresh the design-system evidence.
- **Resultado observável:** `pnpm check` exits 0 with no test deleted and no new skip (baseline after 14.2.5: 2104 passed / 28 skipped, lint 0), `pnpm design-system:evidence:verify` accepts a current run, and each Phase 14.3 behaviour is pinned by a test that would fail against the pre-phase code.

## Estratégia

Order is realign → cover → repair → evidence. A suite still encoding the old destinations hides real defects, so stale assertions are rewritten in place first — never deleted — and only then does new coverage land. Realignment is mechanical and deterministic: directory consumer suites gain the `next/navigation` `useRouter` mock and assert the reset redirect (`?filters=ignored`) where they asserted the `invalid-query` render; mutation route suites assert the on-page destinations; the token suites move to the on-soft primitives and the 27 `@theme inline` utilities.

Repairs stay inside the phase's reach: the files 14.3.1–14.3.3 delivered plus the five cheap items registered by the judgments. Anything else — a durable contract that is wrong, a structural miss of an earlier request — is recorded and proposed as a new task or modification, never fixed here. **Contract text is read-only in this task:** if a repair would make a spec or DOX sentence untrue (the free-text debounce against "on-change controls" is the known candidate), the repair is dropped and becomes a follow-up instead. This is the one task where tests are `verify: agent`; environment failures follow the stop rule (two attempts, then `ambiente` in telemetry and reclassification to `verify: user`), never new infrastructure, and Docker-dependent checks stay out entirely.

## Riscos e condições de aborto

- **Risco:** a repair contradicts spec or DOX wording (free-text debounce, default `pageSize`), or a failure's fix lies outside Phase 14.3 (durable contract, earlier structural miss) — mitigação: drop/record it and propose a task or modification; contract files stay untouched (WORKFLOW §"Verificação de phase").
- **Risco:** flaky teardown (the `input-otp` timer class of failure seen in 14.2.5) or an unavailable Playwright browser — mitigação: two attempts, then `ambiente` + `verify: user`, per `notes/references/limites-de-verificacao.md`.
- **Abortar se:** `pnpm test` stays red after the in-reach repairs, or the only remedy is outside the phase's reach — sinalizar `blocked: true` com the failing test path and the run output.
