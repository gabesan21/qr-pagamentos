# Plano — [[14.7.2-phase-verification]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** close Epoch 14 by running the aggregate gate over the integrated `develop` after 14.7.1's BEM retirement, realigning every suite and every evidence spec that retirement falsified, regenerating the two locally runnable evidence pairs (design-system and login), repairing only the retirement's fallout inside Phase 14.7's reach, consolidating every `verify: user` item of Phases 14.1–14.7 into one checklist file, and drafting the `develop` → `main` PR body the agente principal will open.
- **Resultado observável:** `tsc`, the lint chain, `vitest` and `next build` exit 0 from the task worktree with exact counts reported; no suite or evidence spec still asserts a deleted class; `artifacts/design-system` and `artifacts/login` are regenerated, reviewed and verified; [[pop/notes/references/2026-09-08-epoch-14-human-verification-checklist|the consolidated checklist]] exists as one readable file; the PR body draft sits in the slice's `Resultado`, ready for `gh`.

## Estratégia

Verification and handover only. Behaviour changes exclusively where the suite proves a defect **inside Phase 14.7's reach** — the CSS retirement fallout (a class dropped without its geometry replaced, a deleted rule that still had a referrer, a contract line that now names a class that no longer exists). A defect outside that reach is a reported follow-up, never a repair here.

Seven decisions are pinned. **(1) Direct binaries in the worktree, never `pnpm <script>`, never a container:** `./node_modules/.bin/tsc --noEmit`; `node scripts/generate-design-tokens.mjs --check && node scripts/generate-brand-assets.mjs --check && node scripts/check-font-provenance.mjs && node scripts/check-design-tokens.mjs && ./node_modules/.bin/eslint .`; `./node_modules/.bin/vitest run`; `./node_modules/.bin/next build` — the same four gates `check` aggregates (`package.json:76`). The aggregate `pnpm check` runs **once more**, at the repo root, on the integrated `develop`, by the agente principal (C13). **(2) Realignment never lowers the bar:** no `.skip`/`.todo` added, no case deleted without named re-coverage, every rewritten assertion read from the delivered source. **(3) The falsified set is discovered, not assumed:** 14.7.1 C10 names its floor (`login/page.test.tsx`, `reset-password/page.test.tsx`, `(merchant)/settings/settings-surface.test.tsx`, `storefront-settings-management.test.tsx`, `design-system/specimen-mounted.test.tsx`, `routes.test.ts`, `check-admin-ui-inventory.test.ts`, the suites of the deleted `OrderListCard`/`payment-link-management`); the run and the integrated diff add to it. **(4) Evidence splits by runner, not by area — and `tests/**` is source too.** Locally runnable: **design-system** (`pnpm design-system:evidence` = build + Playwright) and **login** (`pnpm login:evidence`, `/login` needs no database — `src/app/login/page.tsx:16` reads cookies only). Everything else, **including `reset-password`**, drives `docker compose` (`scripts/run-reset-password-evidence.mjs:60,97`; `scripts/run-admin-evidence.mjs:75,89`) and is user-exclusive. But two evidence **specs** are falsified in source by 14.7.1 and must be realigned here even when their run is the user's: `tests/login.evidence.spec.ts:174-175` (`.auth-brand[data-brand-identity]`, `.auth-brand [data-brand-mark]`) and `tests/store-settings.evidence.spec.ts:253` (`.settings-surface__nav-link`). **(5) A regenerated baseline is argued, never rubber-stamped.** The login run has no self-written review: `scripts/verify-login-evidence.mjs:24-25` demands `artifacts/login/<runId>/review.md` naming the run and the manifest SHA-256 with no unresolved severity 2+. The verifier authors it after reading the eight captures and names each pixel change against the class-for-utility swap that caused it; a difference it cannot explain is a defect, not a new baseline. The design-system spec writes its own review (`tests/design-system.evidence.spec.ts:497`), so there the argument goes in the report. **(6) The suite floor is read at run time** from 14.6.3's slice `Resultado` or its memory ledger, else 14.5.4's; if neither is filled, the pinned floor is 2185 passing / 28 skipped with lint at 0. Passing only grows; skipped does not. **(7) The PR is drafted here and opened there.** `pop_delivery.py scope-pr` hardcodes title and body (`pop/scripts/pop_delivery.py:75-76`) and requires a clean tree, a checked-out `develop` and `gh`; so this task writes the body draft into the slice `Resultado` and the agente principal opens the PR (`gh pr create --base main --head develop --body-file`, or `scope-pr` followed by `gh pr edit --title --body-file`). The merge is the human's.

## Frentes de execução

### F01 — Epoch 14 gate, realignment, evidence, checklist and PR draft

- **Entrega:** the whole verification pass — realignment, the single-system regression, in-reach repairs, the two local evidence regenerations, the aggregated gate result, the consolidated human checklist file and the PR body draft.
- **Contrato:** [[14.7.2-phase-verification.g01-phase-gate]] — *siga como fatia única desta frente* · **Papel:** `pop-phase-verifier` · **Depends on:** 14.7.1 (F01, F02 **e** F03) integrada · **Critérios:** C01–C14.

**Frente única, justificada:** the gate is one indivisible run over the integrated tree; the retirement crosses every route family at once, so any split would produce overlapping write sets in the same test tree, two conflicting suite states and two competing evidence runs on the same port — parallelism buys nothing and costs the single source of truth for the aggregated result.

## Ordem e paralelismo

1. Read 14.7.1's three reports and its integrated diff; run `vitest run` once to turn the floor list into the real failing set.
2. Realign suites and the two evidence specs (C01, C02), add the single-system regression (C03), then repair what stays red (C04) — in that order, so a repair never rescues a stale assertion.
3. Run the four gates to green (C05); only then regenerate design-system (C06) and login (C07) evidence, after the last source-touching commit.
4. Write the handover: Docker runners declared stale with their pairs (C08), the consolidated checklist file (C09), the PR body draft (C10), carried criteria closed (C11). **Integração:** o agente principal confere ownership, integra, roda `pnpm check` na raiz (C13) e abre o PR; o merge é humano.

## Riscos e condições de aborto

- **Risco:** baseline drift — a regenerated capture differing for a reason nobody can name. Mitigação: C07 forces a per-difference justification against the class-for-utility swap; an unexplained difference is treated as a defect and repaired, never accepted as the new baseline.
- **Risco:** flaky Playwright (toast/animation races, non-deterministic captures — [[pop/notes/references/limites-de-verificacao|verification limits]]). Mitigação: `--workers=1`, `reducedMotion` already pinned by the specs; at most 2 attempts, then record `ambiente`, reclassify that pair to `verify: user` in the checklist and continue — the gate result is not blocked by it.
- **Risco:** port 4319 already bound, or Playwright starting its own server through `pnpm start`. Mitigação: always export `ADMIN_EVIDENCE_BASE_URL` (it is what disables `webServer`, `playwright.config.ts:20`); if the port is taken, start on another port and export the matching URL; tear the server down at the end.
- **Risco:** time budget — the design-system matrix is 48 captures (~700s) plus login's 8. Mitigação: regenerate **after** the last source commit, once; never per attempt.
- **Risco:** the checklist swelling past the 150-line note cap. Mitigação: group by page/family, one line per check, Docker pairs as a single table.
- **Abortar se:** 14.7.1 is not fully integrated (any of F01/F02/F03 missing) → `BLOCKED`, never verify half a phase. **Abortar se:** a caught defect can only be fixed by a schema, route, dictionary-owner or `src/components/ui/**` contract change → `blocked: true` com arquivo, linha e o contrato que impede.
