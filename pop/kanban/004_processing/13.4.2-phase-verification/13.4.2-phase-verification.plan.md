## Objetivo e resultado esperado

- **Objetivo:** run Phase 13.4's accumulated checklist on the integrated 13.4.1 tree, repair only Phase 13.4 defects, and — if 13.3.4 has already closed — append Phase 13.4 to the epoch's hand-off notes and **suggest** the `develop` → `main` PR.
- **Resultado observável:** every `phase` criterion of [[13.4.1-validate-currency-pair-and-wire-payment-settings]] has a recorded run with its exact command and output; the provider-configuration work is proven without a single Nautt call made by the agent; the real-pair proof reaches the human checklist instead of being claimed here.

## Estratégia

Planned **before** 13.4.1 executes, from its approved plan and its three slices in `003_human_approval`. This checklist is a **forecast**: the first act of 004 is to re-read the final plan, the three slices as merged and the 13.4.1 memory ledger, and to **amend by `lacuna`** any criterion that moved — the sibling's final table wins over this one, a vanished criterion is recorded as such, never silently dropped, and IDs are append-only.

**Nothing runs through Docker and nothing calls Nautt.** Every `agent` gate is direct pnpm on the integrated tree; `pnpm db:migration-policy` and `pnpm db:contract-check` are static (no database). `pnpm db:test`, a real Nautt account, `install/*`, `container:*` and evidence runners stay `user`. If a pnpm wrapper misbehaves, fall back to `./node_modules/.bin/{tsc,vitest,next}` and record the substitution — this is **not** an attempt. On an environment failure, at most **2 attempts**; on the second, record `ambiente`, reclassify the criterion to `verify: user`, append one line to [[pop/notes/references/limites-de-verificacao|verification limits]] and continue ([[WORKFLOW|WORKFLOW]], `005_closing`).

**Repair reach is Phase 13.4 only.** A falsification traceable to 13.4.1's own diff is repaired here, each edit naming the criterion it repairs. A durable-contract defect (spec text, DOX rule, an earlier phase's unmet request) is **not** repaired: it is recorded in the memory entries and in the 004 report as a modification/task proposal. The five declared gaps of 13.4.1 (L1–L5) are **gaps, not defects** — a criterion demanding proof the in-repo documentation cannot give is a plan defect, not a failing product.

**Hand-off is conditional.** If [[13.3.4-phase-verification]] has closed when this runs, its two notes exist and this task **appends** a Phase 13.4 section to each (same files, same shape, no rewrite of prior rows) and suggests the `develop` → `main` PR — never opens it ([[pop/notes/decisions/2026-09-23-epoch-13-decisions|decision 2]]). If 13.3.4 is still open, this task creates no note and records in the 004 report that 13.3.4 remains the epoch's hand-off ([[pop/roadmap/13-pre-production-hardening|Epoch 13]]).

## Riscos e condições de aborto

- **Risco:** the forecast checklist diverges from what 13.4.1 delivered (suite names, front boundaries) — mitigação: A0 re-reads the final plan and ledger first; divergence is an appended `lacuna`, never a renumbering.
- **Risco:** a green suite is mistaken for provider proof (gap L2) — mitigação: no `agent` criterion asserts PIX/BRL reality; the real pair and the first real order live only in U1.
- **Risco:** a repair widens scope into a spec, a DOX file or an earlier phase — mitigação: classify before repairing, send out-of-reach findings to the report's follow-ups and to memory, and stop for the principal's authorization before any out-of-`owns` edit.
- **Abortar se:** the 13.4.1 ledger is missing, the tree does not contain its merged diff, or a criterion would require Docker or a Nautt call — sinalizar `blocked: true` naming the path or the command.
