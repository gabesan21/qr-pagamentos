# Plan — [[15.3.1-checkout-explicit-states-without-retry]]

- **Stage:** 002_planning · **Role:** `pop-planner` (separate from execution)

## Objective and expected result

- **Objective:** the buyer checkout of `/pay/[identifier]` and `/store/[slug]/pay` names every non-confirmed outcome as an explicit state whose single action is **Start over**; no automatic or manual retry survives.
- **Observable result:** a payload renders QR + copy-paste; `PENDING` without payload, `INDETERMINATE` and a rejected QR generation render *PIX unavailable*; a failed status read renders *status unavailable*; a failed submit renders *submit failure*. Nothing pulses forever and no control re-executes a failed call.

## Strategy

Pinned by the human (decision 3, not reopenable): remove the `1s·2^n` backoff, `retryPoll`/`pollRetryTick`, `checkoutCheckAgain`, `checkoutPollErrorBanner`, `checkoutRetryStatus`, `checkoutRetry`, `checkoutGeneratingQr` and the same-attempt resubmission; keep the 5 s visibility-aware read, keep the opaque `404` treatment, keep server-side idempotent replay. `checkoutStartOver` is the only action and re-keys the attempt.

**Waiting rule (fixed here, do not widen):** the short honest waiting treatment — state badge, amount, `aria-busy` on the waiting region, no QR frame and no caption promising data — is allowed **only** for `RESERVED`/`CREATING`/`CREATED`, where the next 5 s read can still change the outcome. `PENDING` renders QR + copy-paste only with a payload; `PENDING` without payload, `INDETERMINATE` and a rejected generation are the explicit *PIX unavailable* state. Polling keeps observing while the state is non-terminal, so a later read still flips the view; a **failed read stops the loop** (no reschedule) and renders *status unavailable*. F01 fixes the presentation contract and the copy, F02 rewires the controller and both adapters onto it, F03 amends the spec in parallel; tests are updated in place but never run here.

**Non-goals (collision fences):** `pixQrCodeUrl` is not touched anywhere — parsers and public DTOs belong to 15.2.3, and it is never a PIX fallback; the customer-data block stays as is (15.3.2); `aria-live`, on-soft warning tone, token vocabulary and locale-aware loading stay as is (15.3.3).

## Affected areas

- `src/app/pay/[identifier]/` and `src/app/store/[slug]/pay/` — shared controller, both adapters and the payment/outcome view.
- `src/components/ui/qr-display.tsx` — a rejected generation must reach its caller instead of rendering a blank frame.
- `src/i18n/dictionaries/checkout/` (both locales) and `pop/specs/checkout-and-order-lifecycle.md` — copy and the pinned retry/backoff lines.

- **Risk:** 15.3.2/15.3.3 touch the same files — mitigation: the non-goals above; this task runs first in the phase and leaves their surfaces untouched.
- **Risk:** removing the INDETERMINATE warning paragraph removes 15.3.3's on-soft item — mitigation: record it in the task memory so 15.3.3 re-scopes instead of restoring copy. **Risk:** `QrDisplay` is shared (`totp-qr-code`, `/design-system`) — mitigation: the failure report is an **additive optional** prop; no existing owner changes behavior.
- **Abort if:** after Phase 15.1 the polling controller has no V2 home (relocation was 15.1.1's fork), or honoring the plan would require editing `src/app/api/**`, `src/checkout/**` or a server DTO — report `BLOCKED`, never recreate a V1 module or cross the boundary.
