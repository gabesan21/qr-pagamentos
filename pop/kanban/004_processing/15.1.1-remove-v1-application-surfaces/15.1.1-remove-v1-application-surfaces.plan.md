# Plano — [[15.1.1-remove-v1-application-surfaces]]

- **Etapa:** 002_planning · **Papel:** `pop-planner` (separado da execução)

## Objetivo e resultado esperado

- **Objetivo:** remove the V1 payment-link/checkout/order line from the application layer, so `src/` and `tests/` describe Commerce V2 only — no V1 module, route, page, DTO branch, dictionary key or test left behind.
- **Resultado observável:** `/pay/[identifier]`, the checkout/status APIs, `/orders`, `/admin/orders` and `/links` resolve V2 services exclusively; a grep for any V1 module specifier in `src/` and `tests/` returns nothing; every V2 surface keeps the behavior it has today.

## Estratégia

V1 and V2 are entangled by **shared vocabulary**, not by behavior: `src/orders/payment-link-order.ts` owns `CHECKOUT_DATA_POLICIES`, `PAYMENT_LINK_ORDER_STATES`, `CustomerSnapshotV1` and `normalizeCustomerSnapshotV1`; `src/app/orders/order-views.tsx` owns `orderStateLabel`/`OrderStateBadge`; `src/auth/payment-link.ts` owns `PAYMENT_LINK_TYPES`. More than ten V2 modules import them. Wave 1 therefore relocates that vocabulary into V2-owned homes with identical members and semantics — the fork the epoch declares — so that deletion afterwards is pure subtraction instead of a rewrite.

Deletion then runs over two **disjoint surfaces** (public checkout · merchant/admin orders and links), each removing its modules, routes, pages, V1-first branches and V1 tests in one go, because a branch and the test that pins it are a single edit. A final wave sweeps the cross-cutting inventories, which only become dead once both surfaces are gone. The recon's V1 footprint is a **floor, not a ceiling**: the import graph decides, and `src/auth/public-payment-link.ts` (the V1-first branch of `/api/payment-links/[identifier]`) is one already-confirmed addition. No V2 export, signature or DTO field changes. Persistence belongs to [[15.1.2-remove-v1-persistence-and-rebase-migrations]] and contracts/parity to [[15.1.3-rewrite-contracts-and-parity-without-v1]]; a deletion that would require either one stops and reports.

## Áreas afetadas

- `src/checkout/**` · `src/orders/**` · `src/auth/payment-link.ts` · `src/auth/public-payment-link.ts` — V1 services and stores leave after their shared types move; V2 services rewire.
- `src/app/pay/**` · `src/app/api/payment-links/**` — V1-first resolution collapses into the V2 path.
- `src/app/(merchant)/**` · `src/app/admin/orders/**` · `src/app/orders/**` · `src/app/payment-links/**` — legacy tables, sections, detail pages and V1 admin routes leave.
- `src/i18n/dictionaries/**` · `src/observability/server-request-log.ts` · `src/security/public-rate-limit.ts` · `src/app/routes.test.ts` · `tests/*.evidence.spec.ts` — inventories and copy that still enumerate V1.

- **Entrega:** every V2 consumer imports policies, order states, customer snapshot, state labels and link types from a V2-owned module; no V1 file is deleted yet. **Contrato:** [[15.1.1-remove-v1-application-surfaces.g01-shared-vocabulary-relocation]] — *siga como fatia única desta frente* · **Depends on:** nenhuma · **Critérios:** C06, C07, C10.

### F02 — Delete the public checkout V1 surface
- **Entrega:** V1 checkout/presentation/status services, the `/pay` V1 form and page branch and the V1-first API resolution are gone; the public checkout is V2-only. **Contrato:** [[15.1.1-remove-v1-application-surfaces.g02-public-checkout-surface]] — *siga como fatia única desta frente* · **Depends on:** F01 · **Critérios:** C01, C02, C03, C04, C08, C10.

### F03 — Delete the merchant and admin V1 surface
- **Entrega:** V1 order/link services, legacy tables and sections, the two V1 detail pages and the V1 `/payment-links` routes are gone; the directories are V2-only. **Contrato:** [[15.1.1-remove-v1-application-surfaces.g03-merchant-admin-surface]] — *siga como fatia única desta frente* · **Depends on:** F01 · **Critérios:** C01, C02, C05, C08, C10.

### F04 — Sweep the cross-cutting inventories
- **Entrega:** route contract, request-log and rate-limit inventories, both dictionaries and the evidence specs name no V1 route, key or era. **Contrato:** [[15.1.1-remove-v1-application-surfaces.g04-inventories-and-dictionaries]] — *siga como fatia única desta frente* · **Depends on:** F02, F03 · **Critérios:** C02, C09, C10, C12.

## Ordem e paralelismo

1. **Onda 1:** F01 — sole writer of the relocation; every later front assumes it landed.
2. **Onda 2:** F02 and F03 in parallel — disjoint write sets, no logical dependency. Each alone leaves the tree non-compiling; only the integrated result is consistent, and no test runs here.
3. **Onda 3:** F04, after both deletions expose the dead inventory entries. **Integração:** o agente principal valida ownership com `pop/scripts/pop_check_scope.py`, integra e confere os critérios `agent`.

## Riscos e condições de aborto

- **Risco:** a V2 module still imports a V1 helper after F01 (the epoch's declared fork) — mitigação: F02/F03 relocate nothing on their own; a surviving import is reported to the principal, never solved by keeping a V1 file alive.
- **Risco:** a surviving V2 test mocks or imports a V1 fixture (`links/new/page.test.tsx`, `links/v2/[id]/edit/page.test.tsx`, `page.test.tsx`, `checkout-shell.test.tsx`, `checkout-footer.test.tsx`) — mitigação: the front that deletes the section also deletes the mock that pinned it; a V2 assertion that genuinely depends on V1 data is reported, not rewritten into new behavior.
- **Risco:** inventories keep enumerating deleted routes (`routes.test.ts` V1-first ordering, `serverRequestRoutes.paymentLinks`/`paymentLink`, rate-limit buckets, evidence "both eras" grid) — mitigação: F04 owns all of them exclusively and runs last.
- **Abortar se:** a deletion requires editing `prisma/**` or a pinned migration (hand it to 15.1.2), or rewriting a spec, an `AGENTS.md` or a parity record (hand it to 15.1.3) — sinalizar `blocked: true` com `arquivo:linha`.
- **Abortar se:** removing a V1 path would change or remove observable V2 behavior — sinalizar `blocked: true` with the evidence.
