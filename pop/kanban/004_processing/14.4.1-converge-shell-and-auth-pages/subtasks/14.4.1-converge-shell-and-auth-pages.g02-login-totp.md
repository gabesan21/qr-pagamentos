## Decisões que restringem esta frente

- The auth card is a shared server composition at `src/app/auth-card.tsx`, consumed by login now and by F03 next; its public API must accept both a form panel and a state-only panel as children, plus the existing language control slot. It composes owned `src/components/ui` primitives and adds no new entry to the shared-UI inventory. Publish the API in the result note — F03 cannot edit this file.
- The brand panel moves to the leading side, stays hidden below 900px, and carries the tagline plus the product caption, the accent strip and the six-swatch row. Strip and swatches reuse the generated `/application-assets/theme-swatch-<id>.svg` assets over the closed theme-id registry exactly as `shell-theme-picker.tsx` does; no literal color, no theme-id branching, and the decorative images stay out of the accessibility tree.
- The forgot-password disclosure is a link to `/reset-password` plus a note that resetting requires a valid administrator-issued link. Self-service reset does not exist in this application, so no new route, form or promise is created.
- Inline required copy is client-side progressive enhancement: the native `required` attributes and the native POST to `/login/submit` remain, the message is localized per field with `aria-invalid`, and no message ever distinguishes which credential failed.
- The challenge uses the owned `InputOTP` with six slots, native paste fill and submit on completion, adds a Back link to `/login`, and keeps the recovery-code mode with its current 64-character format posting the same `code` field to the unchanged route. Do not add a lockout state: no attempt counter exists server-side, and inventing one would be fiction.
- The login caption stops addressing administrators and adopts the template's account wording in both locales.
