# Plan — [[10.2.2-build-admin-payment-links-directory]]

- **Stage:** 002_planning · **Responsible:** planner agent

## Objective and expected result

- **Objective:** give administrators a bounded, read-only, re-authorized global Commerce V2 payment-link directory on the `src/data-directory/` foundation — keyset pagination over the closed 10/20/50/100 set with **default 50**, derived-lifecycle/type/kind/date/search filters, owner attribution with navigation, composition facts, expiry, read-time generated-order counts, and a read-only detail with order drill-down — replacing the delivered `/admin/payment-links` honest scaffold.
- **Observable result:** `/admin/payment-links` renders the V2 global directory (canonical `307`s, zero-I/O invalid-query, six states) under `ADMIN_GLOBAL` cursor binding; `/admin/payment-links/v2/[id]` serves a read-only detail with one opaque unavailable outcome and a drill-down link into the admin orders directory; soft-deleted owners keep full attribution with a localized deleted badge; contract tests and a run-bound `admin-payment-links:evidence` pair prove authorization, redaction, and accessibility.

Stage skills on the card are correct (clean-code + ui-change/ui-review + sync-specs at 002/004, clean-code-review + ui-review + yolo-critic at 005); nothing missing.

## Strategy

Pure additive read surface; no mutation, no migration, no edits to frozen V1 modules, the owner V2 view, or the foundation. Pinned decisions the executor must not revisit:

1. **Scope: V2-only directory, honestly recorded.** The roadmap row's fields (status, type, product lines or fixed value, expiry, order counts) map 1:1 onto the delivered V2 derived-lifecycle vocabulary; no administrator V1 link projection exists today, V1 link files and their trigger stay byte-frozen, and 10.2.1 set the V2-only precedent for admin global directories. V1 links remain merchant-managed through frozen V1 routes with no admin table; the administrative-foundation spec amendment states this boundary explicitly. This is a scope decision, not a silent gap.
2. **Query ownership: new module, never extend the owner view.** A new server-only `src/auth/payment-link-v2-admin-directory.ts` mirrors the delivered `payment-link-v2-view.ts` adapter shape but runs `queryAdministratorDirectory` with the `ADMIN_GLOBAL` scope purpose (both delivered by the foundation — no foundation edit), directory id `admin-payment-links-v2`, path `/admin/payment-links`, the same `(createdAt desc, id desc)` keyset and seek tuple (reuse the exported `validatePaymentLinkV2DirectoryTuple`), and its own page-size policy `{ sizes: [10,20,50,100], defaultSize: 50 }` mirroring the 10.2.1 admin policy. The owner view file is not touched (9.1.3/9.3.1 in flight).
3. **Derived lifecycle: reuse the exported pure derivation, never recompute.** Import `PAYMENT_LINK_V2_DERIVED_STATES`, `derivePaymentLinkV2State`, and the filter definitions from `payment-link-v2-view.ts` unchanged: `inactive` > `expired` > `paid` > `active`, where `paid` is the SINGLE_USE settlement claim or at least one CONFIRMED LINK order, and `orderCount` is the same filtered Prisma `_count` of every LINK-source order. The non-exported Prisma state-condition mirror is re-declared locally with a contract test asserting filter↔derivation agreement across the whole closed vocabulary.
4. **Filters (six, under the eight-filter cap):** `state` (derived four), `type` (SINGLE_USE/REUSABLE), `kind` (PRODUCT_LINES/FIXED_AMOUNT), `from`/`to` (validated created calendar-day bounds, zero-I/O invalid), and `q` (exact 24-character identifier match, otherwise bilingual description and owner-username containment). No currency-pair or UUID filters; the pair renders as its redacted label only.
5. **Redaction surface: owner row shape + owner attribution only.** Rows carry exactly the delivered `PaymentLinkV2DirectoryRow` fields plus the owner relation's `username` + `deletedAt` — nothing else. Never select or render currency-pair UUIDs, owner email/id, provider data, verifiers, capability material, expected-version/lifecycle CAS fields, or V1 data.
6. **Deleted-owner rendering: history preserved, never filtered.** 10.3.1 deactivates a deleted owner's links, so they list naturally under the derived `inactive` state with username + localized non-color deleted badge; eligibility and ordering never change on deletion (10.2.1 precedent).
7. **Owner navigation and drill-down: pinned targets.** The owner cell links to `/admin/accounts` (interim; the spec records that 10.3.3 repoints to the per-user profile). The detail's order drill-down links to `/admin/orders?link=<identifier>`, the exact-link filter pinned by 10.2.1's approved plan; if 10.2.1 has not merged when this executes, the target resets harmlessly to the delivered ledger page — prefer sequencing after 10.2.1, do not block on it.
8. **Detail view: read-only composition over one bounded global read.** `/admin/payment-links/v2/[id]` re-authorizes the admin, resolves by UUID id with no owner scoping (global read), shares the one opaque unavailable outcome for malformed/missing identities, and renders the redacted composition facts (bilingual line titles/quantities/prices or fixed-amount description/amount, pair label), derived state, expiry, order count, owner attribution, and the drill-down. Owner-only surfaces (edit/activate/deactivate forms, comment thread) are never rendered.

Rate-limit and request-log inventories: unchanged (SSR admin pages, no API routes) — no intersection with 9.1.3/9.3.1.

- **Risk:** locally re-declared Prisma state-condition drifts from `derivePaymentLinkV2State` — mitigation: pinned decision 3 contract test covering every filter/state combination.
- **Risk:** global description/username `contains` search scans grow — mitigation: bounded keyset reads, no offset, no new index (same stance as 10.2.1).
- **Risk:** evidence harness conflicts with 10.2.1's concurrent append — mitigation: distinct flag and seed block, rebase-level merge; never reword shared harness code.
- **Risk:** drill-down target absent if 10.2.1 not yet merged — mitigation: pinned decision 7; harmless canonical reset to the delivered ledger, spec records the final target.
- **Abort if:** the global directory cannot be served from the delivered schema (missing owner relation/column) — signal `blocked: true` with the schema evidence; a migration would violate the task constraint.
- **Abort if:** the admin UI inventory gate cannot pass without editing frozen foundation/design-system sources — signal `blocked: true` with the failing check output.
